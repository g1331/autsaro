# AUDIT-001：主机 CAN 信号基线证据审计

**状态：**active。**分支：**`audit/AUDIT-001-host-can`。**基线：**`aef47c3`。**关联能力：**HOST-CAN-01。**类型：**审计；不预设通过，也不新增协议功能。

## 目标与边界

以明确提交为基线，核查 README 声明的 CP/FO R24-11、11 位 Classical CAN、DLC 1–8、无符号 LSB0 信号、Windows 主机虚拟双 ECU 子集。记录实际 Rust、GCC、Node 版本与样例输入。CAN FD、29 位 ID、真实 MCU、第三方 CanIf/Can 和实机时序不计入本能力；适用的拒绝行为或未验证状态须写明。

## 验收工作

1. 固定多文件 ARXML、官方 XSD/MOD、源码和工具链基线，区分结构约束与项目支持子集。
2. 核对导入、受支持编辑、保留项/未修改文件、外部改动与未决变体的适用拒绝路径。
3. 对同一配置重复生成并比较完整输出目录；检查 ECUC/符号/类型闭包，从输出目录编译链接主机程序。
4. 用独立算出的位向量和两个不同配置 ECU 检查收发、错误 DLC、接收超时及 BUS_OFF/恢复；保存输入、预期、命令和实际输出。
5. 对照 [07 号验收决定](../../../.scratch/autosar-platform/issues/07-assurance-gates.md)核查静态/工件义务与真实工作区、独立交接；未运行者列为待审，不由 `cargo test` 推定通过。

## 收口

填写一份基于 [证据模板](../evidence/TEMPLATE.md)的记录，逐门写通过、失败、待审或有理由的不适用；由另一 Agent 独立复核。更新能力记录与下一项缺口。即使结论是“尚不能声明内部支持”，只要审计可复核且缺口具体化，本任务也可完成。
