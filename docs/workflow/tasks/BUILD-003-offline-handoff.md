# BUILD-003：生成工程的离线构建交接

**状态：**review。**分支：**`feature/BUILD-003-offline-handoff`。**基线：**`0f7f474`。**依赖：**BUILD-002。**关联能力：**HOST-CAN-01。**类型：**产品用户流程增量。

## 确定范围

CP/FO R24-11、无配置变体、Windows 主机虚拟 ECU 与 MinGW GCC；先以 11 位 Classical CAN 信号工程验证交接。生成器仍携带自身的 C99 主机运行时；可选 DoCAN、DTC 和 0x27 只决定启动参数说明，不扩大其已验证行为或第三方互操作声明。生成目录不包含原始 ARXML、官方 XSD/MOD、密钥或真实硬件构建依赖。

这项任务不新增标准 BSW 模块、ECUC 参数或运行服务，因此没有由本改动引入的 R24-11 SWS/MOD 行为条款。07 号验收议题中的“交付目录内明确依赖、构建方法与产物”是项目质量门；现有主机信号和诊断规范义务仍留在各能力档案中，不能因离线脚本通过而标为已审。

## 用户可见结果与验收

1. 生成预览列出随工程交付的 `README.md` 和 `build.ps1`，确认后两者进入 `files.list` 和 `files.sha256`。文档写出 Windows/GCC 依赖、构建命令、stdin/stdout 协议、配置映射位置及主机边界；按是否配置 DTC/0x27 给出准确的启动参数。
2. 把仅含生成目录的 CAN 工程移到另一条含空格的路径，从其他工作目录按文档运行脚本，独立编译、链接并用已知 `T 10` 金向量运行。已有二进制时拒绝覆盖；手改说明或脚本后再次生成须按现有完整性规则拒绝。
3. 核对全量 UI、核心和 Tauri 无头构建；隔离原生桌面若未执行则如实标为未验证。当前范围不升级 `HOST-CAN-01` 的六道证据门或支持声明。新 Agent 会话独立复核后再收口。
