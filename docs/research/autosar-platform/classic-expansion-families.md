# CP R24-11 模块族覆盖边界与扩展依赖（决策输入）

**口径。** [CP R24-11 Release Overview §3／表 3.1，PDF 页 19–27](../../official/R24-11/CP/ReleaseDocumentation/AUTOSAR_CP_TR_ReleaseOverview.pdf#page=19) 把发布物分为 **19 个 cluster**，并非 19 个可执行模块，更非一台 ECU 必须装入的全集；[Layered Software Architecture，PDF 页 10、13–14](../../official/R24-11/CP/General/AUTOSAR_CP_EXP_LayeredSoftwareArchitecture.pdf#page=10) 是*信息性*分层图，模块的具体接口、动态行为仍以各自规范为准。目标是最终能覆盖适用的 Classic 模块及多个硬件平台，每个受支持配置只启用其需要的功能。先前 [议题 02](../../project/archive/autosar-platform/issues/02-classic-inventory.md) 的 R20-11 是历史调查基线；[议题 05](../../project/archive/autosar-platform/issues/05-first-verified-profile.md) 已将产品基线定为 **CP/FO R24-11**，首个双虚拟 ECU CAN 信号闭环，诊断随后，不得将历史版本材料混作该基线。[CP Overview §1.3.5、§1.4.5，PDF 页 9、12](../../official/R24-11/CP/ReleaseDocumentation/AUTOSAR_CP_TR_ReleaseOverview.pdf#page=9) 指定 FO R24-11、`AUTOSAR_00053`／内部 `R4.10.0`。

**逻辑上的相邻能力，而不是标准强制的时间顺序。** CAN→诊断是[议题 05](../../project/archive/autosar-platform/issues/05-first-verified-profile.md) 的产品取舍。其后，模式/生命周期与持久化通常一起审视，是因为 **BswM §5.11、§5.16（页 18–19）** 规定 Dcm 模式请求及 NvM 启停读写联动；真正使用非易失块时，**NvM §5.2–5.4（页 19–20）** 通过 MemIf 接入按存储设备配置的抽象/驱动，CRC 是可配置选项，并非“所有诊断均先要实体 Flash”。[BswM 依赖](../../official/R24-11/CP/ModeManagement/AUTOSAR_CP_SWS_BSWModeManager.pdf#page=18)；[NvM 依赖](../../official/R24-11/CP/Memory/AUTOSAR_CP_SWS_NVRAMManager.pdf#page=19)。**[推论]** I/O/MCAL、其他有线网络、时间同步、Crypto/Security/Safety 和 V2X/充电/J1939/DDS 等专业族，可按具体 ECU 功能与资源分成相邻的验收单元；它们不是彼此统一的线性先决链。网络子栈则有具体组合边界：架构页 45 区分普通 CanTp/ISO 诊断与 J1939Tp/J1939 诊断，页 49 区分 FrTp/FrArTp；不可将“支持 CAN”外推为已支持这两种协议族。[架构，页 45、49](../../official/R24-11/CP/General/AUTOSAR_CP_EXP_LayeredSoftwareArchitecture.pdf#page=45)。

**验收边界。** [架构，页 15–16、21–22、32–35](../../official/R24-11/CP/General/AUTOSAR_CP_EXP_LayeredSoftwareArchitecture.pdf#page=15) 将 MCU 内部驱动定位为 µC 相关，ECU 抽象层也可能依赖板上器件/连接；主机虚拟控制器可验证生成配置、上层行为和受支持组合，但不能证明物理驱动、寄存器、中断时序、收发器、非易失器件或真实网络。实机组合需单独证据；[议题 07](../../assurance/acceptance-policy.md) 已规定内部端到端门槛，候选 NXP 板卡尚非已支持实机（[议题 05](../../project/archive/autosar-platform/issues/05-first-verified-profile.md)）。还须逐规格检查生命周期与 **Known Limitations**：Overview §4／表 4.1（页 28）列出总线镜像、CanSM、Ethernet/LIN/FlexRay、J1939、WdgM、NvM、Mem/MemAcc 等限制；例如 Mem 不支持 NAND 块设备及小于物理页/扇区的写入策略，MemAcc 的共享设备映射访问有并发限制（§4.19–4.20，页 34–35）。[Overview §4](../../official/R24-11/CP/ReleaseDocumentation/AUTOSAR_CP_TR_ReleaseOverview.pdf#page=28)。

**AP 不并线。** [CP Overview §1.3.3–1.3.5，页 8–9](../../official/R24-11/CP/ReleaseDocumentation/AUTOSAR_CP_TR_ReleaseOverview.pdf#page=8) 明确 CP、AP 为不同标准，FO 是互操作的共享基础、并非同一运行时；共享 release/schema 也不等于共享 C99 ECU 生成路线。[议题 04](../../project/archive/autosar-platform/issues/04-adaptive-feasibility.md) 已确定当前 CP 优先、AP 不实施；将来是否开展 AP 的 POSIX/C++、ARA 与部署闭环须另行进行产品决策。
