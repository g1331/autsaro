# MCU 前参考工程

本篇属于[路线图](README.md)，定义主机工程平台的最低功能范围、验收规模和交付归属；决定见 [ADR 0022](../adr/0022-reference-ecu-before-mcu.md)。先扩大主机功能和工程可用性，再接入真实 MCU；R10 可后移，不能按上板日期缩减本篇范围。以下是待实现的目标，当前支持与任务状态仍以 README、代码和 GitHub Issues 为准。

## 目标与输入

工具应能从正常配置入口建立或导入工程，配置多个网络、诊断对象、故障、持久数据和任务，在多个项目／变体间解释差异，生成自有 BSW 工程并独立构建、运行和交接。参考工程覆盖通用 ECU 集成能力，模块、模型及接口不绑定特定产品类型。

首批实施前准备原创或可合法使用的配置与独立行为预期，明确场景预期和固定版次标准依据。外部输入的参数、硬件约束、编码值和接口语义逐项核实，不直接当作 R24-11 定义。回归输入采用原创合成数据或已核定可分发的样例。

功能范围是 MCU 前的最低基线，并可随研究继续扩大；至少两份有网络、诊断、持久数据及任务／功能差异的参考配置用于累计集成验收，共用一个可追溯的平台基座。单份工程不必同时启用全部互斥选项，但所有已定义功能须有独立配置和行为证据。最小示例用于快速回归，不能替代功能覆盖或完整规模。

## 首批场景与规模

下表概括已定义的功能广度和建议样本规模。对应阶段开工前，按本篇参数组固定具体语义、支持组合、对象数、预算、输入和独立预期，写在对应 Issue。不能只挑参考工程当前用到的少量参数，也不能以缩小样例、隐藏未实现选项或标为“可选”删除功能。标准版次或语义确有冲突时明确修订依据。样本数不是永久上限，各项最大值是否同时出现由组合定义。

| 场景 | 首批目标与建议样本 | 必须证明的行为 |
| --- | --- | --- |
| CAN 与信号 | 2 路与 4 路配置；11／29 位 ID；7～17 个 HOH、12 Rx／5 Tx PDU 的代表性规模；Intel／Motorola、有符号／无符号及所需信号类型；周期／事件发送 | 控制器—HOH—CanIf PDU—路由—信号—应用闭合，通道与句柄隔离，位布局、长度、初值及非法组合可验证；R11 原有 CAN FD 目标保留并独立验收 |
| 诊断传输 | 4 Rx／4 Tx NSDU 规模、物理与功能寻址、所需连接与缓冲 | 寻址、请求／响应及 FC 路径正确；缓冲、超时、忙碌、取消、恢复及功能寻址响应规则有独立预期，不把 NSDU 长度当作 CAN DLC |
| 服务与诊断数据 | 百级 DID；读／写／控制、RID、会话与两级安全访问的代表性组合 | DID／RID 与权限、长度、类型、数据源和回调绑定正确；批量增删改、授权拒绝、异步或 pending 行为按所选标准配置核定；不能仅用 0x10／0x3E／0x22 冒烟验收 |
| 故障 | 10～26 条 DTC，事件、监测源、快照和状态策略可配置 | 独立、同时触发、恢复、读取、清除及重启恢复；查询数量、列表、掩码与实际事件一致，事件—DTC 映射按选定标准配置定义 |
| 持久数据 | 6～8 个 NV 块，长度、默认值、CRC、所需冗余及配置版本 | 请求完成／失败、块间隔离、默认值恢复、版本不匹配、损坏、写入失败和关机写回；Fee 布局与容量在所选后端具备依据时校验 |
| OS 与应用 | 8～10 个任务，周期／事件触发、多个计数器和所需闹钟动作 | 从配置生成 OS／RTE／SchM 并实际调度；激活、事件、同级优先级、资源与跨任务共享按所选契约验证；运行时已有能力不能替代生成器接纳证据 |
| 网络与生命周期 | 多路 CAN 与 NM／ComM／CanSM 映射，主动 CanNm、用户请求／释放及所需常开组合 | 启停、通信组、bus-off、准备睡眠、睡眠、唤醒及 NV 关机协作；一个网络的请求或失败不污染另一网络 |
| LIN 与主控交互 | 所需 1 路 LIN 的角色、ID、长度、校验和、调度／表切换，以及 SPI 承载的 IPC 消息 | 私有设备协议、消息编解码、时隙／超时、失联恢复、变体与 PM 联动；先区分标准总线语义与私有应用消息，再确定标准模块和扩展对象边界 |
| 原始 PDU 与应用接入 | 标准 Com 信号链及独立的原始 PDU／应用组包路径；帧表、信号表、Rx 分发与 Tx 注册 | 路径与配置可选择，位布局、默认数据、周期／事件发送和回调类型正确；直接 PDU 接入不伪称具备 Com 的 update-bit、DM 或网关语义 |
| 工程变体与扩展对象 | 基座／项目／变体、配置字位域、来源、参数与代码 diff、帧／信号／IPC／DTC／NV 对象和双向引用 | 覆盖、删除、功能位与 DID／模块联动、引用闭合、变体切换和重生成；差异解释到参数和输出，不能只记录来源而不实现覆盖 |
| 配置输入与受管生成 | 有界 C 宏／初始化器／枚举反导、显式命名与结构适配、版本身份、受管区域与部分生成 | 公开合成样例导入同一模型，未识别项逐项定位；幂等、块外字节保护、手改冲突拒绝、第三方文件保护和应用函数体保护，不要求任意 C 工程可逆 |

### 参数与接口覆盖

- **Can／CanIf：** 波特率、采样点、SJW／TSEG 和时钟约束，物理量与声明编码格式换算，controller／HOH／邮箱／FIFO／过滤映射；HRH 单 ID／范围、HTH 引用、静态／动态 Tx ID、DLC、通知、Rx 缓冲及回调分发。约束来自明确的目标描述或主机模型，未知目标不能假称通过硬件校验。
- **CanTp／Dcm：** Rx／Tx 寻址、padding、BS／STmin／WFTmax、N_* 定时及数据／FC PDU；协议行、连接、优先级／抢占、缓冲、P2／P2*／S3、服务／子功能、会话、安全等级、尝试／延时、DID／RID 及其权限和数据源绑定。多协议与并行组合按标准核定，不能用固定一条连接替代配置能力。
- **Dem／NvM／Fee：** 事件、DTC、监测与状态策略、快照和清除条件；块 ID／长度、默认值、CRC、冗余、回调、版本迁移及存储布局。数据结构尺寸按声明 ABI 核对，块容量、擦写和失败语义在存储模型上验证。
- **网络／生命周期：** CanNm 的周期、偏移、超时、重复／立即发送、节点 ID、NID／CBV、用户数据、远程睡眠，CanSM 的恢复时间／计数／确认和通信组，Nm／ComM 的用户／通道／模式映射；EcuM 的启动、复位、RUN 请求、睡眠／唤醒及关机存储协作。
- **OS／SchM／PduR／Det：** Task／ISR／Counter／Alarm／Event、优先级、栈、触发与启动；BSW 主函数清单、周期与独占区，诊断／应用路由和错误报告配置。ISR 的配置、调用上下文和恢复逻辑在主机先验证，具体向量与端口随后绑定；不将 FreeRTOS 原语直接当作完整标准语义，也不以空壳模块验收。
- **LIN／I/O：** 主从角色、帧 ID／方向／长度／校验和、调度时隙／周期／切换、设备映射、SPI 消息及 PM；控制器、收发器、端口和存储等接口及软件行为由可运行的主机适配／模型承接，不能统一记成 R10 才实现。

参数的预编译、链接期、后构建配置类与“单一配置／变体”的维度分别表达，不能把常量表当作后构建能力。回调检查声明、签名、链接与调用效果；跨模块按实际路由和长度语义校验，不把事件—DTC、NM—通道等关系无依据地写死为一对一。

诊断服务须列出准确的 SID／子功能及正反输入，保留原路线的 `0x10`、`0x3E`、`0x22`、`0x19/0x01`、`0x19/0x02`、`0x19/0x0A` 和 `0x14` 目标，再扩展所需 DID／RID、会话与安全授权的读写和执行能力。安全算法由明确的应用或安全服务契约承接，工具验证签名和接线；不把测试算法宣称为生产安全方案。是否需要编程／更新能力另按 R24 定义，存在编程会话不自动表示支持刷写。

CanNm 与无 NM／常开配置分别验收。已调查的 OSEK NM 模式与 OBD 可选包也保留在 MCU 前功能范围，先固定独立版次、角色、参数和有界行为，再实现可选择配置；“默认不启用”不能等同于“可以不实现”。不把 OSEK 扩展冒称 R24-11 CanNm，也不从 OBD 功能实现推定法规认证；尚未定义的完整 OBD／其他变体继续单独研究。

## 交付归属与依赖

功能主线为 **Epic 9 → R11 → R7／R18 → R8 → R9／R14 → Epic 10 主机累计验收**。R30 的主机运行、仿真和可视化随功能逐步接入，基础闭环在累计验收前形成，深入能力继续演进。R10 在主机出口之后按目标条件独立启动，可以晚于更多功能或仿真增量；箭头不表示尽快上板的截止日期。需求、标准和目标可行性研究可提前，依赖 Epic 9 主线的实现等待其出口。

| 归属 | 必须交付的增量 | 集成时点与已有入口 |
| --- | --- | --- |
| R11 | 多通道 CAN、ID、布局、所需路由及控制器／HOH／PDU 的一致配置 | 为 R7／R8 提供稳定通信契约，通信闭环不依赖后续诊断或 NM |
| R6／OS 后续增量 | 多任务、计数器、事件、闹钟配置生成及实际需要的 RTE 通信／映射 | 接续 [#198](https://github.com/g1331/autsaro/issues/198)、[#212](https://github.com/g1331/autsaro/issues/212)，先于消费它们的阶段验收；不重开已完成的 R6，不一次承诺全部可选机制 |
| R7／R18 | DID／RID、服务／会话／安全访问、Dem／NvM、多块数据、Fee／存储模型、布局与版本／恢复策略 | 与 R8 共用持久和启停契约；读写／擦除、掉电中断、损坏、磨损与恢复的软件行为先完成，R10 核对真实介质与时序 |
| R8 | EcuM／BswM、ComM／Nm／CanNm／CanSM 的多网络生命周期闭环 | 消费 R7 持久契约；应用服务端口分别接续 [#187](https://github.com/g1331/autsaro/issues/187)、[#195](https://github.com/g1331/autsaro/issues/195)，共同 RTE 接线归 #212，既有 Epic 9 义务不因本表延期 |
| R9／R14 | I/O、SPI／IPC、PM、LIN 的已定义配置、生成、驱动接口与主机协议／外设模型 | 消费 OS 与生命周期契约；标准接缝与私有消息分别建模，R10 只绑定特定芯片寄存器、向量、板级接线和真实对端 |
| 共享配置能力 | 平台基座→项目覆盖→功能变体、参数来源、跨项目语义 diff、批量诊断编辑 | 在 R11 首个多项目消费者前固定身份、引用、覆盖、删除与冲突语义，随模块接入并在各消费者验收前完成；支持变体切换与重生成，不能只显示来源而不实现覆盖 |
| 工作台主线运行 | CAN 收发、诊断及后续故障／存储／NM 场景的操作入口、结果与失败原因 | 接续 [#65](https://github.com/g1331/autsaro/issues/65)，Epic 9 后按稳定 host-batch 契约重建，随 R11／R7／R8 接入，Epic 10 前通过隔离原生验收 |
| 输入适配与受管生成 | 有界 C 反导、显式命名／结构映射、区域生成和冲突保护 | 与首个消费这些输入的配置阶段共同固定格式及公开样例，MCU 前交付；只转换到同一模型，不建立平行 BSW 主线 |
| 可选协议包 | OSEK NM 模式、已调查的有界 OBD 功能 | 分别接续网络管理与诊断消费者，明确版本和行为后纳入主机出口；不要求所有变体在同一参考配置中同时启用 |
| R30 | 场景驱动、虚拟总线／外设、故障注入、重放与运行可视化 | 详见[主机运行、仿真与可视化](host-simulation.md)，基础能力随模块接入，后续模拟器或多 ECU 扩展不绑定实机日期 |
| Epic 10 | 功能范围、互斥变体及至少两份集成配置的累计标准、工作流、行为和交接复核 | 接续 [#62](https://github.com/g1331/autsaro/issues/62)；每个功能有证据，残留回责任阶段修复，不以某份参考配置未使用为由关闭 |

项目差异管理复用原字节、原子 ChangeSet 与唯一验证计划。基座和覆盖的持久表达、来源身份与升级冲突在实施前设计并审阅，解析后的有效配置走同一条校验／生成链，不维护隐藏的第二份配置权威。宏、表、应用接口由各自唯一生成方输出；业务实现继续放在受保护的用户源码位置。

## MCU 前累计验收

- **正常工作流：** 在声明支持的 Windows、Linux 平台独立取证。从工作台完成新建／导入、基座与项目配置、变体切换、批量编辑、问题定位、保存重开、生成及主机运行；GUI／IPC 走隔离原生入口。正常配置与生成仍无需编译器和官方档案，执行构建／运行时才检查其工具依赖。
- **输入与输出：** 支持范围内无静默丢失，未支持项逐项定位并明确是否阻止相关生成；相同输入生成字节一致，未修改来源与用户代码保持。项目差异可解释到对象／参数、来源与生成影响，旧输出或部分结果不冒充当前成功。
- **独立行为：** 除合法场景外，验证权限拒绝、边界、超时、取消、网络故障与恢复、存储损坏／失败及版本不匹配。标准预期来自固定 R24-11 原文和独立向量；导入／导出自洽不能作为唯一依据。
- **资源与规模：** 对固定规模完成实际编辑、生成、构建和运行；给出明确的 RAM／Flash／缓冲预算与计量方式，不使用“段大小变化 ±2%”或“往返 99%”代替语义与资源验收。主机对象大小不能替代目标 ABI 下的尺寸，未知资源开销保持待验。
- **交接与质量：** 非实现者仅凭封存工程和声明依赖独立构建、运行并复现失败恢复，不依赖原 checkout 或手补符号；参考工程消费的必要健康子集、适用标准、C 源码分析、必要人工评估和持续门禁按现有规则完成。GUI、安装包、主机、目标构建和硬件结论分别记录。

## R10 的目标接入与取证

R10 将已经实现并经主机验证的配置、BSW、驱动软件接口及故障恢复接入具体 MCU／板卡。其工作是核定合法供应商驱动与接口适配、寄存器／端口、中断向量、目标执行栈、MemMap／链接地址、收发器与引脚、真实存储介质和对端，并测量时序、资源、电气唤醒及物理掉电行为。它不接收尚未实现的通用 LIN、Flash 算法、ISR 软件逻辑或运行可视化功能。

板卡、许可、工具链和对端可行性调查可提前；目标工具链可合法取得时提前检查编译、链接和布局。软件功能及仿真平台不依赖硬件就绪，R10 可以后移。真正目标相关的待验项逐项附规范依据、影响、工具／目标、责任与失败判据；目标通道和容量按硬件核定，主机模型或指令级仿真不代替真实目标执行。

## 迁移与后续范围

输入适配、C 反导和受管生成按本篇有界能力进入 MCU 前范围；任意商业栈的逐字节兼容或任意 C 程序反编译不在承诺中。主线保持 R24-11，自有标准模块满足所选配置的必需契约。

已定义的功能是最低范围，未定义的所有协议变体、其他网络／MCU、功能安全和认证不自动纳入。其他能力在[长期候选目录](candidates.md)保留，可按价值在 R10 前继续增加；真实 MCU 不是主机平台停止扩展的分界线。
