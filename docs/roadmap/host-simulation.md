# 主机运行、仿真与可视化

本篇属于[路线图](README.md)，定义 R30 的成果与发展顺序，补充[主机功能与参考工程](reference-ecu.md)。本篇为规划，尚非已交付能力；相关决定见 [ADR 0022](../adr/0022-reference-ecu-before-mcu.md)。R30 的基础能力在 Epic 10 主机累计验收前闭合，后续深化不依赖真实 MCU 就绪。

## 产品目标

使用者能够运行自己配置、生成的 ECU，构造总线、诊断、I/O 和存储场景，观察状态变化与应用数据，复现问题并比较配置或变体的结果。运行和仿真是工作台的持续产品能力，不只是测试脚本或上板准备；正常配置与生成仍可独立使用。

## 逐步交付

1. **主线运行与观察。** 接续 [#65](https://github.com/g1331/autsaro/issues/65)，复用生成工程、受管执行和既有主机契约。启动、停止、输入场景、运行进度、结果与错误绑定当前配置和构建身份；失效配置、旧二进制和残留进程不显示为当前成功。
2. **场景与模型。** 随通信、诊断、存储和 I/O 扩展提供虚拟总线／对端、外设及存储模型，能够驱动真实生成的 ECU 代码。支持消息输入、周期刺激、丢帧／延迟、bus-off、设备失联、存储损坏、写入失败和可控的掉电中断。模型的时钟、容量、错误和精度边界明确；场景用项目可维护的格式保存、版本化并重放。
3. **运行可视化。** 展示所运行工程的网络／路由关系、报文／信号值与趋势、诊断交互、DTC 与 NV 状态、任务／事件时间线以及生命周期状态变化。图表与配置对象双向定位，可比较不同运行／变体，标明输入、时间单位、状态和失败位置；显示来自实际运行事件，不根据配置绘制虚假的成功状态。
4. **深化仿真。** 在基础场景和事件契约稳定后，按价值增加多个 ECU／网络对端、环境模型、时间控制及指令级／外设模拟器接入。每项先核对可运行目标、模型覆盖、依赖、许可和执行成本；不预先把某款模拟器或板卡绑定为唯一实现。需要更深仿真时可在 R10 前继续投入，不受“下一步必须上板”的顺序限制。

前两步的基础闭环与第三步的关键场景视图进入 Epic 10；第四步按具体消费者继续拆分，不能用尚未定义的完整数字孪生替代可运行增量或形成无限验收门槛。

## 接缝与证据

- 原生主机执行、行为级模型、指令级仿真和真实硬件是不同的执行方式，分别记录能力、时钟及误差范围。主机上应执行实际生成的 BSW／应用逻辑，模型负责环境和设备接缝；不能用替身实现隐藏被测协议栈的缺口。
- 复用同一配置、生成计划和输出所有权，后端在各自责任边界接入；增加运行方式不重建一条配置／生成主线，也不创建第二个 OS 调度所有者。目标程序、场景驱动和模型状态的归属及终止行为在实施前固定。
- 场景输入、实际事件和独立预期分别保存。重放依据明确的事件顺序和时间模型，不能通过固定等待、重试或更长超时制造一致；实时线程的调度时间与模型时间区分显示。
- 先固定够用的输入／事件契约，再按已有工作台结构实现关键视图。事件关联配置对象和运行身份，注意有界缓冲、背压、采样、取消及资源释放；不为图表另建代理专用状态系统。
- 原生 Tauri／IPC 下实际执行场景，检查成功、拒绝、停止、异常退出和再次运行。保存的场景可在正常离线／自动测试入口复验；交接不依赖开发者临时目录、源码 checkout 或个人数据。

## 与 R10 的关系

R30 提前增加软件功能覆盖、问题可复现性和可视化反馈。R10 将已验证软件接入具体芯片与板卡，取得寄存器、中断向量、物理总线、真实 Flash、执行栈和时序资源证据。主机／模型结果不证明硬件已通过，硬件尚未就绪也不阻塞主机平台继续交付。
