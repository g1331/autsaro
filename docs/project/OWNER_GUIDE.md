# 怎样推进 Autosar 项目

在仓库中打开 Codex，直接说“**按项目计划继续推进**”。Agent 会从 BMad 的项目计划和当前 story 恢复工作，完成开发、验证与复核；一次最多处理两个 story，碰到阶段出口、重大方向选择或真实阻断就报告。你不必分配函数或任务编号，也不必复述上次聊天。

| 你想做什么 | 直接说 | 你会得到什么 |
| --- | --- | --- |
| 看进度 | “只读告诉我当前项目进度、能实际运行什么、最大风险和下一步。” | 当前 epic/story、可运行范围、未通过证据门和推荐动作；仓库不变。 |
| 连续推进 | “按项目计划继续推进。” | 最多两个 story 的实际交付，或具体阻断及可继续的下一步。 |
| 改目标 | “我希望用户能【操作】并得到【结果】；请调整项目计划并推进已明确部分。” | 对 PRD/epic 的影响、推荐方案和必要时才请你决定的问题。 |
| 看成果 | “演示这次交付的成功和失败路径，告诉我怎样复现。” | 输入、输出、拒绝或恢复结果，以及测试没有证明的范围。 |
| 复盘流程 | “复盘最近一个 epic 的交付与工作方式。” | 有出处的问题、后续行动及关闭条件。 |

项目计划在 `_bmad-output/planning-artifacts/`，任务状态在 `_bmad-output/implementation-artifacts/sprint-status.yaml`。旧任务卡和证据仍留在 `docs/workflow/` 供追溯；能力是否有资格标为“内部支持”看 `docs/assurance/capabilities.json` 的独立证据门。story 完成只代表那项交付完成，不代表某个 AUTOSAR 模块已完整实现。

第一次迁移保留了进行中的 `STD-001`（主机 Can Driver 接口）；下一项候选是扩展两个 DTC 的实际主机诊断行为。后者开始编码前须先确认适用规范和当前配置边界。若 Agent 反复只做资料或审计、没有新的 ECU 运行行为，让它指出哪个具体失败阻断了当前 story；无法指出时应回到功能开发。

项目目前由你主动唤起 Agent，不会在你离开后后台自动开发或发送通知。Agent 可作日常技术判断；新标准版次、真实芯片、重大兼容性或费用、对外推送与发布，应带着推荐和影响请你决定。
