## 问题

独立开源的 Classic 实现及生成器受哪些权利与限制约束？调查 AUTOSAR 规范、Schema、商标及一致性声明、引用的 ISO 标准，以及常见 MCU SDK 和工具链的再分发限制。区分已由公开条款证实的事实与仍需法律或厂商确认的问题；不能把规范公开可下载等同于获得实现或再分发许可。

## 答案

公开 AUTOSAR 规范及 XSD 不等于开源许可证，也不能默认随产品再分发；独立编写的实现是否涉及 AUTOSAR 的其他知识产权或商业利用条款，需按发布方式和具体行为取得适用的法律/官方判断。引用的 ISO 资料、MCU SDK、工具链、商标与一致性宣传各有独立边界。初期采用原创代码和逐文件来源记录，不捆绑未经确认可再分发的规范、Schema 或厂商材料；在公开发布前逐项核定许可证与声明。此结论不等于“独立开源实现被禁止”，也不等于“已经获准”。

条款出处、行为矩阵与待核清单见[研究记录](../../../../research/autosar-platform/open-source-rights.md)。

## 平台决策再评估（2026-09-26）

未来若决定公开发布，可将依赖治理设为项目自选的发布门槛：逐项记录直接与传递依赖的来源、版本、许可证及再分发条件，维护类似 SBOM 的清单，并验证发布包可按记录复现；同时明确项目承诺支持的范围、维护方式与期限。具体门槛由项目在发布决策时确定，不预设法律结论。

该门槛只针对公开发布准备，不是本地研究、原型或内部验证的前置条件。清单和可复现包有助于审查来源与交付，但本身不证明法律合规，也不替代对适用权利、许可和再分发条件的判断。
