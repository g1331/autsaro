## 问题

首版 Tauri 配置工作区如何让用户从空项目创建 ECU/CAN 配置或导入多份 R24-11 ARXML，并理解项目文件、跨文件引用、只读保留项与不安全编辑的提示？生成后如何展示校验、构建、主机虚拟 CAN 闭环结果及独立工程的交付位置？比较少量可交互的工作区/反馈方案，选一种既适合大配置树也不会把“生成成功”误当“已上板验证”的交互模型；只产出设计决策，不实现正式 UI。

## 交互比较资产

[配置工作区交互草稿](../prototypes/configuration-workspace.prototype.html) 是仅供本地决策的单文件 HTML，双击即可打开；不解析 ARXML、不保存配置、不生成或编译代码。底部可切换三种结构，网址 `?variant=A|B|C` 可直达；顶部可对照从空项目、导入多文件、危险修改、未支持变体四个示意场景。

- **A · 工程树**：文件与模块树、信号表、对象检查器并排，适合导入复杂项目后定位和编辑。
- **B · 任务流程**：按来源、通信、保护、生成逐步工作，适合首次从空项目配置，但大型导入项目的定位可能慢。
- **C · 依赖链**：以应用→RTE→COM→PduR→CanIf→Can 的路径理解影响面，适合分析引用和失败，但不宜单独承担大型项目的全部编辑。

原型阶段选用 A 作为主工作区，B 和 C 仅吸收相应能力，不建设三套平行编辑器。原型的反馈文字只是界面示意，不构成已运行或已上板证据。该 HTML 形成时仓库尚未初始化 Git，现保留为历史交互比较资产，不作为正式产品代码。

## 答案

以下记录原型阶段的界面决策；正式软件的后续调整见本节末尾。

**工程树为日常主工作区**：文件与模块树用于定位多文件 ARXML 和配置对象，主体表格/编辑区处理 CAN 帧、信号与映射，选中对象的检查器显示引用、只读保留项和编辑约束。无需在任务流程与依赖链之间切换才能编辑大型项目。

**任务流程仅用于新建/导入入口**：引导选择从空项目创建或导入 R24-11 多文件 ARXML，展示可编辑范围及保留项，完成后进入同一工程树工作区；不维护第二套编辑器。**依赖链作为对象级检查视图**：从选中信号或错误定位到相关模块、跨文件引用和阻断原因，而非独立全屏工作区。

保存、校验、生成、构建、主机虚拟 ECU 行为验证和实机验证必须是不同状态；保留项不可编辑、无法证明引用安全的修改阻止保存，影响有效配置的未支持变体阻止生成。显示具体对象/文件位置及阻断原因，生成工程交付目录单独可见；“生成成功”不得表述成虚拟闭环已验证，更不得表述成已上板。原型本身不构成正式软件的运行证据。

**正式界面的后续调整（2026-09-25）**：实际操作反馈要求减少顶栏信息并对功能分级。桌面工作区改为左侧项目导航，配置、诊断、生成与构建、虚拟运行分别成页；工程树、主体编辑区与对象检查器仅位于配置页。其他页面在主内容区居中呈现，左侧导航与主区独立滚动；阶段状态分离的约束保持不变。

## 平台决策再评估（2026-09-26）

后续工作区应区分项目来源（**新建**或**导入**）与后续阶段状态：**已配置、已校验、已生成、已构建、主机已运行、目标已验证**；另将适用的验收门槛是否通过单独呈现为**适用验收门槛已通过**。这些状态不得合并成单一“通过”或由较早阶段自动推导较晚阶段；例如主机运行不代表目标验证，目标验证也不自动代表适用验收门槛已通过。对不支持、不适用或被阻断的项目应明确显示状态与原因，并提供对应输入、日志或验证记录等证据链接。

以上是对工作区状态表达的后续决策要求，不表示当前 UI 已实现这些状态、证据链接或相应验证流程。

状态之外，工作区还应支持用户完成可追溯且不易误操作的真实旅程：从新建或导入项目，定位文件与对象，安全编辑并保存，到校验、生成、构建和运行；每一步都能看出当前对象、受影响内容、结果与下一步。对未支持配置或错误，给出可定位的源文件路径/对象、具体原因和可执行的修复建议；被阻断时保留相应状态及证据链接。生成目录的位置应明确可见，且能据记录重现生成与构建。

设计评审至少覆盖代表性成功与失败流程：从空项目创建并完成一条受支持配置；导入分散在多份 ARXML 的配置并安全保存；遇到未支持变体或引用问题时定位来源、理解阻断并按提示修复；生成后找到交付目录并复现构建；区分主机运行成功与目标验证未完成。以上是后续可用性和可追溯性要求，不表示当前 UI 已实现这些流程或提示。
