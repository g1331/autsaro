## 问题

首版从空项目创建与导入已有 R24-11 ARXML 时，项目的权威保存格式是什么？如何处理多份 ARXML、引用与变型、未支持的标准配置项和厂商扩展，才能避免导入/保存丢失数据或生成半成品？决定支持范围内的导入→编辑→导出往返不变量、版本标识及迁移规则；不要引入与 ARXML 长期分叉的第二套项目配置真相。

## 讨论依据

- R24-11 ARXML 是项目配置的权威保存内容；工具内部模型不是并行维护的第二套持久化配置。
- 导入策略允许项目包含未支持内容，编辑已支持部分时保留其余内容；不采用“只要有未知项就完全拒绝可写导入”。这不允许静默丢失数据或破坏未知内容中的引用。
- R24-11 [ARXML Serialization Rules §2.1.1、§2.2.3—2.2.4](https://www.autosar.org/fileadmin/standards/R24-11/FO/AUTOSAR_FO_TPS_ARXMLSerializationRules.pdf)允许模型分散于多个 ARXML 文件；注释与处理指令可被工具忽略，但只允许 AUTOSAR 与 XML Schema Instance 两种 XML 命名空间。

## 答案

**R24-11 ARXML 文件集合是 ECU 项目配置的唯一权威保存内容**。可另存工具自己的文件清单和界面状态，但不得在 JSON/数据库中维护与 ARXML 并行的通信或模块配置。软件从空项目创建 ARXML，也能将多份 ARXML 作为一个项目导入，解析跨文件引用，保存时保留原有文件边界；目标代码输出到独立目录，不覆盖输入。

对未支持但符合所选规范版本的内容，允许编辑已支持的部分，同时在导入/编辑/保存往返中保留未知配置**元素、属性、值与引用的语义**；不承诺整个编辑后文件逐字节不变。未修改的文件不重写。若无法证明一次编辑不会破坏未知内容的引用或依赖，阻止该次编辑/保存并报告具体位置，而不是静默丢失内容或拒绝整个项目。XML Schema 不允许的第三方命名空间等不符合输入契约的内容，不按有效 R24-11 项目可写导入。

未支持的配置变体可以保留于项目，但若它影响本次要生成的有效配置，必须拒绝生成并指出受影响路径，不能擅自选择一个变体。首版不自动迁移其他发布版本的 ARXML；没有明确转换与验证规则时，版本不匹配的文件不得作为 R24-11 项目编辑或生成。生成结果、文件保存及往返不变量应纳入发布验证。

## 2026-09-26 版本、变体与保存不变量复核（保留 ARXML 唯一权威决定）

**输入契约与来源。** 每次项目导入、编辑和生成须关联选定的 CP/FO R24-11、实际使用的 `AUTOSAR_00053.xsd`/适用 ECUC 定义来源、全部文件集合及其散列；Schema 命名或 `schemaLocation` 字符串加一次 XSD 通过不证明发布版本及跨模块语义已匹配。版本无法可靠确定、与选定基线冲突或缺少必要定义时报告具体文件/对象并停止编辑或生成的相应操作；未经明示的转换规则与往返验证，不静默迁移 R20-11、R25-11 或混版配置。源材料中的官方 PDF/XSD 是用户本地、Git 忽略的参考，不捆绑至交付包；模型、Schema 与约束的区别见[质量门研究](../../../../research/autosar-platform/generated-c-quality-gates.md)。

**引用与变体。** 同一 ECU 的多文件/同名分段 `AR-PACKAGE` 合并后核对绝对路径唯一性（允许合法分段）、目标存在性、`DEST`/类型及与当前有效配置的关联，不能只凭文本路径存在决定可生成。按实际声明支持的 binding time 和所选变体核对 ECUC multiplicity、条件依赖及关联输出；未知有效内容继续保留，未选中且不影响有效配置的变体不必阻止其他部分编辑，但无法证明影响范围时拒绝该次编辑/生成并说明依赖路径。不默取“默认变体”，也不把一个变体验收外推到全部变体。

编辑/生成入口应让用户辨认本次文件集合、判定的版本依据、实际选定的变体与目标、保留项与阻断项及其受影响路径；超出支持范围时说明所需的输入修复或选择，不静默把有效配置转为默认信号、删未知元素或悄悄缩小生成范围。此为[用户流程验收](../../../../assurance/acceptance-policy.md)的可观察要求，并非声称当前 UI 已具备。

**保存与往返。** 保存以原始文件集合为事务边界：编辑前检查保留项对已改对象的反向引用；变更只落到应修改的文件，未改文件保持字节不变，受支持与未知内容的元素/属性/值/引用语义往返不丢。提交前复核外部并发改动，失败时回滚或保留可恢复备份并报告状态，不把部分成功显示为完整保存。将跨文件删除/改名、未知反向引用、变体受影响路径、外部修改、暂存/替换失败及重新导入生成作为负向证据交给[内部质量档案](../../../../assurance/acceptance-policy.md)；这些是产品门禁，不声称 ARXML Serialization Rules 已规定工具的具体事务算法。
