# 非实现者独立交接验收

[独立交接 Issue](https://github.com/g1331/autsaro/issues/56) 的执行入口。由未参与被验收实现的接收者在 Linux 与 Windows 各执行一次，从冻结的 `master`
和可识别的交付物开始。练习可以提前运行。正式验收在[出口总览](https://github.com/g1331/autsaro/issues/30)的其他有效出口项完成后开始。

- [双平台执行命令](execution.md)覆盖生成、独立构建、配置与用户源码保护、离线接收、原生行为、官方对照及工作台。
- [出口证据与判定](decision.md)覆盖门禁、进入条件、失败归属和硬件交接。

| Issue 验收 | 逐项执行 | 通过条件 |
| --- | --- | --- |
| 从新目录接手 | A1 配置往返与生成、A2 独立构建与行为、A3 用户源码、旧格式和完整性拒绝 | 两平台分别有单／多 SWC 的保存重开、每个 main 新构建、CAN／诊断／调度正反与恢复、拒绝前后字节证据 |
| 搬移后的离线复验 | B1 无源码接收、B2 浏览器前端、B3 隔离 GUI／Tauri／IPC、B4 安装与发行 | 两平台分别完成 B1 和 B3。B2 与 B4 独立记账，按所选实际交付判定 |
| 确认出口并交回状态 | C1 官方 oracle 与条款、C2 实际 PR 保护、C3 性能与遗留、C4 结算与板级剩余 | 依赖与全部有效出口项有证据，缺失项回责任 Issue，项目负责人凭双平台记录结算 |

在启动前，将同一完整 Git SHA、接收者、日期、OS 版次、工具版本及路径、输入与交付物摘要记入结果目录的 `identity.txt`。
每项保存命令、实际退出码、原始输出以及通过／失败／无法验证的判定。失败和无法验证均保留到正式结算，不用重跑覆盖原日志。
有适用性裁决的步骤附决定链接及当前主线拒绝证据。保留失败目录直至证据上传，临时目录和进程只清理本次创建的部分。

以验收 PR 或 [#56](https://github.com/g1331/autsaro/issues/56) 的结算评论作为证据索引，按平台和检查编号链接日志及受控工件位置。
涉及许可的官方／MISRA 原文只记版次、编号、页码和核对结论。安装介质、崩溃转储与日志含本机路径时，上传前核对可分享范围。
