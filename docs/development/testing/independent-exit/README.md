# 非实现者独立交接验收

[独立交接 Issue](https://github.com/g1331/autsaro/issues/56) 的执行入口。由与实现无关的独立会话在 Linux 与 Windows 各执行一次，从冻结的 `master`
和可识别的交付物开始。Linux 保持原有断网、无源码的隔离核验标准；Windows 按 [#56 维护者决定（2026-11-20，方案 1）](https://github.com/g1331/autsaro/issues/56#issuecomment-7031215781)
在 GitHub 托管的 Windows runner（`windows-2025-vs2026`）上执行——不检出源码，只下载搬移包，用防火墙禁止被测程序联网，并在验收记录中如实写明仅做到被测程序断网的差距。练习可以提前运行。正式验收在[出口总览](https://github.com/g1331/autsaro/issues/30)的其他有效出口项完成后开始。

- [双平台执行命令](execution.md)覆盖固定样本、原生行为、离线／隔离接收和工作台。
- [编辑后交付复验](edited-handoff.md)把单／多 SWC 保存重开的封存树交给两个生产程序。
- [安装包实测](installation.md)分别执行安装、手工检查和卸载。
- [出口证据与判定](decision.md)覆盖门禁、进入条件、失败归属、记录规范和硬件交接。

| Issue 验收 | 逐项执行 | 通过条件 |
| --- | --- | --- |
| 从新目录接手 | A1 配置往返与生成、A2 独立构建与行为、A3 用户源码、旧格式和完整性拒绝 | 两平台分别有单／多 SWC 的保存重开、每个 main 新构建、CAN／诊断／调度正反与恢复、拒绝前后字节证据 |
| 搬移后的离线／隔离复验 | B1 无源码接收、B2 浏览器前端、B3 隔离 GUI／Tauri／IPC、B4 安装与发行 | 两平台分别完成 B1 和 B3（Linux 整机断网、Windows 托管 runner 不检出源码并用防火墙禁止被测程序联网）。B2 与 B4 独立记账，按所选实际交付判定 |
| 确认出口并交回状态 | C1 官方 oracle 与条款、C2 实际 PR 保护、C3 性能与遗留、C4 结算与板级剩余 | 依赖与全部有效出口项有证据，缺失项回责任 Issue；按正常工程流程收口，不设维护者人工签字，执行记录、证据工件与协调者的出口判定写入 #56 即为正式验收记录 |

在启动前，将同一完整 Git SHA、独立执行会话信息、日期、OS 版次、工具版本及路径、输入与交付物摘要记入结果目录的 `identity.txt`。
每项保存命令、实际退出码、原始输出以及通过／失败／无法验证的判定。失败和无法验证均保留到正式结算，不用重跑覆盖原日志。
有适用性裁决的步骤附决定链接及当前主线拒绝证据。保留失败目录直至证据上传，临时目录和进程只清理本次创建的部分。

按正常工程流程收口，不设维护者人工签字：将执行记录、证据工件（含 Windows 方案 1 与“整机断网”原要求的唯一差距说明）及协调者的出口判定写入 [#56](https://github.com/g1331/autsaro/issues/56) 即为正式验收记录，按平台和检查编号链接日志及受控工件位置。
涉及许可的官方／MISRA 原文只记版次、编号、页码和核对结论。安装介质、崩溃转储与日志含本机路径时，上传前核对可分享范围。
