| --- | --- |
| `00020／00028／00029／00032`（`[SWS_MemMap_00032]`／`[SWS_MemMap_00029]`） | 每个实际模块与每个 SWC type 的 MemMap 由 Memory Mapping 按输入配置提供；主机段映射不代表 MCU 段放置 |

## 已知差距

- **MemMap 与段放置**：主机 PE／ELF 段映射已有实际证据，MCU 段与权限只由目标工具链与布局关闭。

## MISRA 预处理布局

MISRA 主文 R20.1（Advisory，印刷页155／PDF163）按预处理前的文件顺序限制 include 之前的内容；R20.5（Advisory，页158／PDF166）限制 undef。AMD2 为两条增加 C11 适用性，不改变本实现 C99 下的上述义务；其他适用 amendment／TC 没有提供 MemMap 例外。

D4.10为Required（主文印刷32–33／PDF40–41，AMD2追加C11）；TC2.2明确示例的两种保护形式并非穷尽，没有增加MemMap例外。普通声明头仍保护其内容不重复展开，而实际MemMap分派头必须依不同START／STOP请求重入；一次性guard会吞掉后续关闭及重新开启。Os_MemMap.h只对固定属性定义做一次性保护，映射分派主体没有也不能借此声称满足D4.10。该真实冲突应连到实际调用方的重复include及对应头，而非伪装为某个函数违反；非法、嵌套和错配拒绝控制重入风险，不将这些控制当作不存在违反的证明。

固定 R24-11 的 `SWS_MemMap_00003`（页36）要求 START 定义、映射头包含、声明／定义、STOP 定义、映射头包含依次出现，并禁止序列中其他预处理代码；`SWS_MemMap_00011`（页41）要求映射头撤销 START／STOP 关键词。因此，代码之后的必要映射头包含及关键词 undef 是真实的 R20.1／R20.5 冲突。把所有映射头移到文件顶部会破坏段的开启／关闭；保留关键词则使下一次包含无法独立识别请求。映射头的非法／嵌套／错配拒绝和实际代码／存储段检查分别控制误配风险；逐处冲突记录与源码注释仍由 #58 按 ADR 0023 完成，不把 AUTOSAR 原文对其 MISRA 例外的说明当作 MISRA 批准。

普通业务头不受上述冲突理由保护。`Os.h` 的 Hooks 头、生成通信配置的诊断路由头，以及 SchM 的模式／主机独占区头在实际声明前导入；对应 release 检查保留。SchM 的五个生命周期常量也在 START 之前定义，段内只保留状态声明。正常消费者仍使用同一类型、数值和 MemMap 边界；`generated_schm_lifecycle_section_contains_no_other_preprocessing` 依据 00003 检查实际生成的生命周期变量块。

同类连续对象也不要求在仅有空白的间隙关闭再开启：Os_Time、Os_Backend、Os_HostServices、Os.h及Ecu_Target中的这类块共用外层配对，保持声明顺序及每个C token的映射类；不跨不同类别、条件或其他预处理合并。只对余下实际必要的后置包含作冲突判断，不能把可删除的内部配对也写成AUTOSAR强制行。

采用内核的可选测试头、MSVC 专属分支、MPU 标记，以及 Windows 名称导入的 undef，分别有自己的条件和消费者，不属于本节的必要映射关键词判断；原始报告及其后续人工评估保留。

逐处评估还须区分00011直接要求的模块START／STOP关键词，与当前属性实现为清除临时OS_MEMMAP／active状态而使用的内部undef。后者不是该SWS直接规定的名字；不能把选定GCC属性策略写成AUTOSAR强制实现。实际替代、接口影响和Advisory保留理由应分别核查，不给全部undef统一授权。当前仅补齐这些规范边界，尚不进入具体批准表或添加MR12注释；完整来源、逐处位置、风险证据与累计独立复核仍按ADR0023前提执行。
