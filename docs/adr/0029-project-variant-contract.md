## 1. 基座身份、引用与变体选择

**决定。** 基座是只读输入，身份为 `{baseId, release, 定义身份, revision, 源摘要}`：release 固定
R24-11；定义身份为 `RuleSetIdentity` 加已接纳扩展定义 `{catalogId, release, version, sha256}`；
revision 是发布者的标签；源摘要是成员（路径、字节 SHA-256）按路径排序的帧式摘要。项目以
`{baseId, revision, 源摘要}` 引用基座，随项目保存只读副本，打开时逐项核对；同 revision 不同字节、
release 或定义身份不符都拒绝加载，基座不被改写。

项目由若干层组成。层是一组 ARXML 成员（新增对象）加一份操作清单（对已有对象的操作）。
层序固定为基座 < 项目层 < 变体层。变体由项目声明：单选组必选恰一项，可选组任选；每个选项对应
一个变体层，选择记在 manifest。选择缺失、单选组多选、组或选项未知，生成前拒绝并定位到选择条目；
编辑与保存沿用 [ADR 0021](0021-incomplete-configuration-editing.md)，保留不完整状态。未选变体层保持原字节，
不参与合并与校验。不同变体层对同一标识给出不同操作即冲突（§3）。

项目变体与 ECUC 的 `implementationConfigVariant` 是两个维度，后者生成期只接纳
`VARIANT-PRE-COMPILE`（`configuration.rs:484`），保持不变。

**依据。** TPS_ECUC_02103（页 120）：`implementationConfigVariant` 是对单个模块配置的选择；
TPS_ECUC_02097–02100、08034（页 54）把配置类对应到各变体的最晚更改时间；constr_3589（页 115）
要求生成时定义版次已定。TPS_ECUC_02141、02110（页 116、47）：标准的变体机制是 atpVariation 加绑定表达式，
本 ADR 不引入。TPS_GST_00435（页 211）：约束在绑定后的纯模型上检查，有效配置即这一模型。

**否决。** 仅凭 revision 标签识别基座，放过同标签的改动；变体由基座声明，平台耦合每个产品，升级还会改变
既有选择的含义；按文件读入顺序后者覆盖，结果随目录顺序漂移；执行变体点绑定需要系统常量与表达式求值，超出 R11。

**约束。** #490：引用核对、层序、选择；#491：选择字段；#492：两份配置引用同一基座。

## 2. 对象身份与 rename／move 迁移

**决定。** 跨项目、跨修订的身份为 `{release, 定义类型, 完整 AUTOSAR 路径, 实例上下文}`，实例上下文
沿用不变量 8；参数与引用字段再加定义 id；上限大于 1 的字段以整体列表为操作单位，不按序号局部覆盖。
路径区分大小写比较，新对象与既有对象的重名按大小写不敏感检查。`objectId`、文件路径、C 宏和 CAN ID
都不进入身份。

rename 与 move 改变路径，必须是显式迁移：新基座随附迁移表（旧身份 → 新身份，同定义类型且目标存在），
项目自己的改名生成同样的记录。应用迁移时覆盖操作改指新身份，指向旧路径的全部引用同步改写，任一入边
无法核定（含不透明扩展引用）即整体拒绝。没有迁移表而目标消失，按冲突处理（§4）。

**依据。** TPS_GST_00020（页 204）：引用是区分大小写的 shortName 路径；TPS_GST_00029（页 27）：这类关联
只以完整限定路径为标识；TPS_GST_00021、constr_2508（页 70）：名字区分大小写、唯一性不区分；
TPS_GST_00092（页 57）：ARPackage 是命名空间；TPS_GST_00436、00170（页 81）：绝对与相对路径；
constr_2630（页 300）：同标识不同类型的拆分元素不得存在。现有改名已按“更新全部入边或拒绝”实现。

**否决。** 按短名或路径后缀猜匹配，会把相似对象配错；以删除加新建模拟改名，丢失覆盖与入边；
以 `objectId` 作跨版本身份，重开即失效。

**约束。** #490：迁移表、覆盖改指、入边改写；#491：改名入口。

## 3. 覆盖操作语义

**决定。** 层内每个条目是对一个标识的操作：

| 操作 | 层中的记录 | 有效结果 |
| --- | --- | --- |
| 继承 | 本层没有该标识的条目 | 取下层值 |
| 设置 | `set(值)` | 该值，来源为本层 |
| 移除覆盖 | 删掉本层条目 | 恢复继承，随基座升级而变 |
| 采用默认值 | `set(定义默认值)`，记默认值来源 | 与设置相同，值是当时默认值的副本 |
| 显式空值 | `set("")`，定义类型允许空串时成立 | 参数存在且为空串 |
| 删除 | `delete(标识)` | 对象（含子树）或可选参数缺席，遮蔽下层值，不回落定义默认值 |
| 禁用 | `exclude(模块配置)` | 该模块配置不在有效配置中 |

继承与移除覆盖对应“没有条目”；`ValueState::Absent` 描述有效值的缺席，两者各管各的。写入与基座相同的值
仍是设置，升级后不再跟随，所以恢复继承只能删条目。

删除与禁用先收集全部指向删除闭包的入边，闭包外的引用方仍在即整体拒绝，所有层字节不变，不级联；同一
ChangeSet 删除或改指全部引用方则接受。必填多重性与引用闭合交给有效配置的常规校验。功能关闭须由删除与禁用
带来真实依赖变化（模块、DID、路由随之消失），隐藏界面对象不算关闭；联动参数放进同一 ChangeSet，影响清单列出各来源层。

覆盖只作用于已有对象。新增对象写进本层 ARXML 成员，按 GST 拆分规则并入同标识的包、模块配置和容器：
重复的模块配置须带相同的 `implementationConfigVariant` 与定义版次，同标识参数值取值不同即合并冲突。
对配置类为 PUBLISHED-INFORMATION 的参数，覆盖拒绝，内置定义须由 #490 补入配置类并对照官方定义。

**依据。** TPS_ECUC_08054（页 133）：缺席的可选参数表示没有值，即使定义有默认值；
TPS_ECUC_03009、03010、03034（页 133）：默认值是可复制的初始值，可选参数可省略，已提供的参数须有值。
TPS_ECUC_02070、02071（页 53）：PublishedInformation 在预编译前固定，各变体相同；官方 ECUC 定义归档
（`core/resources/official.json`）中的 `CONFIG-CLASS` 含该取值。TPS_ECUC_02089（页 116）与表 2.48（页 128）：模块配置内容、参数值、引用值、子容器可拆分；TPS_GST_00047、00417、
00420（页 299、300）按标识合并；TPS_GST_00447、00449（页 298）要求不可拆分属性重复时取值相同，否则合并冲突；
标识只含角色名的元素按 00417 直接并入集合，再由多重性拒绝。两种结果都表达不了“覆盖”。
TPS_ECUC_02093（页 142）：被引用的容器须属于集合内的模块配置，被禁用模块的容器因此成为入边。

**否决。** 重复同标识的 ARXML 作覆盖，标准里是合并冲突；一个 null 兼指继承、空值和删除，三者结果不同；
删除自动级联会静默扩大范围；缺席时回落默认值违反 TPS_ECUC_08054；叠加冲突的变体层，结果依赖顺序。

**约束。** #490：操作清单、有效值计算、入边检查，并补齐 ECUC 模块配置与容器的拆分合并；#491：编辑动作对应上表。

## 4. 基座升级：三方比较与冲突

**决定。** 以旧基座、新基座、项目层三方比较。先应用迁移表，再逐标识判断，取值按 §6 的规范化比较。

| 情形 | 结果 |
| --- | --- |
| 基座未变，项目有覆盖 | 保留 |
| 基座变了，项目无条目 | 新基座值流入 |
| 两边都变且结果相同 | 合并，条目保留并标注与基座一致 |
| 同字段两边取值不同 | 冲突：同字段 |
| 项目删除，基座改了该子树或新增了引用它的对象 | 冲突：删除与修改、删除仍被引用 |
| 类型、单位、范围或定义变化使覆盖值失效 | 冲突：定义变化 |
| 迁移目标已有覆盖，或目标不存在 | 冲突：路径迁移 |
| 项目新增对象与新基座对象同标识 | 冲突：标识碰撞 |
| 已接纳的扩展定义与新基座不符 | 冲突：扩展定义失效 |

预览阶段只出分类报告，不写文件。确认后原子写入新基座引用与变基后的覆盖；冲突条目保留旧基座值、
新基座值、项目值及来源，状态为待解决。待解决条目存在时可继续编辑，生成被阻止；每条解决（保留项目、
采用基座、自定值）是一次 ChangeSet。无冲突部分照常做完整引用与规范校验，不重新格式化，不用默认值抹掉证据。

**依据。** TPS_ECUC_04004（页 276）要求更新时考虑既有配置并称之为合并功能，冲突分类是项目设计；
TPS_GST_00449（页 298）把单值属性的不等取值定为合并冲突，TPS_GST_00420（页 300）限定祖先标识一致才合并，上表沿用此立场。

**否决。** 两方比较分不出谁改了；固定“项目优先”或“基座优先”静默丢掉一方的意图；丢弃项目层重来毁掉用户工作；
只校验冲突字段放过无冲突部分的断引用。

**约束。** #490：比较、报告与逐条解决；#491：呈现冲突与解决动作。

## 5. 唯一主线、来源保留与失效

**决定。** 有效配置是各层按 §3 计算的派生图，校验、`ValidatedIntegrationPlan` 与生成保持现有的一条主线。
有效图不序列化回 XML 作权威，按 [ADR 0003](0003-original-bytes-and-single-validated-plan.md) 保留每个输入的原字节与摘要，
计划的输入清单扩展为基座成员、各层成员与操作清单、含选择的 manifest、应用源。每个字段记来源（层、文件摘要、
字节区间或条目），被遮蔽的下层值留给差异使用，未识别片段与注释原样保留。

有效身份由下列部分逐项帧式摘要：规则身份、定义指纹、基座引用与成员摘要、各层字节、选择、应用源字节，交付侧再加工具版本。
身份对输入计算，值相同而来源变化时身份也变。任一部分变化使旧预览、计划和交付确认失效（不变量 13）。切换变体即选择变化，
重新解析引用、校验与生成；同一选择保存重开后得到同一身份与字节（不变量 10）。封存包携带基座成员、各层成员与操作清单、
含选择的 manifest，离线重开重新解析出同一有效身份。

**依据。** ADR 0003 决定 1、3、4 与不变量 1、7；`input_fingerprint`（`projection.rs:1202`）与 `snapshot_identity`
已按同样的帧式摘要覆盖现有组成部分。TPS_ECUC_06040、06041（页 276、277）：以 `EcucValueCollection` 为入口，只处理其引用的
模块配置，有效模块集合以此为准。TPS_GST_00382（页 31）允许合并时忽略注释，注释的保留由源字节层负责。

**否决。** 把合并结果物化成 XML 作新权威，违反 ADR 0003；只哈希有效值，漏掉来源变化；为变体另建校验链，多出一套语义。

**约束。** #490：清单格式、身份计算、封存，同步更新 `sealed_package.py`；新输入角色归 `configuration` 所有者，
台账保持 v3。manifest、交付元数据与守卫在 #490 首个改变结构的 PR
中原子升版，版本号按与 [ADR 0028](0028-r11-communication-contract.md) 的落地顺序确定；旧工程与旧包按真实结构身份
拒绝（[ADR 0011](0011-no-backward-compatibility-before-stable.md)）并提示从原 ARXML 重新创建，用户的 R24-11 ARXML 仍是合法输入。

## 6. 三层差异

**决定。** 三层各自独立给出，都能定位到来源对象。

1. **源字节。** 逐层逐文件的字节差异，含注释、空白、未识别片段。
2. **对象与参数语义。** 按 §2 身份对齐，比较有效值、来源与引用。值先规范化再比较：整数的进制与正号
   （沿用 `core/src/definitions/validation.rs:19` 的解析）、布尔、枚举字面量、引用的完整目标路径与类型，其余逐字节。
   条目分为值变化、来源变化（有效值相同）、继承／设置／删除间的状态变化、对象增删、引用改指、定义变化。
   信号布局与路由等校验消费的类型化属性同属这一层；写法不同而语义相同的改动只出现在第 1 层。
3. **生成与用户代码。** 两个有效身份的产物差异，按台账的 owner 与 producer 归类；仅由身份戳（规则、版本、摘要）造成的变化
   与 C 逻辑变化分列，无法归类的按逻辑变化处理。用户应用文件只显示槽位增减与字节是否一致。

**依据。** TPS_ECUC_02074（页 64）：数值正号可省略；`OwnershipEntry` 只记路径、owner、producer 与摘要
（`core/src/generator/delivery/ownership.rs:46`），没有从产物回到源对象的索引，#490 经计划的 producer 记录补出。

**否决。** 只做文本差异，等值改写被当成行为变化；只做有效值差异，来源变化不可见；
生成差异不分类，身份戳淹没 C 逻辑变化。

**约束。** #490：三层差异的核心 API；#491：展示并由差异跳转到源对象与受影响产物。

## 7. 与所有权账本和用户代码的关系

**决定。** 基座成员、各层成员与操作清单、manifest 都属 `configuration` 所有者，现有 owner 集合（`ownership.rs:22`）不增加。
用户应用源沿用 [ADR 0007](0007-live-and-sealed-application-source.md)：live 文件属于用户；生成器唯一生产接口、表与宏；
重生成拒绝覆盖外部改过的生成物或用户文件。

应用槽位由有效配置的计划派生。切换变体新增槽位时，预览列出新槽位，确认后 create-only 初始化；槽位在当前选择下消失时，
manifest 成员与 live 文件原样保留，标为未启用，不进入交付快照，不参与身份，也不触发成员数与槽位数不符的拒绝；
切回后复用同一文件。成员只在用户显式操作时移除，变体切换从不重写或删除算法。封存包的应用快照仍是不可变字节，
台账不授予写权限。

**依据。** ADR 0007 决定 2–6；`classification` 对找不到槽位的应用快照拒绝（`ownership.rs:93`），未启用成员因此不得入快照。

**否决。** 切换时自动删除或重写槽位文件，丢用户算法；为变体新增 owner 类别，扩大守卫的面；放宽守卫接纳未知输入角色。

**约束。** #490：槽位的启用与未启用状态；#491：预览列出槽位增减；#492：覆盖变体切换后的用户代码保留。

| 1 | 两个项目引用同一基座，网络、任务、功能各不同，各含可切换变体 | 从正常入口生成并构建；基座引用与字节相同，有效配置在通道数、任务表、功能模块上有差异；复制目录改名不满足 |
| 2 | 选择缺失、单选组多选、选项未知 | 各自拒绝生成并定位到选择条目；编辑与保存仍可进行 |
| 3 | 设置任务优先级后移除覆盖，再升级基座改该值 | 设置后有效值来自项目层；移除后恢复基座值，项目层无该条目；升级后随基座变 |
| 4 | 显式空值、采用默认值、删除可选参数 | 有效配置各不相同：空串、默认值副本、参数缺席且不回落默认值 |
| 5 | 删除仍被引用的对象 | 拒绝，诊断列出每条入边的引用方与字段；各层字节不变；不级联 |
| 6 | 同一 ChangeSet 删除对象及全部引用方，或禁用整个模块 | 接受，引用闭合；生成物中对应模块、DID、路由真实消失 |
| 7 | 升级：项目覆盖的字段与基座改动的字段互不相交 | 自动合并，可生成 |
| 8 | 基座把某值 3 改为 4：项目设为 5，另一例项目设为 4 | 设为 5 报同字段冲突，列出三方取值，生成被阻止，项目条目原样保留；设为 4 合并无冲突 |
| 9 | 项目删除对象，新基座新增了引用它的对象 | 报删除仍被引用，生成被阻止，解决后可生成 |
| 10 | 新基座改名对象，一例带迁移表，一例不带 | 带表：覆盖与入边改指新路径；不带：报路径迁移冲突，不按短名配对 |
| 11 | 切换变体，保存关闭重开 | 旧预览、计划、交付确认被拒；重开前后选择与有效身份一致，两次生成字节相同 |
| 12 | 同值不同写法（`0x10` 与 `16`、注释空白）；同值不同来源（继承与项目显式设置同值） | 前者只有源字节差异；后者语义层有来源变化行，有效值与生成物无逻辑差异 |
| 13 | 项目 ARXML 含未识别片段与注释，其他处编辑、保存、切换变体 | 这些字节不变 |
| 14 | 用户编辑 live 算法后保存、生成、迁移交付、离线重开；变体使该槽位消失再恢复 | 每一步算法字节不变；槽位消失时文件保留且不入交付，恢复后复用 |
| 15 | 封存包离线重开；篡改任一层字节、选择或输入角色 | 未篡改时重解析出同一有效身份；篡改后拒绝 |
