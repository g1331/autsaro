# 0026. 项目源码验收与原始分析结果分离

## 状态与背景

已接受（2026-11-06）。项目负责人明确委托按严格门验收调整建议推进，[授权落实与范围](https://github.com/g1331/autsaro/issues/55#issuecomment-6679583380)归 #55。本决定调整其原始 `summary.passed=true` 正例，不改变 [ADR 0023](0023-autosar-required-conflict-disposition.md) 和 [ADR 0025](0025-misra-layered-scope.md) 的处置边界。

所选 AUTOSAR MemMap 协议必须在声明后关闭段映射并撤销模块关键词。固定检查器仍报告对应构造，已有类别处置也要求保留原始诊断。因此，保留这些构造与诊断时，原始分析器通过不能作为项目验收的唯一正例。

## 决定

原始分析与项目验收分别表示不同事实。

- `passed`、`error`、程序退出码、全部诊断、221 项 assessment、`completeCompliance` 和严格比较保持原义。每轮重新生成和完整扫描，不缓存扫描通过结果，不增加 suppression 或诊断基线。
- 最终严格门消费独立命名的项目验收结果。只有本次工具、目标、配置、程序、源码、producer 和评估输入下精确有效的处置才可参与判定；同一规则或路径前缀不能替代实体与证据闭包。
- 新增或未知诊断、过期记录、缺失或未评估义务、未完成的 Required 正式义务均阻止验收通过。Mandatory 不得偏离。来源分类、零新增、历史人工分类和 MR12 标记都不是放行许可。
- 工具或解析失败、不完整扫描、漏重样本及所需上游跳过或取消仍须阻断。沿用唯一 `CI required` 聚合，以实际故障与恢复 PR 验证分支保护，不降低保护条件。
- 项目验收不表示整体 MISRA 符合性，不替代人工评估、正式偏离义务、供应方责任或实际平台验收。

## 渐进实现与验证

沿既有标准篇维护处置，沿正常分析摘要保存其消费结果，不建立第二份批准清单。局部实现须明确区分记录匹配与证据闭合，未覆盖范围保持未完成，不能让部分消费者形成全量绿色门。

诊断身份保留程序名称。对同一规则、文件及源码文本，HostBatch 的移除不能抵消 probe 的新增；行号移动和程序列表顺序变化不算新增。比较结果仍分别报告新增与移除，不改变原始分析结论。

最终完成须取得同一 head 的双目标、四样本、双程序完整扫描，合法正例，以及未知、过期、身份变化、工具失败、漏扫和取消的拒绝证据。阶段 PR 使用 `Refs #55`；前置与真实保护证据齐备前不关闭 #55 或 Epic 9。

## 授权边界

本决定不批准新偏离、SDK 修改或维护分叉、供应方投稿、vendor 身份申请、费用、许可及公开支持承诺。#58 的实际规则缺口与 #59 的正式身份出口分别保留。
