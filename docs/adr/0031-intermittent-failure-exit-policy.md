# 0031. 无法复现的间歇失败离开 Epic 9 出口清单的条件

## 状态与背景

已接受（2026-11-14），执行项目负责人的决定，跟踪见 [#524](https://github.com/g1331/autsaro/issues/524)。
[ADR 0032](0032-pr-checks-and-master-validation.md) 调整了部分作业的触发位置。下文提及必需 CI 的
自动取证和测试保留要求，同样适用于迁往 master 的作业，连续运行仍按实际执行的作业计数。

Epic 9 出口清单（[#30](https://github.com/g1331/autsaro/issues/30)）里有几项只在正常 CI 中偶发、没有稳定复现的失败：
[#311](https://github.com/g1331/autsaro/issues/311)、[#412](https://github.com/g1331/autsaro/issues/412)、
[#414](https://github.com/g1331/autsaro/issues/414)、[#463](https://github.com/g1331/autsaro/issues/463)。它们的出口条件是
“取得失败现场并修复根因”，失败一旦不再出现，这个条件就没有任何事件可以满足。路线图又把 R11（#485–#491）及之后的
功能实施放在 Epic 9 出口之后，一个不复现的现象因此挡住了全部功能开发。

## 决定

### 离开出口清单的两个条件

间歇失败的 Issue 同时满足下面两条时，才能离开 #30 的出口清单，改为 `known-gap`：

1. **自动取证已在必需 CI 中运行。** 下一次复发时，不需要再追加日志或探针就能定位根因的现场，已经由必需检查
   （`CI required`）里的步骤自动保存并上传，例如 WER LocalDumps 转储与产物上传（#521）、进程／Job 成员身份采集
   （#415）、跨进程请求身份链（#446）。“失败后再加日志”不满足这一条。
2. **自取证合并起连续 30 次完成的运行没有复发。** 统计受影响作业的 master push 与 PR 运行，受影响的测试实际执行过，
   取消的运行不计入；同一作业上同一 Issue 的失败再次出现（包括该 Issue 已纳入范围的取证夹具失败），计数清零重来。
   核对时以每次运行的全部尝试为准，重跑通过不能抹掉首次尝试的失败。

### 离开之后

- 测试原样留在必需 CI：不建跳过或隔离名单，不重试，不放宽期限（见 AGENTS 验证一节）。
- 复发时 Issue 保持或重新打开，附上自动保存的现场，标 `bug` 并归入当前活动的 Milestone；根因修复从该现场开始。
  Epic 9 出口之前复发的，回到出口清单。
- 取证不足的 Issue 留在出口清单，直到补上取证并重新计数（#414 需要先补 ETW 进程身份）。
- 每个 Issue 的资格判定写成一条评论：取证位置与合并提交、运行编号范围与计数、最近一次复发。

## 依据

- Google 的做法是监控不稳定测试，超过阈值就提 bug 并移出阻塞路径，同时承认隔离“容易掩盖真实的竞态或其他缺陷”
  （[Flaky Tests at Google and How We Mitigate Them](https://testing.googleblog.com/2016/05/flaky-tests-at-google-and-how-we.html)，2016）。
- Chromium 的做法是由负责人用失败现场分诊，原因不明的旧不稳定测试直接重新启用，并指出被禁用的测试意味着覆盖逐渐消失
  （[Chromium Chronicle #2: Fighting Test Flakiness](https://developer.chrome.com/blog/chromium-chronicle-2)）。

两者共同点是不稳定测试不再让主线整体停下，处理依据是已有的失败信息。本项目比它们多一个条件：取证是自动的，下一次复发本身
就是需要的证据，所以测试继续阻塞合并，而不是移出阻塞路径；隔离只会把这份证据藏起来。

选 30 次的理由：每次运行失败概率为 10% 时，30 次内至少出现一次的概率约 96%（1 − 0.9³⁰）。低于 10% 的失败可能漏过这个窗口，
这类失败按 `known-gap` 接受，由已就位的取证在复发时兜底。

## 否决的方案

- **一直阻塞到复现。** Epic 9 和 R11 全部停在一个不复现的事件上，且没有任何动作能推进它。
- **隔离或跳过。** 丢覆盖，也丢掉复发时的证据，违反 AGENTS 对跳过名单和弱化检查的禁止。
- **自动重试。** AGENTS 明确禁止，重试还会把首次失败变成一次绿色。
- **取证未就位也放行。** 复发时拿不到现场，等于重新开始调查。

## 约束

- 本决定只改变出口清单的归属，不改变任何测试、CI 配置和失败的认定标准。
- 计数取自 GitHub Actions 的运行与作业记录。
