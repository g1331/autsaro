# 0011. 稳定版本前不保留向后兼容

## 背景

原规划要求旧 profile 与旧交接格式保持精确读取、重开与显式迁移，每次模块整改都要维护两套 ABI 和兼容回归。项目尚无稳定版本，也没有需要保护的已交付用户工程；许多 `-v1`／`-v2` 后缀并没有对应的兼容承诺。

## 决策

1. 稳定版本发布前以最新主线为准。旧 profile 与旧格式的工程、交付包**不识别为可用输入、不迁移**；打开或复验时按真实结构身份识别并**明确拒绝**，给出可理解的错误，不静默误解析、不改写、不重写摘要。
2. 不兼容的对象是工作台自己的工程与交付元数据；用户的 R24-11 ARXML 源文件仍是合法输入，可以导入新工程。
3. 公开签名、布局、句柄语义、wire 或交付格式变化仍须审阅 ABI 与第三方身份并写入 CHANGELOG；资产摘要更新不能代替审阅。新版本不以重命名旧接口宣称标准化。
4. 新增标准必填依赖时，官方定义保持严格，并保留新配置的拒绝反例。
5. 只有持久化或交付格式带版本，并登记在格式版本表中（见 ADR 0015）。
6. 稳定版本后的兼容与迁移策略在首个稳定版本发布前另行决定。

## 后果

- 取消 legacy 识别、重开与迁移工作；模块整改不再需要维护旧 ABI。
- 早期用户若持有旧工程，需要从原 ARXML 重新导入；旧封存包不能在新版本复验。
- 拒绝路径本身需要正反测试，保证不会误解析。

## 状态

已接受（2026-10-11），实施中；取代早期“旧格式精确兼容与显式迁移”的约束。
