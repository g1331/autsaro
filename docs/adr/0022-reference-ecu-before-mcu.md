# 0022. 先扩大主机工程能力，再接入真实 MCU

## 背景

现有路线以通用 CAN＋诊断参考 ECU 为第一条完整产品链，近期顺序为 Epic 9 → R11 → R7 → R8 → 所需 R9 → Epic 10 → R10。参考输入仍以单网络、示例 SWC、应用 DID 和最小故障场景为起点，通用 OS 生成、多块存储、LIN 与项目变体尚未全部纳入 MCU 前出口。

完整 ECU 集成需要多路 CAN、批量诊断对象、多块 NV 数据、多任务、网络生命周期及 LIN／SPI 消息。只围绕首块板卡选择最小组合，会把可在主机完成的软件功能推迟到硬件阶段，也会限制仿真和运行可视化的发展。产品应先形成具有足够功能广度的主机工程平台，真实 MCU 接入日期可以后移。

## 决定

1. 产品继续交付通用、自有 R24-11 Classic BSW 与配置／生成工作台，以[已定义的功能范围](../roadmap/reference-ecu.md)作为 MCU 前的最低基线。不能按某块板卡、最小演示或预设上板日期反向缩减范围；样例组合和容量不代替功能广度。保留既有阶段编号，已完成阶段不重开。
2. R11、R7／R18、R8、R9／R14 在主机交付通信、诊断、存储、调度、生命周期、I/O 和 LIN／SPI 的配置、生成、软件实现及恢复。驱动接口、控制器／存储模型、ISR 逻辑和可注入的软件故障在前序完成；R10 只承担特定芯片／板卡的寄存器、端口、中断向量、链接布局、对端及硬件取证。
3. 多任务 OS 配置生成接续 #198，RTE 机制接续 #212；项目基座／覆盖／变体、双向引用、语义 diff、输入适配、受管生成和扩展对象按功能范围交付。共享能力先固定契约再接入消费者，不能因默认示例不使用而整体延期。
4. 基座与覆盖的持久表达、身份、引用及冲突规则在实施前核定，解析后的有效配置进入同一校验／计划／生成链；不另建隐藏配置权威。继续遵守原字节、原子修改、单一计划及用户源码所有权约束。
5. R30 承接主机运行、仿真与可视化：从 #65 的主线运行入口发展到场景驱动、故障注入、重放、状态和时间线观察。基础能力随模块接入，累计主机验收前形成闭环；更深入的多 ECU／外设模型、指令级仿真按明确需求继续扩展，不能把仿真降低为一次性的上板准备工具。
6. Epic 10 对功能范围及至少两份有差异的集成配置累计复核；一份配置不必启用所有互斥变体，但整个功能范围必须有配置和行为证据。功能、类型和边界的取舍依据标准与工程用途，不能把未实现能力写成“不适用”。主机可验证的软件差距关闭，R10 不承担补做前序功能。
7. 配置输入适配和 C 反导采用明确语法／映射范围与公开合成样例，未识别项可定位且不静默丢失。它们导入同一模型，不引入平行运行时，不承诺任意商业栈兼容。保持 R24-11、自有标准接口、单一生成主线及既定 OS 路线，功能支持与目标证据分别声明。

## 后果

- MCU 前以主机功能广度、工程可用性及验证／可视化能力为优先，R10 可以后移。硬件可行性调查可提前，主机和仿真功能发展不依赖购买或选定板卡。
- R14、R18 已定义的功能前移，其他未定义变体继续保留；R30 为持续发展方向。模块图只同步阶段备注，交付状态和条款比例仍由实现与证据决定。
- 具体实现与状态继续在原有 Issue 或其机制子任务中跟踪；本决定不关闭 Issue、不宣布能力已交付，也不创建未定义接口或容量的占位任务。
- 本决定补充 ADR 0001、0003、0004、0010、0013 和 0016，不取代它们。详细场景、阶段归属和出口在路线图中保持单一来源。

## 状态

已接受（2026-10-17）；能力扩展待实施，参考输入与具体支持组合待按路线图核定。
