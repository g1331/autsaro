# 0020. 配置编辑采用“模块 → 容器”树、容器参数视图与单字段直接应用

## 背景

AUTOSAR 的 ECU 配置按 ECUC 结构组织：模块配置（`ECUC-MODULE-CONFIGURATION-VALUES`）下是容器（`ECUC-CONTAINER-VALUE`），容器下是参数值和引用值。每个参数的类型、多重性、范围和默认值由模块定义决定。配置工程师熟悉的工具（DaVinci Configurator、EB tresos、ISOLAR-AB）界面各异，工作模型却一致：左侧是模块 → 容器树，中间是所选容器的参数编辑区，下方是可以定位的问题列表，旁边放参数说明与引用。

工作台审计（[#227](https://github.com/g1331/autsaro/issues/227)，发现 D1–D9）显示当前实现与这一模型相反：

- 中心是全部对象的清单，内容与树重复；参数只能在 290px 宽的检查器中逐个修改。
- 树按 ARXML 包组织，导入多个文件后出现同名包根节点，BSW 描述包与模块配置混在同一层。
- 改一个值要经过“输入 → 预览更改 → 确认应用 → 预览保存 → 确认保存”五步。
- 打开标准 ECU 工程后先落在“标准输入”页。
- 问题窗口不能按严重度或模块筛选，定位后其他地方也没有错误标记。

[#233 的进入调查](https://github.com/g1331/autsaro/issues/233#issuecomment-6228975838)确认：现有投影与修改事务足以支撑新模型，不需要新的 IPC。具体是：

- `objects` 带 `parentId`、`kind`、`definitionId`；
- `fields` 含每个对象定义允许的全部参数，包括 XML 中未写出的参数；
- `objectId`／`fieldId` 在重建投影时保持稳定；
- `prepare_configuration_change`／`apply_configuration_change` 以 revision 绑定，原子提交。

缺少的参数说明与标准 ECU 联动参数由 #250、#251 承接。

## 决策

### 1. 工程树的对象视图按类别分组

对象视图第一层是固定顺序的类别分组，只显示有成员的组：

| 组 | 成员 |
| --- | --- |
| BSW 模块 | 每个模块配置一个节点，按模块名（`definitionId` 中 `/EcucDefs/` 之后的一段）排序；节点下是容器层级 |
| 应用组件 | 软件组件类型、组合、原型、端口、接口及其行为 |
| 通信 | `SYSTEM`、`ECU-INSTANCE`、集群、通道、帧、PDU、信号及其映射与触发 |
| 类型 | 数据类型、基础类型、类型映射、模式声明组、`SW-ADDR-METHOD` |
| BSW 描述 | `BSW-MODULE-DESCRIPTION`、`BSW-IMPLEMENTATION` 及其内部行为与入口，默认折叠 |
| 其他 | 无法归类的元素与没有定义的对象，不隐藏 |

- 包（`AR-PACKAGE`）不再是对象视图的节点；节点提示和检查器显示完整包路径。文件视图保持按来源文件组织。
- 非模块组的成员是包下的顶层元素，按名称排序，其子元素保持投影中的嵌套。
- 分类由前端按 `kind` 与 `definitionId` 计算，与对象角色色（`objectRole.ts`）同一来源；图标按对象角色着色。
- 节点右侧显示子树中的错误数与警告数，以及“已修改”标记（相对上次打开或保存）和“未应用”标记（有草稿）。

### 2. 中心“配置”文档是容器视图

树中选中的节点决定中心内容：

- **模块、容器或其他对象**：顶部是名称、定义、角色标签与路径；其下是子容器表和参数网格。
  - 子容器表按子定义分组列出实例（名称、定义、状态），并给出每个子定义的多重性与当前数量；数量未达下限的子定义显示为一行“缺少”。
  - 参数网格每行一个参数，列为参数、值、单位、默认值、范围、多重性、状态。值在网格中直接编辑；只读参数显示值与原因，不渲染成禁用输入。
- **分组节点或未选中**：显示该组成员的概览表（如模块名、容器数、错误数）。工程打开后未选择任何对象时显示 BSW 模块概览。
- **全部对象**：原对象表保留为配置文档内的另一种视图，用于跨层级搜索和批量选择。复选框只表示批量选择；当前对象用选择色加起始边竖条表示（D8）。批量选择多个对象时，参数网格按对象分组列出它们的参数。

检查器显示当前参数（网格中聚焦的行）或当前对象的信息：

- 定义路径、类型、多重性（写作 `0..1`、`1..*`）、范围、默认值与来源、单位；
- 引用的目标与候选、错误详情与修复建议、来源文件。

检查器不再承载值编辑。参数说明在 #250 提供内容之前不显示，不编造。“属性／引用”切换保留。

### 3. 单个参数直接应用，批次预览只用于多项与结构修改

- 在网格单元格中修改值或选择引用，先写入现有草稿（`changes`），行上显示“未应用”。Enter 或行内“应用”按钮提交这一个参数；Escape 还原这一格的草稿。
- 提交时用只含这一项修改的修改集连续调用 `prepare_configuration_change` 与 `apply_configuration_change`，不弹对话框；revision 绑定与原子性不变。
- 成功后，这一项从草稿中移除，其余草稿保持不变，焦点留在同一单元格（`fieldId` 稳定）。
- 后端拒绝时，错误就近显示在该单元格，草稿保留，原配置不变。
- 不在每次输入或失焦时提交：单次应用约 0.25 s，输入到一半的值（如 `0x`）必然被拒绝。
- 以下操作仍走现有的批次预览与确认：多项草稿一起应用、新建实例、删除实例、改名。这些修改会改写其他文件中的引用，需要先看到影响范围。
- 保存始终经过差异预览与确认，与本决定无关。
- 整数接受十进制与 `0x` 十六进制输入（后端已支持），值按输入原样写回。网格在值旁以次要文字显示另一种进制，前端即时范围提示同时支持两种写法。
- 标准 ECU 的 CAN ID 与应用周期是联动修改（同时改写帧触发与 CanIf 参数、多个定时事件与 OS 告警），在 #251 之前继续在“标准输入”文档中修改；网格中照常显示这些参数。

### 4. 打开工程默认进入配置视图

新建、导入或打开工程后，活动文档是“配置”。标准 ECU 工程仍打开“标准输入”标签，但不再是默认落点；该页把受支持参数放在前面，来源角色与原字节摘要表收进页尾的折叠区。

### 5. 问题窗口是紧凑表格

- 投影诊断、工程校验问题与标准输入检查问题合成一张表，列为严重度（图标加文字）、模块、对象或参数、消息、文件。
- 表头可排序，默认按严重度再按模块；按严重度、模块和文字筛选。
- 双击行、Enter 或“定位”按钮执行问题定位接力，焦点落在参数单元格；只有对象时落在容器标题；只能定位到文件时打开来源文件；都不能时不提供定位入口。
- 同一诊断的标记同时出现在树、子容器表与参数网格中，悬停或聚焦时显示消息。
- 多重性诊断的消息带上子定义名、期望多重性与实际数量，由后端消息给出，界面不解析见证中的原文。

### 6. 其余范围内的调整

- **D7**：交付页中不会在本产品内通过的项目（完整 SC1 等级复验、实机）不再作为阶段标签，改为一处说明。重导入 ECU 交接包进入“文件”菜单。用户应用初始化从组件节点的上下文菜单与命令面板进入。
- **D9**：树节点与子容器表提供上下文菜单，“添加 ⟨子定义⟩”只列出定义允许且多重性未满的子定义（来自 `instanceDefinitions`）；改名与删除也在这里加入批次。检查器中的下拉框保留为补充入口。

### 7. 状态归属

本决定不做 #97 的目录重组：

- 当前参数 `activeFieldId` 与已保存值基线放进 `WorkbenchState`，因为检查器、问题定位和树标记都要读取。
- 配置文档的视图切换、问题表的排序与筛选、分组节点的折叠留在各自组件内。
- 单字段应用是 `batchEditing.ts` 的一个新入口，与批次共用同一份草稿和拒绝处理。

## 拒绝的方案

- **保留对象表居中，只加宽检查器。** 仍不能在一个表格里连续修改和并排比较参数。
- **按模块手写专用编辑页。** 15 个模块共 500 个参数，需要逐一编写和维护；通用网格由定义目录驱动，新增模块不用改界面。
- **后端返回已分组的树。** 分组只是呈现方式，所需信息已在投影中；再加一份对象结构会带来同步与失效问题。
- **每次输入或失焦就应用。** 见决策 3。
- **新增不经 revision 的单步应用命令。** 只省一次调用，却要多维护一条不受 revision 绑定的写入路径。
- **显示官方 MOD 的 DESC 文本。** 违反 [ADR 0006](0006-builtin-rules-without-official-archives.md)：内置目录是产品原创内容，官方档案不随产品分发。
- **完全取消批次预览。** 删除、新建与改名的跨文件影响需要在提交前可见。
- **保留包层级，只合并同名包。** BSW 描述包仍与模块配置混在同一层。

## 后果

- 中心与检查器的职责互换，交互规格中的工程树、中心文档、检查器、问题窗口与动作词随之修改；`DESIGN.md` 的组件规则（[docs/design/components.md](../design/components.md)）增加容器视图、参数网格与问题表。
- 单字段修改从五步变为“输入 → Enter → 预览保存 → 确认保存”，应用后工程变为未保存。工作台没有全局撤销，误改要再改回；“已修改”标记和保存差异预览让改动可见。
- 依赖旧中心结构的前端测试与桌面场景（对象表选择、检查器中的“预览更改”、问题列表选择器、标准 ECU 默认落点）随实现修改。
- 参数说明（#250）与网格中的联动参数（#251）未完成前，检查器不显示描述，CAN ID 与应用周期仍在“标准输入”中修改。
