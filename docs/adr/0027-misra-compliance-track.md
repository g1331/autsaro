# 0027. MISRA 人工评估合规线与 Epic 9 出口

## 状态与背景

已接受（2026-11-13），执行项目负责人在 [#480](https://github.com/g1331/autsaro/issues/480) 的决定。本决定部分取代 [ADR 0026](0026-project-source-acceptance-preserves-raw-analysis.md) 的启用阶段与“前置齐备前不关闭 #55 或 Epic 9”，以及 [ADR 0023](0023-autosar-required-conflict-disposition.md) 所述 Epic 9 出口对完整人工评估的依赖；两者其余决定不变。[ADR 0030](0030-host-simulation-layer-outside-misra-scope.md)（2026-11-14）补充：主机仿真层移出合规范围后，不回退门和完整验收只要求范围内位置，范围外位置只报告。

2026-11-13 核算时，MISRA C:2012 的 221 项中只有 31 项对当前输入有有效结论：固定 11 项 checker 限制已完成，144 项 checker 覆盖义务结清 20 项，66 项人工记录仍停在历史冻结输入。按已观察的批次速度，剩余部分还需数周。路线图把 R11 及之后的全部功能实施放在 Epic 9 出口之后，人工评估因此挡住了所有功能开发。

## 决定

### 合规线

#58 及其未完成子项 #439、#443、#445，连同 Required 正式义务，移出 Epic 9 出口，归入“MISRA 合规线” Milestone，与 R11 起各阶段并行。各项验收标准、证据要求和 ADR 0023／0025／0026 的处置规则不变。合规线以 ADR 0026 的完整项目验收正例为出口；切换时按 ADR 0026 补齐未知、过期、身份变化、工具失败、漏扫和取消的拒绝证据，再把必需门禁改为完整验收模式。该切换由合规线中新建的 Issue 承接。合规线须在 Epic 10 主机累计验收前完成，Epic 10 以完整验收模式的必需门禁为前提。

### 不回退门

Epic 9 出口时，#55 把以下检查接入唯一 `CI required`，并以真实故障与恢复 PR 验证分支保护。#55 以此为验收，交付后关闭。

- **完整性：** 工具或解析失败、不完整扫描、漏重样本、身份缺失或重复、所需上游跳过或取消，均阻断。
- **基准：** 基准是合并目标分支当前提交，即测试合并提交的第一父提交。同一次运行用 PR 的分析工具、addon、驱动和样本配置分别扫描基准树与 PR 树；两侧只允许源码、生成器及其输出不同。基准扫描失败或不可比时阻断，不设无基准放行。工具或 runner 环境的变化因此同时作用于两侧。
- **新增：** 沿 c-check 比较语义，按“规则＋相对文件＋源码行文本＋程序名称”计数，文件改名按 git 识别的对应路径比较。PR 树的新增位置在本次项目验收中有当前输入下有效的精确处置时不阻断，其余阻断。改写带现存诊断的行属于新代码。
- **验收报告：** 项目验收照常生成，报告 accepted／blocked、未评估义务和过期记录。合规线完成前，blocked 不阻断合并。

ADR 0026 关于“零新增不是放行许可”“部分消费者不能形成全量绿色门”的约束针对项目验收结果；合规线期间的合并许可由不回退门给出，不表示项目验收通过，也不是诊断基线或 suppression。原始结果、`passed`、退出码和 221 项 assessment 保持原义。

### 功能开发的义务

新增诊断原则上整改代码。确需处置时，由该 PR 按 ADR 0023／0025 的权限链取得对当前输入有效的处置，包括所需的证据绑定和独立复核；Mandatory 不偏离，类别外的新例外仍由项目负责人决定。功能 PR 不承担合规线已有的未评估义务，也不重绑与其新增诊断无关的评估组；被功能改动弄过期的已有处置，由合规线按批次以当时的 master 重绑。master 合并后的运行若相对其父提交出现新增，按 Extended 失败的做法建 Issue，由引入者修复或回滚。

## 影响

Epic 9 剩余出口为 #55 的不回退门、#56 的非实现者复验，以及仍开放的间歇失败与开发效率项。#56 复验不回退门与交付，MISRA 评估状态只核对报告是否真实。R11 仍在 Epic 9 出口后实施。

不回退门只覆盖检查器可报告的诊断：同一文件内行文本相同的同规则诊断一删一增会相互抵消，人工记录和检查器不可判定的义务对新代码没有自动信号。新代码的人工评估由合规线批次承担，其工作量随功能扩大而增长。基准与 PR 双侧扫描使分析量加倍，由 #55 结合 CI 效率要求实施。对外仍不声明完整 MISRA 结论。

## 授权边界

本决定不批准新偏离、SDK 修改或维护分叉、供应方投稿、费用、许可及公开支持承诺。合规线中需要项目负责人决定的偏离仍逐项提出。
