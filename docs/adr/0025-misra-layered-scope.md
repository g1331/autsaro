# 0025. MISRA 适用分层与类别偏离

## 决定与依据

已接受（2026-10-27），执行[项目决定](https://github.com/g1331/autsaro/issues/58#issuecomment-6437338057)。本决定部分取代 ADR 0008 的逐项批准限制、ADR 0023 对下列类别逐处重复记录的要求，并扩展 ADR 0024 之外的主机平台处置；三个旧决定的正文保留历史。

过程依据为 [MISRA Compliance:2020](https://www.misra.org.uk/app/uploads/2021/06/MISRA-Compliance-2020.pdf) §4.2（印刷12页，允许共用记录并以文件／宏等上下文识别每个实例）、§5.1（印刷15–16页，GRP）、§6.1–6.6（印刷17–19页，采用代码及头文件的责任边界）。这是项目当前适用策略的显式修订，不能反向把历史分析改记为通过。

## 四层适用范围

| 层 | 来源与责任 | 处置 |
| --- | --- | --- |
| 自有平台无关代码 | BSW、RTE、OS 核心和生成 C；生成器的输出仍是自有代码 | 221 项逐项评估，按下节 GRP 应用；偏离限 ADR 0023 的已核实 AUTOSAR 必需冲突，其中 MemMap 用类别记录 |
| 自有主机平台适配 | Linux／Windows 受控端口、项目 FreeRTOS port 补丁、host bridge | 正常整改；由宿主 OS 接口决定且当前平台无法消除的违反，按已授权类别有界记录，平台／provider 变化重评，不外推实机 |
| 工具链／SDK | glibc、libgcc unwind.h、Windows SDK／CRT 的原头及二进制 provider | 采用代码，供应方承担实现责任；按可追溯来源整体分类一次，保留版本、头／库身份和集成验证，不逐条声明已评估，不修改原头或手写替代声明 |
| 固定 FreeRTOS 内核 | 上游固定版本的原件 | 采用代码，引用该版本上游 MISRA 说明及其范围；项目有序补丁是自有代码，单独评估，不能用上游说明覆盖 |

采用代码的系统级交互与自有调用方仍须评估（Compliance §6.2／6.5）；宏展开造成的诊断按真实来源归属，不只看报告文件。provider 内部异步／fiber 语义及 Windows CRT／DLL 实现不逐项复评；Windows 集成证据取必需 CI 的实际编译和运行。来源分类不是供应方符合性证明，也不豁免自有代码。原始诊断、passed/error/not_assessed、完整扫描与严格比较保持；不加 suppression 或基线。

## 类别记录格式与引用

每项在既有模块标准篇中用稳定标题记录：规则与有效类别；文件／来源模式、平台及配置／程序范围；共用机制与理由、实际调用或包含闭包；风险及控制／验证入口；重评条件；原决定和提案链接。一次独立审查覆盖完整类别记录与检查机制，PR 写审查 head、发现与处置。具体分析在 #381–#385 引用“模块篇路径＋标题＋实际源码身份／profile／target”，并保留可追溯诊断位置；不逐行重写相同必要性，不新增台账。

三项记录为 [MemMap R20.1／R20.5](../standards/memmap/README.md#memmap-类别偏离)、[主机动态设施与同步嵌套 ISR](../standards/os/native-facilities/storage-interrupts.md)。类别仅覆盖满足所列模式和条件的位置。MemMap 由现有 memory-mapping 检查器的共用协议检查逐包含确认 START→include→内容→STOP→include；不符合即报错。检查器不替代段归属、最终 ELF／PE 放置或任意 C 语义核查。

源码注释沿 [C 编码规范](../development/c-coding-standard.md#misra-偏离注释) 与 SWS_BSW_00115 的 MR12 技术理由路径，类别记录集中共用依据，后续整改在实际违反位置写简短技术理由；不要求逐处另写必要性报告。现有精确偏离记录／注释关联继续约束已有记录；本次不批量写入源码注释或裁决诊断。类别外仍按 ADR 0023 的逐项格式，新例外由用户决定，Mandatory 不允许偏离。

## GRP：指南重分类计划

| 指南 | 原类别 | 项目类别 | 范围与理由 |
| --- | --- | --- | --- |
| R15.5 | Advisory | Disapplied | 本项目自有 C（含生成 C 和主机层）：参数校验、DET 报告及失败处理采用早返回，使拒绝路径就近、避免多层嵌套；审阅仍检查资源回收、输出与返回语义 |
| 其余 220 项 | 固定 C:2012＋AMD1–4／TC1–2 的有效类别 | 保持 | 按语言、配置与实际机制评估；不因 R15.5 调整其他 Advisory 或 Required／Mandatory |

R15.5 的 disapply 是 Compliance §5.1 允许的 Advisory 重分类，不是 Required 偏离。原始 checker 仍运行并保留其诊断；资源泄漏或错误返回不能引用 R15.5 免除。采用代码沿其来源说明处理，本 GRP 不声称重新认证供应方代码。
