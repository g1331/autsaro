# 产品界面与交互基线

## Foundation

本规格是**已完成并由用户暂时定稿的设计基线，不是正式软件实施或能力验收记录**。2026-10-03 用户确认本轮界面与透明珊瑚 A 图标“暂时定稿”；final 表示规格已完成，后续实施仍须经过选定范围的需求／架构收口、故事拆分及就绪检查。本轮不改 `ui/src/`、桌面后端及运行时；旧 logo 候选及无领域特征的抽象方向已撤回。

**后续规划覆盖说明**：用户随后批准 R5 采用软件原生内置校验与产品自有模块定义。本规格的启动、规则设置、错误恢复与普通工程旅程据此更新为 PROPOSED；当前软件仍依赖外部 XSD／MOD，尚无本轮新增的原生规则实现。冻结 HTML、图片和已运行原型证据均未改动；其中“官方资源”设置、缺失档案门禁及先配置档案的入口流程属于历史设计，已被本规格的新规范取代，不能据旧截图宣称新体验已实现或验证。

**主线收敛覆盖说明**：ADR 0012／0013（#33）已删除外部 XSD／MOD 校验模式、“CAN 信号工程”帧／信号 host 链路（模板、帧／信号与诊断／DTC 编辑、源码交付与独立构建、主机交付包导入）及“主机运行”窗口的双 ECU 与诊断运行；旧 v1 交接包导入时拒绝，旧设置中的档案路径被忽略并提示。本规格涉及这些能力的映射行、剖面边界与旅程步骤仅作历史记录；标准 ECU 工程、配置编辑、源码交付、编译预检、构建及固定主机验证继续有效。工作台内交互运行生成 ECU 的重做见 #65。

主要使用者为 ECU 集成工程师与 BSW 开发者，交接接收工程师也是完整流程参与者。保留产品名称“Classic CAN 配置工作台”与已有工程基础；logo 采用用户暂时定稿的 A 形体及透明珊瑚材质，撤回绿色适配和近似 Toolbox 的橙粉紫转色。[A 与界面对照](../mockups/logo.html)保留材质版与平面原色比较，主行动用珊瑚实色建立关联，图标色层不铺到工程工作区；正式软件未改。工程树＋对象表＋属性检查器、JetBrains 式菜单和工具窗口、ChatGPT 式中性壳层及对象／结果角色保持完整体系。

身份图形外围、车窗和灯位留白为真实透明背景；浅色石墨灯位与深色暖白灯位共享车身 RGB 和 alpha。外观“应用”及“跟随系统”的有效主题变化同步切换图形，不重建工程或丢弃设置草稿。已在无头浏览器实际验证四组图形／主题组合、外观应用与系统明暗切换；桌面通用导出采用固定中性灯色，未验证操作系统安装或原生主题联动。

视觉权威为根目录 [DESIGN.md](../../../../DESIGN.zh-CN.md)，行为权威为本规格；[交互原型](../mockups/index.html)仅佐证布局和关键交互，冲突时两份规格优先。正文、选择、面板间距与文字尺寸分别引用 `{colors.text-primary}`、`{colors.selection}`、`{spacing.panel}`、`{typography.body.fontSize}`，不在行为规格复制色值。浅色、深色和跟随系统共享所有权、导航与状态逻辑。

本目录保留初始界面暂时定稿和冻结评审产物；本规格后续规划覆盖不改写历史证据。视觉规格以根目录 DESIGN.md 为唯一入口，不另建并行状态或规格文件。原型初始为已保存、已校验的 CAN 样例，三个示意帧／六个 unsigned little-endian 信号；这些是内存场景，不代表真实校验或 scaling 能力。旧缺失规范档案、取消及失效仍只是可切换评审场景。

### 能力与设计的三种陈述

- **EXISTING／已有能力**：以下操作映射中的当前 Workbench 方法与现有 UI 处理器；后端决定输入是否安全、剖面是否支持及结果是否有效。现有 UI 尚不是本规格描述的统一壳层。
- **PROPOSED／拟新增界面行为**：统一菜单、持久工程树、对象／文件筛选、中心文档标签、问题焦点接力、主题和快捷键、不丢草稿的导航保护，以及后续批准的内置规则启动／设置／恢复体验。它们是设计要求，不宣称控制器或原生校验已经实现。
- **FUTURE／未支持产品目标**：通用 R5 ECUC 参数编辑、多 SWC 连接编辑、批量修改、MCU／真实硬件控制、ComM／NM 等扩大模块覆盖、学习层、Adaptive、认证及任意 ECU 工程的完整 SC1 等级验证。本轮不提供假入口、不用示例生成结果替代这些能力。

事实依据为 PRODUCT.md、当前规划，以及 `ui/src/workbench/useWorkbench.ts` 公共接口（117–196 行）、各操作实现、`forms.ts` 和现有 App／EditorPage／DiagnosticsPage／IntegrationPanel／IntegrationDelivery／BuildPage／VirtualPage／SettingsPage 处理器。这是当前操作到新界面的映射，不另建项目完成度或保证等级矩阵。

### 工程剖面边界

**CAN 信号工程**：有界多文件 ARXML；Classical CAN 标准 11 位 ID、DLC 1–8。帧可创建及修改名称、ID、DLC、Tx/Rx、Tx 周期或 Rx 超时；信号可创建及修改名称、起始位、1–32 位长度与初始值，按所属帧容量校验，当前为 unsigned little-endian 链。名称遵守已有标识符规则，字段输入与内核校验均不可绕过。当前没有任意帧／信号删除操作，不添加“删除对象”菜单。

诊断为单条 11 位物理 DoCAN 连接及一个 DID：配置请求／响应 ID、S3、N_As／N_Bs／N_Cr，按顺序选择 1–8 个不同的 32 位 Tx 信号。可选 DID 写入 0x2E、依赖写入的复位 RID 0x31/0x01，以及有界 0x27 单级 seed/key。关闭写入清空复位 RID；密钥不写入 ARXML，运行时独立文件提供，该安全档案仅限已有 Windows 主机虚拟目标。可选单个 DTC，代码 0x000100–0xFFFFFE，绑定已有信号且超时大于零的 Rx 帧；先应用 DoCAN 再配置 DTC。相关 Dem／主机文件 NvM 行为不等于完整 Dem、硬件存储或符合性。候选列表由真实资格条件产生，不允许自由填入不存在的引用。

**标准 ECU 工程**：导入后依据后端 `integrationCandidate`／检查计划识别，不由用户强行切换剖面绕过限制。只允许编辑计划中的 CAN ID（0–2047）和应用周期（1–2147483647 ms）。类型、端口、诊断、组件及引用映射只读；不能调用普通帧／信号创建器作为旁路。未能获得有效 description 的输入显示具体计划诊断，而不是伪造可编辑通用 ECUC 表格。只读关系可浏览、定位，但不能重接或创建。

### 内置规则与声明覆盖（PROPOSED）

正常安装启动时，R24-11 内置规则及所有产品支持 BSW／配置剖面的产品自有定义已就绪。起始页直接提供新建或导入真实工程；受支持 CAN 与标准 ECU 输入在离线、无官方档案、无编译器时仍可打开、编辑、保存、重开、校验及生成源码。普通用户不需 XSD／MOD 路径、相关环境变量、源码 checkout 或 Node／Rust／uv／编译工具链来完成这些配置动作；构建与主机执行另遵守既有工具／宿主限制。

`BuiltinRuleSet` 是产品编写的校验代码及随软件发布的不可变模块元数据，不是官方 XSD／MOD 的加密、原样或自动转换副本。官方档案只用于开发侧合法持有的固定 R24-11 对照验证，不是用户启动或交付依赖，也不据此推定公开发布许可。产品构建／启动核对确定性规则清单与完整性；`RuleSetIdentity = {release, rulesVersion, sha256}` 标识编译后的产品规则清单／实现来源，sha256 不代表官方档案。

项目投影携带 `ruleSetIdentity`，当前 capabilities／输入 fingerprint 纳入该身份；`definitionFingerprint` 继续作为内置模块定义与显式接受的可选扩展目录的 opaque 身份。前端只展示、传递后端身份，不生成业务 ID 或经 JS number 往返。规则版本、定义与覆盖变化必须进入结果归属，不仅修改设置文字。

问题窗口保留 `source-safety / schema / definition / target-generation` 四种校验作用域。`schema` 表示声明支持范围内的原生结构检查，覆盖合法结构、顺序、基数与类型；`definition` 覆盖模块参数、值／默认值与引用语义；既有跨模块目标约束仍在目标检查中执行。不得将其写成“完整官方 XSD 校验通过”，也不得把未覆盖或未执行标为通过。支持边界与错误就近显示，未知内容保留、不安全部分只读；不支持的消费语义阻断相应生成，而非禁止所有浏览或安全修复。

默认定义目录必须覆盖所有产品支持的 BSW／配置剖面，不缩成少数字段。R5 的通用类型编辑、结构操作、批量修改及真实引用验收仍基于实际多模块配置；上文已有剖面与下表当前操作边界不因此被伪称已扩展。内置化不扩大生成 allowlist、MCU／运行时能力或完整符合性承诺。
