# Voice and Tone · Component Patterns

本篇属于[产品界面与交互基线](README.md)。视觉权威为根目录 [DESIGN.md](../../../../DESIGN.zh-CN.md)，行为权威为本规格。

## Voice and Tone

用简体中文表达任务；AUTOSAR、ARXML、CAN、DID、DTC、模块名、路径和错误码保持准确原文。普通界面称“CAN 信号工程”“标准 ECU 工程”，不把内部历史标识暴露成产品分区。

动作使用结果明确的动词：“应用更改”只改内存工程，“预览保存”不写文件，“确认保存”写原始配置集合，“预览源码”不编译，“确认生成”写独立输出。“校验无阻断错误”不写成“工程完全正确”；“主机行为验证通过”不写成“实机通过”。

错误按“发生什么＋影响范围＋下一步”组织，并保留原始错误码／详情。例如：“标准输入编辑被拒绝，原配置保持。检查 CAN ID 对应的端口诊断。”普通流程区分规则不兼容、不支持范围、安装规则损坏、可选扩展缺失与具体执行工具缺失，不把所有情况统称“环境错误”，更不提示下载 XSD 来修复内置规则。兼容／开发专用外部档案错误明确标注用途。取消请求尚未确认时用“取消未确认”，不可提前宣称进程关闭。

动作词表在 `ui/src/i18n/actions.ts`：同一动作在菜单、工具栏、页面按钮、对话框、工具窗口和命令搜索中使用同一个 `action.*` key，命令的标签只来自 `workbenchCommands()`；需要进一步输入的动作以“…”结尾。忙碌与失败文案使用 `activity.*`：中文为名词短语（“正在校验…”“保存失败”），英文为动名词（“Validating…”“Saving failed”），不拼接动作标签。不用“真实”“后台”“后端”作修饰语，中文统一称“工程”；不向使用者显示 objectId、更改编号、IPC 命令名或 profile 标识，错误码只留在可复制的详情中。可见标签就是无障碍名称：字段由外层 `<label>` 命名（标签内还有选择按钮时，`aria-label` 与可见标签逐字相同），只有图标的按钮才另设不同的 `aria-label`。`ui/tests/vocabulary.test.mjs` 检查这些规则。

正常软件壳层不放设计解释或大段免责声明。能力边界在只读提示、不可用原因和帮助中就近说明。原型的“仅评审演示：所有数据及结果均在内存中，不进行文件、编译或 ECU 操作”提示置于模拟软件窗口之外，并始终可见；演示完成提示也不构成实际检查证据。

## Component Patterns

### 树、表、检查器

树节点以真实路径和对象类型识别，显示名不是唯一键。筛选范围区分“工程树”和“当前对象表”；筛选隐藏选中对象时保留选择与草稿，提示“当前对象不在筛选结果中”，不能自动选另一行。清空筛选恢复原展开位置。定位问题必要时临时揭示目标，并让使用者恢复原筛选。

表格保留工程数据列、单位、方向、只读属性；允许横向滚动，不将每行变成装饰卡片。选中使用 `{colors.selection}`，键盘焦点与选中不是同一状态。新建信号必须有明确所属帧，不能凭搜索结果位置猜归属。

检查器标题同时给名称／类型，路径和所属文件可复制。可编辑字段有独立 label、单位、范围和错误；只读字段为可选取文本并说明剖面限制，不伪装成禁用输入。应用成功保留同一对象焦点；改名后依据返回路径重定位。拒绝应用时保持原配置及所有输入，以便修正。

### 保存与生成预览

保存差异对话框列出整个文件集合、每个文件是否改变、路径、before／after 与差异；默认首个改变文件。生成预览列出 new／changed／unchanged 等后端状态、输出目录、交付种类、目标、文件归属与内容。二进制或不可展示内容明确说明，不显示空白假文本。

两个预览使用一致文件导航，但标题和确认动词严格不同。确认绑定预览的 revision 与当前输入身份；后续 R5 的输入身份包括 `RuleSetIdentity` 及 `definitionFingerprint`。任何相关变化使旧预览失效，必须重新预览，不能把旧确认迁移到新目录或新目标。无变化时说明“没有需要写入的更改”，不鼓励空保存。关闭预览只放弃确认，不还原配置、不清除编辑草稿。

ARXML 属于用户配置集合；生成文件属于选定输出；构建产物属于独立构建目录；应用算法与既有用户代码不是可静默覆盖的生成物。展示后端实际拒绝或冲突，不能用设计层自动删除目录、改写源码或接受危险引用。

R5 `autosar-workbench-handoff` 的 `resourceIdentities` 记录规则身份及所需已接受扩展定义，不携带或要求受限官方档案。导入仅绑定兼容的同一规则身份，核对完整 seal、源配置及重新渲染闭包；复制来的身份文字不构成可执行规则。规则不匹配时明确拒绝，或由使用者显式选择新目录迁移并重新预览／校验，不能原地静默重绑定。原有 legacy v1 的精确格式派发、XSD／MOD 身份及完整性核对保持独立兼容路径，不将旧哈希转换为原生规则哈希，也不放宽原包检查。

### 设置

三个导航项为“外观／规则与模块定义／执行工具”。打开设置克隆可编辑值形成独立草稿；保存仅提交当前可编辑类别，其他类别仍是草稿。关闭丢弃尚未保存的设置草稿，不改变工程草稿。外观立即预览但关闭恢复已保存选择；主题保存是拟新增界面行为，不冒充现有 configureResources。

“规则与模块定义”默认是只读的内置 release、rulesVersion、sha256／完整性状态及模块／配置覆盖说明，不提供替换核心规则的路径框或保存按钮。正常用户不配置官方 XSD／MOD；产品升级后的规则身份来自软件包，任何可变设置或 XSD／MOD 环境变量都不能覆盖内置权威。旧外部设置若为兼容／开发保留，须明确隔离用途，不能成为内置支持范围的必填项或普通起始页前置步骤。

可选第三方模块定义以显式“导入／移除”接入本类别，展示版本、摘要、来源与受影响消费者；接受前核对并确认，不隐式扫描加载。界面共用后台接纳与摘要键本机定义缓存，不建立另一份机器全局选中策略；缓存存在不等于工程接纳。已建立工程时，接纳集合变化为 dirty，经同一工程保存预览／确认与源成员事务持久化；重开只恢复该工程精确身份，缺失／损坏只影响其消费者并提供匹配文件的显式接纳入口，不默选其他版本。直接 ARXML 会话关闭／重开不隐式恢复扩展，提示可“保存为工程”保留选择。扩展不得覆盖内置项，导入不等于生成支持；拒绝操作保留旧接纳集合、草稿及原配置，移除不静默丢失未知内容或替换已有引用。

执行工具为 compiler、objdump、Git、锁定 CPython 的绝对可执行文件路径；环境覆盖优先于保存值并明确列出，沿用既有语义。设置保存成功不等于预检通过。PROPOSED 内置范围的配置及纯源码准备不受编译器缺失门控；构建与执行仍分别要求真实工具、nativeExecution 与适用宿主。**当前软件事实**：通用 `disabled` 仍包含外部资源缺失，执行额外受 nativeExecution／toolError 限制；这不是新规范，也不能据本次规划声称现有软件缺 XSD／MOD 已可用。旧 configureResources 固定档案摘要核对与原子保存属于尚未迁移的兼容／开发流程。
