# Key Flows

本篇属于[产品界面与交互基线](README.md)。视觉权威为根目录 [DESIGN.md](../../../../DESIGN.zh-CN.md)，行为权威为本规格。

以下为**具名工程师的说明性会话**，用于实现与评审行为，不是客户访谈、真实客户案例或验收成果。启动与规则依赖按后续批准的内置规范描述；原型未验证这些新行为，当前软件的旧资源门控见操作映射与设置说明。

## 林岚：修复 CAN 信号后交付源码

1. 集成工程师林岚启动已安装软件，内置规则已就绪；她直接选择同一 ECU 的真实多份 ARXML，无需官方档案设置。打开后落在 CAN 通信文档，工程树展示原文件及帧／信号，声明覆盖随问题作用域可查看。
2. 她选择 Rx 帧，在检查器修改超时；不慎切换对象时系统保护草稿，她选择应用并继续。表格更新但标题出现未保存，旧校验结果失效。
3. 她预览保存，逐文件查看差异，再确认保存。校验得到一个可定位问题，底部“问题”展开但工程上下文仍在。
4. **高潮**：点击问题，树、对象表与检查器接力到同一个信号；她修正位布局，应用后仍保持对象焦点，重新保存并校验，不把旧错误消失当作通过。
5. 她在源码交付文档选择独立目录，预览文件与差异，确认生成。没有编译器也不自动进入构建；已生成源码不标成已构建或已验证。

## 周衡：标准 ECU 的受限集成与显式主机验证

1. BSW 开发者周衡在内置规则已就绪的起始页直接导入真实标准输入，不配置 XSD／MOD。系统打开配置视图，“标准输入”文档同时可用，他在其中检查类型、端口、诊断与引用的只读关系；不支持范围明确报告，不伪造通过。
2. 他在配置参数网格中修改 CAN ID 与应用周期；参数名下说明同时更新的关联位置。Enter 经同一 prepare/apply 事务提交全部关联位置，Escape 还原当前草稿。输入被拒绝时原配置不动，错误保留在该单元格；修正后应用并校验，再预览和确认保存。“标准输入”页保留为补充入口。
3. 选择 Windows 受控目标及交接种类，预览源码；此步骤检查标准输入，但不运行编译器。他确认写入独立输出目录。
4. 在设置填写真实执行工具后，他**显式**执行编译预检；工具就绪不等于预检通过，预检报告也不代替构建。他选择独立构建目录再构建。
5. **高潮**：主机行为验证窗口显示本次构建的 CAN／DID／N_Cr 返回结果。他只记录主机结果，不宣称实机、完整 SC1 等级或标准认证。
6. 改选 Linux 目标后原结果变失效；在不支持该目标执行的宿主上显示“未执行：本机不支持所选目标执行”，仍区分源码准备与宿主执行，不显示假的 Linux 通过。

## 陈澄：接收交接、诊断联调及取消恢复

1. 接收工程师陈澄在内置规则已就绪的软件中使用 File 导入可重建主机交付包，或在标准 ECU 交付入口重导入 ECU 交接目录。两条入口各保留原动作名称，但进入同一工程壳层；不依赖原作者个人路径。新 R5 v2 核对同一兼容规则身份、所需已接受扩展与完整 seal／源配置／重渲染闭包，legacy v1 则走原有精确完整性兼容路径。
2. 如当前有草稿和未保存配置，导入先暂停，她可返回应用并保存；取消导入后原工程仍完整。新交接不携带、也不要求官方档案；规则不匹配明确拒绝或显式新目录迁移，所需可选扩展缺失只引导相应消费者的扩展导入，构建工具缺失才引导执行工具设置。
3. 在 CAN 工程诊断文档中，她建立 DID 的有序信号列表及可选单 DTC，依次应用，不把标准 ECU 的只读诊断当作同样可编辑。
4. 构建当前交付后，她选择对端工程和真实二进制执行双 ECU 信号运行，或独立诊断测试；标准 ECU 则使用自己的主机行为验证入口，不混用对端参数。
5. **高潮**：运行过久时点击取消，旧操作归属立即失效；若取消未确认，窗口保留具体错误，而不是伪造通过。晚到的旧结果不覆盖工程或目标。
6. 她重新检查适用输入／目标、显式构建和验证；交付文档、问题窗口和日志保持同一工程上下文，没有第二套“运行工作区”。
