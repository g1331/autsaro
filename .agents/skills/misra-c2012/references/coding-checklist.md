# 编码检查要点

这是针对本仓库 C99 的实现提示，以原创概括帮助检查实际改动；不列出全部 MISRA 条款，也不取代适用规范中的分类、例外与理由。只检查任务涉及的项，引用精确规则时另外核对原文。

## 数值与表达式

- 沿用公共类型或明确宽度/符号的类型。数据模型、`char` 符号性、枚举和位域的表示不要依赖宿主默认值；目标相关行为写明依据。
- 按 essential type 检查赋值、参数、比较、条件、位运算和复合表达式。C 的隐式转换合法不等于 MISRA 合适；强制转换也不能自动修复类别混用。
- 分析窄整数提升后真正参与运算的类型，再考虑结果类型。要扩大运算范围时在运算前选用正确操作数类型，并核对复合表达式转换限制；结果算完才转成宽类型不能修复之前的溢出。
- 检查有符号溢出、无符号回绕、窄化和符号转换。先证明范围，再转换；容量验证优先采用不会自身溢出的比较，例如先确认 `offset <= capacity` 再比较 `length <= capacity - offset`。
- 移位先验证移位量、有效宽度和操作数类型；处理有符号负值、除零及最小负值除以 `-1` 的边界。无符号常量使用适用后缀；不凭常量外观推断 essential type。
- 控制条件使用适用的布尔表达式；枚举、布尔、字符与算术值按用途区分。位操作使用合适的无符号类型，避免隐含符号扩展。
- 把状态修改和读取分成清楚的语句，不依赖未指定求值顺序；不要在同一复杂表达式中叠加赋值、递增、函数副作用。短路右侧、`sizeof` 或断言中的副作用要单独核对。

### 窄整数移位示例

目标约定：32 位 `int`/`unsigned int`，`uint8_t` 为 `unsigned char`，`uint32_t` 为 `unsigned int`。取位接口接受 0–7，其余输入返回零。下面展示把运算类型和移位范围同时明确的方式，仍需按项目实际规范与工具核对：

```c
#include <stdint.h>

uint8_t ReadBit(uint8_t value, uint8_t bit)
{
    uint8_t result = 0U;

    if (bit < 8U)
    {
        const uint32_t operand = (uint32_t)value;
        const uint32_t shift = (uint32_t)bit;

        result = (uint8_t)((operand >> shift) & 1U);
    }

    return result;
}
```

该目标下直接对 `uint8_t` 运算会先提升为 `int`；仅给最终结果加转换并不改变运算类型。`UINT8_C` 对应的是提升后的 `uint_least8_t` 类型，也不能据此断言运算使用无符号类型。此例先转换单个操作数，移位前验证范围，最终结果可证明只有 0 或 1。换目标数据模型时重新核对类型，不机械复制此例。

## 指针、数据与生命周期

- 为输入缓冲区、输出容量、指针有效性和所有权建立契约。依据实际契约选择入口校验，不对每个内部已保证的条件机械加入防御分支。
- 指针运算限定在同一个有效数组及允许的一过尾位置；一过尾指针不能解引用。不要用对象地址比较代替无依据的跨对象关系。
- 不通过指针/整数互转、去除 `const`、不兼容类型重解释或未对齐访问绕过契约。硬件地址等确实需要的目标特例需适用规则核对和受控偏离。
- 读取前保证初始化；局部对象地址不能逃逸生命周期。仅在无状态更改需求时增加 `const`，使用 `static` 限定真正的内部符号。
- 协议数据按已知字节序显式拆装，避免以宿主结构体布局、位域顺序或 union 重解释默认获得可移植编码。`memcpy` 等库调用须核对有效长度、重叠及错误前提。
- 新增动态分配、递归或 VLA 前先核对适用限制；优先使用有明确最大值的静态/调用方缓冲区和有界迭代，不为了方便引入未经论证的资源行为。

## 控制流、声明与接口

- 条件与循环体使用复合语句；循环的上界、进展和退出路径清楚可证。`switch` 核对枚举/整数类型、`default`、分支终结和贯穿规则，不用空分支掩盖输入错误。
- 删除本次引入的不可达/无效果代码，修复实际未初始化读取；不要为满足扫描添加无意义的赋值。
- 按有效类别处理单出口等建议；不要凭记忆把 advisory 当作 mandatory，也不要未经核对断言多出口天然符合。
- 用完整函数原型；无参数用 `(void)`，跨翻译单元的声明与定义一致。不要为规避未使用诊断删除标准回调参数或改变链接接口。
- 公共头文件防重复包含，避免保留标识符和名字遮蔽；AUTOSAR MemMap 等有意重复包含机制要按契约与规则例外/偏离核对，不能机械加 header guard 破坏功能。
- 可互换时优先函数而非带副作用的函数式宏；确需宏时保护参数和表达式、核对重复求值。条件编译使用真实构建配置，不能通过关闭分支伪造检查范围。

## 库函数、主机边界与生成器

- 校验函数返回的错误信息；区分“无错误信息的返回值”和“被忽略的失败”。不使用 `(void)` 丢弃来掩盖 I/O、转换或持久化失败。
- 主机 `stdio`、文件持久化和平台 API 可能与适用 MISRA 限制冲突。保留用户需要的行为和错误协议，尽量封装边界，明确实际规则、文件范围和必要偏离；封装本身不会让违规消失，也不能笼统宣布主机代码豁免。
- `volatile` 不提供线程安全或原子性。仓库的 C99 目标不能随意引入 C11 atomics/threads；若涉及异步回调、ISR 或共享状态，按实际执行模型证明同步和重入条件。
- 生成器处理配置中的最大值、零元素、枚举和符号名时，生成有效 C99 声明、常量及范围检查，不产生零长度数组、非法标识符或超界索引。测试相关最小/最大配置和拒绝路径，不猜测所有变体均已覆盖。
- 对实际生成的 `.c/.h` 复查，而不是只看 Rust 字符串模板。静态分析、编译和链接使用交付工程的头文件、宏与平台模型，不能借仓库其他头文件遮蔽生成错误。
