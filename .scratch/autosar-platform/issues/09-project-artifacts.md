## 问题

首版从空项目创建与导入已有 R24-11 ARXML 时，项目的权威保存格式是什么？如何处理多份 ARXML、引用与变型、未支持的标准配置项和厂商扩展，才能避免导入/保存丢失数据或生成半成品？决定支持范围内的导入→编辑→导出往返不变量、版本标识及迁移规则；不要引入与 ARXML 长期分叉的第二套项目配置真相。

## 讨论依据

- R24-11 ARXML 是项目配置的权威保存内容；工具内部模型不是并行维护的第二套持久化配置。
- 导入策略允许项目包含未支持内容，编辑已支持部分时保留其余内容；不采用“只要有未知项就完全拒绝可写导入”。这不允许静默丢失数据或破坏未知内容中的引用。
- R24-11 [ARXML Serialization Rules §2.1.1、§2.2.3—2.2.4](https://www.autosar.org/fileadmin/standards/R24-11/FO/AUTOSAR_FO_TPS_ARXMLSerializationRules.pdf)允许模型分散于多个 ARXML 文件；注释与处理指令可被工具忽略，但只允许 AUTOSAR 与 XML Schema Instance 两种 XML 命名空间。

## 答案

**R24-11 ARXML 文件集合是 ECU 项目配置的唯一权威保存内容**。可另存工具自己的文件清单和界面状态，但不得在 JSON/数据库中维护与 ARXML 并行的通信或模块配置。软件从空项目创建 ARXML，也能将多份 ARXML 作为一个项目导入，解析跨文件引用，保存时保留原有文件边界；目标代码输出到独立目录，不覆盖输入。

对未支持但符合所选规范版本的内容，允许编辑已支持的部分，同时在导入/编辑/保存往返中保留未知配置**元素、属性、值与引用的语义**；不承诺整个编辑后文件逐字节不变。未修改的文件不重写。若无法证明一次编辑不会破坏未知内容的引用或依赖，阻止该次编辑/保存并报告具体位置，而不是静默丢失内容或拒绝整个项目。XML Schema 不允许的第三方命名空间等不符合输入契约的内容，不按有效 R24-11 项目可写导入。

未支持的配置变体可以保留于项目，但若它影响本次要生成的有效配置，必须拒绝生成并指出受影响路径，不能擅自选择一个变体。首版不自动迁移其他发布版本的 ARXML；没有明确转换与验证规则时，版本不匹配的文件不得作为 R24-11 项目编辑或生成。生成结果、文件保存及往返不变量应纳入发布验证。
