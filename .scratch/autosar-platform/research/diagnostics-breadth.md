# CP R24-11 诊断“尽量完整”：范围与依赖证据（供决策，非决定）

**读法。** 这里的“完整”不能等同于“开启全部 UDS SID”：R24-11 Dcm 的 *SWS 实现范围* 有完整支持、仅 callout、用户可选及明确不支持的不同项；具体 ECU 还通过活动 service table、subfunction、会话/安全/认证及 DID/RID 配置决定实际可访问项。未列入活动表的 SID 返回 NRC `0x11`，功能寻址下某些 NRC 还被抑制。每个受支持档案应写明 **SID + 子功能 + DID/RID/DTC 来源 + 会话/权限 + 物理/功能寻址 + 传输协议 + 持久化/复位语义**，再逐项验收；这是对规范可配置性的项目化推论，不是 AUTOSAR/ISO 对“完整档案”的定义。[Dcm R24-11 §7.4.2，PDF 页109–110](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticCommunicationManager.pdf#page=109)、[§7.3.4.1、§7.3.4.3、§7.3.4.6.3，页87、89、97](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticCommunicationManager.pdf#page=87)。首个 CAN 信号闭环之后的先行 UDS/CanTp 增量已有[局部范围说明](diagnostics-expansion.md)，以下扩展的是**后续广度，不覆盖先行闭环**。

**横向前置条件。** UDS-on-CAN 是 `Dcm ↔ PduR ↔ CanTp ↔ LSduR ↔ CanIf/CAN`，不是 CAN 信号 Com 路由的自动复用；R24-11 CanTp 下层明确换成 LSduR。LSduR 与 PduR 可合并*实现*，仍需各自静态 ID 路由与 TP 接口语义；CanTp 负责 SF/FF/CF/FC、分段/重组/流控、错误与超时，PduR 转发而不解析 UDS payload。要从主机 CAN 帧到 Dcm 服务响应留可重放证据，覆盖完整多帧和拒绝/溢出/超时/序号错误、接收失败不交付半包，以及诊断服务的否定应答、时间、并发/取消边界。[CanTp R24-11 §1、§5.1.6–7、§7，页9、19–20、23、29–34](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_CANTransportLayer.pdf#page=9)、[LSduR R24-11 §1，页7](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_LSduRouter.pdf#page=7)、[PduR R24-11 §1.3、§5，页16、24](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_PDURouter.pdf#page=16)。**如声明跨进程重启保存**，需证明持久写回实际完成、故障注入后校验/恢复；NvM 的 NV block 通过 MemIf 与 Fee/Ea 抽象，`ReadAll`/`WriteAll` 属启动/停机时序，文件后端只能证明受支持主机配置的语义，不代表车规非易失硬件寿命或断电安全。[NvM R24-11 §5.2、§7.1.2、§7.2.1/§7.2.2，页19、25、43、48](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_NVRAMManager.pdf#page=19)、[Dem §7.11.5，页236–238](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticEventManager.pdf#page=236)。

**外部标准/不宣称事项。** Dcm §3.1 引 ISO 14229-1:2013、ISO 14229-1:2020、ISO 14229-2:2021、ISO 15765-2/-3/-4、ISO 15031-5 与 SAE J1979；§4.1 明确默认跟随 2013、仅选定采用 2020 条款，并列出不支持 `0x83`、`0x84`、`0x29` 的 ACR/DH 等；§7.4.2.26 将 `0x87` 列为用户可选。CanTp §7 还将未排除的 ISO 15765-2 建议委托给原 ISO 正文；DoIP §3.1 对照 ISO 13400-2:2019。即使官方 AUTOSAR 功能表标“Supported”，在未合法取得适用 ISO/SAE 正文、固定版本、测试向量和判定依据之前，也只能说“对 R24-11 指定配置与场景的主机行为”，不能称**全部 UDS/DoCAN/DoIP/OBD 法规或 ISO 一致性**。[Dcm §3.1、§4.1，页30–33](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticCommunicationManager.pdf#page=30)、[§7.4.2、§7.4.2.26，页109–110、224](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticCommunicationManager.pdf#page=224)、[CanTp §3.1、§7，页15、23](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_CANTransportLayer.pdf#page=23)、[DoIP §3.1，页11](https://www.autosar.org/fileadmin/standards/R24-11/CP/AUTOSAR_CP_SWS_DiagnosticOverIP.pdf#page=11)。[ISO 的 14229-1:2020 目录页](https://www.iso.org/standard/72439.html)现标明已被 2026 版取代；**这不追改 R24-11 对 2013/选定 2020 条款的引用**，若项目目标是最新 ISO 版，则须另行确认与 R24-11 的差异。未审阅付费 ISO/SAE 全文，不把目录摘要充当一致性判据。

## 决策前比较的两种宽度/顺序（以下为当时的推论）

1. **广度优先、逐功能族形成有界可验档案**：CAN 传输与会话/动态 DID；再 RAM Dem 的 `0x19/0x14/0x85`；再持久 DTC、`0x27` 与有意义的写入/例程；随后认证、编程、OBD、DoIP/J1939 依被选目标分别纳入。每段显式列出拒绝/不支持项及持久语义。优点是尽早覆盖多族；代价是若目标是早期深度完整/持久化，还需额外回填。
2. **深度优先、先把 CAN 诊断档案做全再扩媒介/领域**：选定 CAN UDS SID/子功能/DID/RID、双向多帧、Dem 与 NvM、权限及失效恢复，逐项通过真实主机状态/故障实验；然后再选 DoIP、OBD、J1939、编程/启动交接。优点是每次宣称支持都有更强端到端证据；代价是横向功能族较晚上线。

**后续决策**：上述广度与深度路线曾作为比较选项；[阶段扩展路线](../issues/08-expansion-route.md)确定先做深一个包含 Dem/NvM、受限访问和失败恢复的 CAN 诊断档案。OBD、DoIP、J1939、真实刷写及 ISO/SAE 一致性声明不自动包含在内，分别验收。
