# Classic R20-11 资料盘点与版本基线（研究记录）

> 历史快照：本文盘点时本地存在的 26 份 R20-11 PDF 选集现已删除；下文的“现有”“本地”均指当时状态，R20-11 调查建议已由 CP/FO R24-11 产品基线取代。

**结论。** `docs/official/R20-11/CP/` 是一个有用的 CAN／诊断／通信及 OS、RTE 入门选集，**不是** Classic R20-11 的发布全集，也不是可直接生成 ECU 软件的配置交付包。按本次实际目录清点为 **26 个 PDF：19 SWS、3 SRS、3 EXP、1 TR**；未见 TPS、MOD、ARXML、XSD。这里的“缺失”仅指**本地选集与官方 R20-11 清单的差集**，不表示某一个具体 ECU 必须部署清单中每个可选协议、驱动或服务。官方 [Classic Release Overview §3／表 3.1，PDF 页 22–30](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=22) 将发布物分成 Release Documentation、Communication、Memory、System Services、MCAL、IO、Libraries、Diagnostics、Safety、BSW General、General、Methodology and Templates、Mode Management、RTE、Application Interfaces、Crypto、Global Time、SWArch、Security **19 类**；另有与之配套的 [Foundation R20-11 清单 §3／表 3.1，页 19–21](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_TR_FoundationReleaseOverview.pdf#page=19)。

## 2. 生成器除了模块 SWS 还需要什么

- **模板、语义及模型。** 补齐 CP 表 3.1「Methodology and Templates」的 `AUTOSAR_TPS_SystemTemplate`（System/ECU Extract）、`AUTOSAR_TPS_SoftwareComponentTemplate`（SW-C）、`AUTOSAR_TPS_BSWModuleDescriptionTemplate`（BSW 描述）、`AUTOSAR_TPS_ECUConfiguration`（ECUC 参数定义与值）、`AUTOSAR_TPS_ECUResourceTemplate`、`AUTOSAR_TPS_DiagnosticExtractTemplate`、`AUTOSAR_TPS_TimingExtensions`，及 `AUTOSAR_MOD_ECUConfigurationParameters`（官方清单标为 XML 模型工件，**不是 PDF**）；按功能补 `TPS_SafetyExtensions`、相关 RS、应用接口模型/例子。[CP 表页 27–29](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=27)。不可仅用 XSD 推断跨对象语义与约束：ECUC 模板对 M1 约束设有不同 binding time（如配置定义完成、代码生成时），见 [TPS ECUConfiguration §1.2–1.3，页 20–22](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TPS_ECUConfiguration.pdf#page=20)。
- **Foundation R20-11 同基线。** CP [Release Overview §1.3.5、§1.4.5](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=9) 写明依赖 FO R20-11、内部版本 `R4.6.0`、schema `AUTOSAR_00049`；补 FO 的 Meta Model、Generic Structure Template、[XML Schema Production Rules](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_TPS_XMLSchemaProductionRules.pdf#page=8)、[ARXML Serialization Rules](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_TPS_ARXMLSerializationRules.pdf#page=12)、Standardization Template、模型约束与 [实际 XSD ZIP](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_MMOD_XMLSchema.zip)，以及启用通信／安全功能时的 FO PRS（如 SOME/IP、SOME/IP-SD、E2E、SecOC、Network Management、TimeSync）。完整 FO 列表见 [FO 表 3.1 页 19–21](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_TR_FoundationReleaseOverview.pdf#page=19)。本次实际打开该 ZIP，内含 `AUTOSAR_00049.xsd`、`xml.xsd`、catalog、说明；内附 `_readme.txt` 称 **仅 `AUTOSAR_00049.xsd` 是该包的 STANDARD 文件**。不能把 schema 生成规则 PDF、schema ZIP 或 XML 配置实例混为一物；FO [序列化规则 §2.2.4](https://www.autosar.org/fileadmin/standards/R20-11/FO/AUTOSAR_TPS_ARXMLSerializationRules.pdf#page=12) 说明 XSD 不按 CP/AP 分出独立的 Classic-only schema。
- **方法论与具体输入。** 增补 [CP `TR_Methodology`](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_Methodology.pdf) 的工作产品/集成与配置流程，并获取实际 ECU 的 System Description／ECU Extract、SW-C descriptions 与实现、BSW module delivered bundles、标准化/厂商特定 module definitions、ECUC values、诊断 extract、网络矩阵、资源/时序/内存映射与变型选择（取决于启用模块）。[TPS ECUConfiguration §1、图 1.1–1.2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TPS_ECUConfiguration.pdf#page=16) 明确 ECU Extract + BSW Module Delivered Bundle 是 ECU 配置输入，配置参数定义和值描述分别是工具与生成器的依据；工具策略、生成可执行代码本身**不在**该模板规范范围。要实现完整 RTE/BSW 生成器，还需按各启用模块 SWS 的 API、配置章及相互依赖实现，不是“从 PDF 自动得出完整 C 工程”。[R20-11 RTE SWS 的 generator 章节](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_RTE.pdf) 同样列出 contract、配置、generation 等阶段。
- **实现方与硬件资料。** 针对选择的 MCU/板卡收集 datasheet、reference manual、silicon revision/mask errata、启动/中断/时钟/引脚/Flash/RAM/安全外设、收发器、编译器 ABI/linker、调试器及安全手册（如适用）；实现方交付的 BSW 实现与 BSWMD、VSMD、可用的配置插件、版本/限制说明要与这套硬件及 release 配对。这是实现新开源代码的**输入约束及兼容性验证对象**，不要求复用某既有栈。依据：[CAN Driver §5.2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_CANDriver.pdf#page=21) 将 on-chip CAN 初始化、pin 配置、MCU 共享寄存器及 off-chip SPI 交互区别对待；[OS SWS §4.5–4.6](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_OS.pdf#page=22) 限定硬件假设。厂商资料的**例子**是 [NXP S32K3 产品资料入口](https://www.nxp.com/products/S32K3)；具体芯片未选，不能把该型号当既定目标。

## 3. 外部引用标准按启用功能取证、锁版

这不是“所有 ECU 必须采购全部标准”的清单，也不能仅由一份 PDF 推出所有适用标准；应对每个拟实现模块的 **Related standards/norms**、FO PRS 和具体车型法规建依赖表。已在一手规范中核实的样例：

| 场景 | 一手引用与适用边界 |
| --- | --- |
| CAN/FD 驱动 | [CAN Driver §3.2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_CANDriver.pdf#page=19) 引 ISO 11898、ISO/IEC 7498-1 与 CiA 601-2；具体采用的版次需与 R20-11 功能和硬件匹配，不能无审查地替换成后出的修订。|
| 诊断／DoCAN／OBD | [DCM §1、§3.1](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_DiagnosticCommunicationManager.pdf#page=22) 引 ISO 14229-1/2（UDS）、ISO 15765-2/3/4、ISO 15031-5/6、SAE J1979；它还说明 J1939 诊断不在普通 DCM 范围，应另看发布表中的 J1939 SWS 与 SAE J1939 相关标准。具体受法规约束的功能/版本须按目标市场另判。|
| OS／BSW C 实现 | [OS §3.2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_OS.pdf#page=20) 引 ISO 17356-3（OSEK/VDX OS）、-6（OIL）；[BSW General §3.2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_SWS_BSWGeneral.pdf#page=10) 引 MISRA C:2012 与 IEC 7498-1。|
| Ethernet／新物理层 | [CP Overview §2.1.1、§References](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=13) 指出 10BASE-T1S 所依 IEEE 802.3cg，以及 OPEN Alliance 的车载以太网睡眠/唤醒规范；仅选用相关驱动/PHY 时再锁版。|

## 4. 建议基线与未决核查

1. **先固定试验/实现基线为 CP R20-11 + FO R20-11 + `AUTOSAR_00049.xsd`（内部 `R4.6.0`）**，因为现有选集已围绕 R20-11；按 CP、FO 官方清单登记每个文件的编号、类型、状态、发布日期/修订、获取位置及适用模块。真正面向新项目时也可以重新选一个较新、与硬件及交付工具相容的 CP/FO 配对，但必须整体迁移并重新评估 schema、配置与外部标准，而非混用不同发布的 SWS/TPS/XSD。[CP Overview §1.3–1.4、§3](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=8)。
2. **分阶段覆盖，不将“全模块”误作单一 ECU 镜像**：优先补基础 TPS/FO 与 OS、RTE、MCAL、Memory、EcuM、BswM、COM/CAN/诊断关联规范和可执行配置；再对照表 3.1 扩到 LIN/FlexRay/Ethernet、加密/安全、V2X/J1939 等可选功能。每阶段核对 SWS + BSW General + TPS/模型 + 外部协议 + 具体硬件／配置／实现交付的闭环。[CP 分类清单](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=22)、[TPS ECUC 输入流](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TPS_ECUConfiguration.pdf#page=17)。
3. **有界不确定性**：本文只清点本地 26 个 PDF 文件名、读取若干代表文档及官方两份 release overview／ECUC／Methodology／FO schema 资料；未逐个比对所有 PDF 的封面修订、官方发布哈希、各模块 Known Limitations、后续 issue notices，也没有完成所有外部标准的版次／授权调查。CP [Overview §4](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=31) 列有多项已知技术缺陷，采用前要逐项核实。官方材料[版权/许可声明，页 2](https://www.autosar.org/fileadmin/standards/R20-11/CP/AUTOSAR_TR_ClassicPlatformReleaseOverview.pdf#page=2) 涉及用途与许可；本文**不作**开源再分发或衍生实现的法律结论，应独立核实当前条款和拟用第三方标准的获取与许可。
