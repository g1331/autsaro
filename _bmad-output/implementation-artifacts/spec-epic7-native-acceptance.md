## 授权与目标

继承用户已批准完整 Epic 7，实现 7.11 必需出口的独立实际验收分支并从非实现者视角取证，不把单项 test 或 mock 当出口。先读取 bmad-build 技能，仅运行一次正确 renderer：`uv run --no-cache "D:/Codebase/Autosar/_bmad/scripts/render_skill.py" --project-root "D:/Codebase/Autosar" --skill "D:/Codebase/Autosar/.agents/skills/bmad-build"`。本 slice 不修改被验收的产品实现；发现真实缺陷发给其负责人。

## Target / Ownership

独占 `scripts/autosar_tooling/{native_profile.py,desktop_scenario.mjs,desktop_windows.py,desktop.py}`，必要时同目录新增 builtin-only scenario/helper 和参数分派；CLI 的新增选项若定义在其他文件，通过真实位置发消息给协调者再授权。允许新增同子系统的真实验收测试，不改 core、Tauri、UI、runtime、官方 fixture 与别人的 specs。不得运行可见窗口或占用户输入、焦点/桌面。Windows 使用现有 private desktop；Linux 使用现有隔离 WebDriver/Xvfb 路径，native 进程并发不得超过 2。禁止在父任务仍写共享实现时重检查；准备好后等待中央队列授予具体运行槽。

## Code Map

`native_profile.prepare` 现有强制使用 `AUTOSAR_XSD_ARCHIVE/AUTOSAR_MOD_ARCHIVE` 并复制旧 seven-file fixture、reference v1，installed 检查 checkout 已搬离；`app_environment` 清除原规范环境、安装态移除开发语言工具。该旧分支必须保留，不能删除 resource 注入/旧 v1 验证来伪造离线通过。新 UI 源码集中 `ui/src/App.tsx` 和 `workbench/useWorkbench.ts`，有真实 metadata projection、ChangeSet、模板/member/save-as、设置/主题 IPC；具体协议在 UI spec 和 `core/src/project_model.rs`，用真实 UI/IPC 获取身份，禁止复制 mock 返回。

## Change

1. 新增显式、独立 builtin-only 验收模式，保留旧 development/oracle/v1 路径的全部拒绝边界。普通用户安装环境不得提供官方规范文件、源码 checkout、开发语言工具或编译器；离线验证真实新建/打开/源查看/通用编辑/预览应用/保存重开/校验/源码交付，执行工具只在独立工程消费者阶段提供。
2. 覆盖 epics.md 7.11 所有 AC 和 PRD CFG-1–CFG-4 出口：两个不同原创 CAN 工程、七文件标准及不同 ID/周期变体、多模块七值类型/default/普通引用/跨源批次/结构创建改名移除、未知只读和关键拒绝/字节保留。输入不能仅同路径复制；必须实质改变配置数据与独立预期。
3. 无头 native actual WebDriver 表面验收统一树/文档/属性/工具窗口、settings 类别隔离、light/dark/system、1480×920 与1080×720、键盘/焦点/草稿守卫/问题跳转、owned 日志完整详情与有界摘要、取消和晚回调。保存截图和实际结构化结果于私有运行 scratch，不能提交原机器凭证或规范资料。读真实表面，不以 DOM 字符串存在替代操作行为。
4. 获准后实际运行隔离 Windows/Linux 发行组合出口；从重新打包或已搬离的构建副本启动发行产物，断网和 unavailable archive/checkout 边界必须可观察。独立工程消费者提供声明的目标工具链，另行执行生成源码构建与真实 CAN/DID/N_Cr/恢复/旧目标行为，结果分开记录。不把 macOS 无宿主改为 Windows/Linux 通过的替代品。
5. 对扩大输入与快速筛选/展开记录可比的快照复用、输入 responsiveness、内存/有界日志行为，验证后台索引/解析且不造通过结果。发现 UI/backend locator/能力不符仅通知负责人，正确适配新的真实表面，不弱化用户可见断言。

- 新增 `native_builtin.py`、`desktop_builtin_inputs.mjs`、`desktop_builtin_scenario.mjs` 和 `native_consumer.py`：真实身份/当前 token、不同 CAN ID/初值/周期、七源标准变体、多模块七值种类与不同普通引用目标、absent/default/explicit、结构/入站闭包、整批/过期/外部变化/路径/缓存拒绝及原字节检查。截图与完整真实 IPC 结果仅写运行 scratch；源码成功和独立构建/行为状态分开。

- `native_station.py`、`native_clipboard.py` 与 CDP/WebDriver 真正键盘/鼠标动作准备了独立 Windows WindowStation/Desktop 或私有 Xvfb 的全文复制验证。Windows 普通私有 Desktop 属于 WinSta0、共享用户剪贴板，不能作为剪贴板隔离。当前 medium token 下无窗口探针观察到：匿名 CREATE_ONLY station 返回 WinError 183，唯一命名 station 返回 WinError 5；不重用共享 station、不降级到用户剪贴板。
- `native_offline.py` 在独立 Linux user/net namespace 内只启用 lo，观察接口、路由与内外 namespace 身份；`native_windows_offline.py` 只对本次私有 app/WebView2 副本创建非 loopback 出站拒绝规则，finally 删除本次规则并保留实际回执。`native_elevate.py` 准备一个有界、明确授权的 UAC 控制器启动、计划摘要、取消与退出状态协议。用户已通过协调者授权提升验收控制器，但发行运行仍等待中央冻结/运行槽；没有实际触发 UAC、修改防火墙或关闭用户网络。
- Windows controller 与产品权限已分离：`native_token.py` 使用实际 linked medium primary token 启动产品，并检查 child token 的非提升/medium 身份；只有 controller 允许提升。新私有 scratch 在任何输入创建前设置继承 Medium label，避免 verifier 的高完整性文件阻断普通产品写入；范围仅本次新目录。上述提升路径尚未实际运行。
- 两尺寸不靠虚拟 viewport 冒充 native window：`native_window.py` 对已确认属于 app PID 的唯一私有窗口使用 `SetWindowPos`，明确 `NOACTIVATE`；观察实际物理尺寸并恢复 controller 线程 DPI context。Linux 使用真实 WebDriver window rectangle；结果另外记录实际 CSS viewport。共享 station 的 resize 请求在访问 OS 前拒绝。
