## Change

1. 依据 epics.md 7.10 全部 AC，实现 normal builtin host/CAN 与 standard ECU 的纯源码准备，编译器缺失只限制执行；精确 rule/definition/实际输入身份进入准备/确认，不读取官方规范。源码生成 preview 不编译，确认只安装已经预览的字节。
2. 新内置交接只用 `autosar-workbench-handoff-v2`。精确记录来源类型、真实规则三字段、实际必需接纳扩展、配置/成员/应用输入和拥有权。Builtin/legacy 精确分派，原 host/ecu v1 的 fixed oracle hash、完整来源闭包、重渲染拒绝与 seal 全保留，不自动升级、不伪造复制来的规则身份。
3. `workbench-ownership.json` v1 按真实来源区分配置、user application、产品/生成/目标/构建；未知 owner/version/范围、生成文件改动、未经核定移除全部拒绝。ledger/payload/application snapshot 全进入原严格 seal，不能不在 files.list/files.sha256 中。
4. 初始应用槽仅 `epic4-single-application-v1`，descriptor 来自实际 component contract；显式初始化仅创建不存在的源，永不覆写 live user application。再生成 live 用户代码不进入输出可写集合；封存 snapshot 不可修改。声明的 applicationInputs、用户文件外部变化、缺失、路径/链接风险、旧预览均真实核对。生成所有接点必须完整，不交 placeholder 或 mock。
5. 导入先验 seal 和本机 trusted RuleSetIdentity 三字段完全相同，再从真实 inputs、accepted catalog、application 数据重建/校验/重渲染，逐字节比较整个拥有权闭包；腐败、旧身份、冲突、晚确认保留旧输出和当前工作区。
6. 保持独立输出可用，不静默引用作者机器 checkout；生成工程中的用户输入边界和独立源码/封存使用方式写入已有生成 README 模板。编译与真实 CAN/DID/N_Cr/恢复复验由中央队列和独立接收者实施。

## Implementation Notes

- rule/definition/source/UI 既有并行任务仍由其负责人编辑；中央 IPC 是协调者。本任务是生成/封存文件独立 wave，原基线及 Epic 冻结意图不变。

- 生成／源接点提案：source owner 提供 `Workspace::generation_snapshot() -> Result<GenerationSnapshot,String>`，类型由 `arxml` 拥有并公开；snapshot 包含 `manifest:ProjectManifest`、`manifest_bytes:Vec<u8>`、`manifest_path:Option<PathBuf>`、`project_root:Option<PathBuf>`、`inputs/applications:Vec<GenerationInputSnapshot>`，各输入含 `logical_path:String`、`disk_path:PathBuf`、`bytes:Vec<u8>`。方法核对 saved/current、完整成员、接纳定义与外部源身份，不把未保存／磁盘变化交给生成器猜测；直接 ARXML 的 manifest 为真实来源映射的派生交付表示。
