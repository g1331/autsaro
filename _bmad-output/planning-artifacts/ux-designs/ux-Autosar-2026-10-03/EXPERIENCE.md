# 产品界面与交互基线

## Foundation

本文件是**已完成并由用户暂时定稿的设计基线，不是正式软件实施或能力验收记录**。2026-10-03 用户确认本轮界面与透明珊瑚 A 图标“暂时定稿”；final 表示规格已完成，后续实施仍须经过选定范围的需求／架构收口、故事拆分及就绪检查。本轮不改 `ui/src/`、桌面后端及运行时；旧 logo 候选及无领域特征的抽象方向已撤回。

主要使用者为 ECU 集成工程师与 BSW 开发者，交接接收工程师也是完整流程参与者。保留产品名称“Classic CAN 配置工作台”与已有工程基础；logo 采用用户暂时定稿的 A 形体及透明珊瑚材质，撤回绿色适配和近似 Toolbox 的橙粉紫转色。[A 与界面对照](mockups/logo.html)保留材质版与平面原色比较，主行动用珊瑚实色建立关联，图标色层不铺到工程工作区；正式软件未改。工程树＋对象表＋属性检查器、JetBrains 式菜单和工具窗口、ChatGPT 式中性壳层及对象／结果角色保持完整体系。

身份图形外围、车窗和灯位留白为真实透明背景；浅色石墨灯位与深色暖白灯位共享车身 RGB 和 alpha。外观“应用”及“跟随系统”的有效主题变化同步切换图形，不重建工程或丢弃设置草稿。已在无头浏览器实际验证四组图形／主题组合、外观应用与系统明暗切换；桌面通用导出采用固定中性灯色，未验证操作系统安装或原生主题联动。

视觉权威为同目录 [DESIGN.md](DESIGN.md)，行为权威为本文；[交互原型](mockups/index.html)仅佐证布局和关键交互，冲突时两份规格优先。正文、选择、面板间距与文字尺寸分别引用 `{colors.text-primary}`、`{colors.selection}`、`{spacing.panel}`、`{typography.body.fontSize}`，不在行为规格复制色值。浅色、深色和跟随系统共享所有权、导航与状态逻辑。

日期工作区在本轮结束后作为冻结评审基线；根目录 DESIGN.md 将导出对应视觉规格，正式实现开始时以根目录当前视觉权威为入口，不另建并行状态或规格文件。原型初始为已保存、已校验的 CAN 样例，三个示意帧／六个 unsigned little-endian 信号；这些是内存场景，不代表真实校验或 scaling 能力。缺失规范档案、取消及失效也只是可切换评审场景。

### 能力与设计的三种陈述

- **EXISTING／已有能力**：以下操作映射中的当前 Workbench 方法与现有 UI 处理器；后端决定输入是否安全、剖面是否支持及结果是否有效。现有 UI 尚不是本文描述的统一壳层。
- **PROPOSED／拟新增界面行为**：统一菜单、持久工程树、对象／文件筛选、中心文档标签、问题焦点接力、主题和快捷键，以及不丢草稿的导航保护。它们是本次设计要求，不宣称控制器已经全部实现。
- **FUTURE／未支持产品目标**：通用 R5 ECUC 参数编辑、多 SWC 连接编辑、批量修改、MCU／真实硬件控制、ComM／NM 等扩大模块覆盖、学习层、Adaptive、认证及任意 ECU 工程的完整 SC1 等级验证。本轮不提供假入口、不用示例生成结果替代这些能力。

事实依据为 PRODUCT.md、当前规划，以及 `ui/src/workbench/useWorkbench.ts` 公共接口（117–196 行）、各操作实现、`forms.ts` 和现有 App／EditorPage／DiagnosticsPage／IntegrationPanel／IntegrationDelivery／BuildPage／VirtualPage／SettingsPage 处理器。这是当前操作到新界面的映射，不另建项目完成度或保证等级矩阵。

### 工程剖面边界

**CAN 信号工程**：有界多文件 ARXML；Classical CAN 标准 11 位 ID、DLC 1–8。帧可创建及修改名称、ID、DLC、Tx/Rx、Tx 周期或 Rx 超时；信号可创建及修改名称、起始位、1–32 位长度与初始值，按所属帧容量校验，当前为 unsigned little-endian 链。名称遵守已有标识符规则，字段输入与内核校验均不可绕过。当前没有任意帧／信号删除操作，不添加“删除对象”菜单。

诊断为单条 11 位物理 DoCAN 连接及一个 DID：配置请求／响应 ID、S3、N_As／N_Bs／N_Cr，按顺序选择 1–8 个不同的 32 位 Tx 信号。可选 DID 写入 0x2E、依赖写入的复位 RID 0x31/0x01，以及有界 0x27 单级 seed/key。关闭写入清空复位 RID；密钥不写入 ARXML，运行时独立文件提供，该安全档案仅限已有 Windows 主机虚拟目标。可选单个 DTC，代码 0x000100–0xFFFFFE，绑定已有信号且超时大于零的 Rx 帧；先应用 DoCAN 再配置 DTC。相关 Dem／主机文件 NvM 行为不等于完整 Dem、硬件存储或符合性。候选列表由真实资格条件产生，不允许自由填入不存在的引用。

**标准 ECU 工程**：导入后依据后端 `integrationCandidate`／检查计划识别，不由用户强行切换剖面绕过限制。只允许编辑计划中的 CAN ID（0–2047）和应用周期（1–2147483647 ms）。类型、端口、诊断、组件及引用映射只读；不能调用普通帧／信号创建器作为旁路。未能获得有效 description 的输入显示具体计划诊断，而不是伪造可编辑通用 ECUC 表格。只读关系可浏览、定位，但不能重接或创建。

## Information Architecture

### 单一壳层与焦点

固定区域按顺序为：应用菜单、紧凑工程／上下文操作条、左侧工具图标轨与一棵持久工程树、中心文档标签与内容、右侧检查器、底部工具窗口、固定状态栏。无工程时显示起始页；设置始终可达。项目切换不是页面切换，必须走保护性工程关闭流程。

- **工程树**只有一份，提供“对象／文件”两种视图及作用域明确的筛选。对象视图包含 CAN 帧／信号、诊断节点，以及标准 ECU 计划实际提供的组件／端口／类型／引用节点；没有数据的未来模块不预占目录。文件视图为原始配置集合，标示只读与保留项。应用源码、生成输出和构建路径显示不同归属，不混为可写 ARXML。
- **中心文档**为 CAN 通信、诊断配置、标准输入／集成、源文件只读视图、源码交付。标签复用同一逻辑文档，不每次选中创建副本。树选择对象时切到所属文档并定位表格行；表格选择反向同步树和检查器。诊断参数编辑与“问题”是不同用途，不再把诊断检查结果伪装成诊断配置页。
- **检查器**固定“属性／引用”切换；属性展示当前对象路径、所属文件、可编辑字段及应用／还原；引用只显示真实关系并支持已有对象定位。关闭面板不关闭对象、不丢草稿。源文件显示绝对路径、访问权限和保留项信息。原始源文本只读查看是拟新增呈现；当前控制器已有文件元数据，未提供独立任意源文件读取方法，正式实现不得把演示文本当作真实文件内容。
- **底部工具窗口**为“问题／生成／构建／主机验证／操作日志”，同一时刻展开一个，切换不卸载编辑草稿。问题呈现 severity、code、message、对象路径与来源文件；生成呈现输出文件／差异／归属；构建和主机验证显示其真实日志；操作日志按实际返回事件保留本次会话记录，不宣称已有持久审计后端。
- **状态栏**仅给当前工程剖面、未应用／未保存提示、目标／宿主、当前操作或结果摘要。点击摘要打开对应窗口；不放新的保证等级总表。

## Voice and Tone

用简体中文表达任务；AUTOSAR、ARXML、CAN、DID、DTC、模块名、路径和错误码保持准确原文。普通界面称“CAN 信号工程”“标准 ECU 工程”，不把内部历史标识暴露成产品分区。

动作使用结果明确的动词：“应用更改”只改内存工程，“预览保存”不写文件，“确认保存”写原始配置集合，“预览源码”不编译，“确认生成”写独立输出。“校验无阻断错误”不写成“工程完全正确”；“主机行为验证通过”不写成“实机通过”。

错误按“发生什么＋影响范围＋下一步”组织，并保留原始错误码／详情。例如：“标准输入编辑被拒绝，原配置保持。检查 CAN ID 对应的端口诊断。”依赖缺失写明 XSD、MOD 或具体可执行文件，不把所有情况统称“环境错误”。取消请求尚未确认时用“取消未确认”，不可提前宣称进程关闭。

正常软件壳层不放设计解释或大段免责声明。能力边界在只读提示、不可用原因和帮助中就近说明。原型的“仅评审演示：所有数据及结果均在内存中，不进行文件、编译或 ECU 操作”提示置于模拟软件窗口之外，并始终可见；演示完成提示也不构成实际检查证据。

## Component Patterns

### 树、表、检查器

树节点以真实路径和对象类型识别，显示名不是唯一键。筛选范围区分“工程树”和“当前对象表”；筛选隐藏选中对象时保留选择与草稿，提示“当前对象不在筛选结果中”，不能自动选另一行。清空筛选恢复原展开位置。定位问题必要时临时揭示目标，并让使用者恢复原筛选。

表格保留工程数据列、单位、方向、只读属性；允许横向滚动，不将每行变成装饰卡片。选中使用 `{colors.selection}`，键盘焦点与选中不是同一状态。新建信号必须有明确所属帧，不能凭搜索结果位置猜归属。

检查器标题同时给名称／类型，路径和所属文件可复制。可编辑字段有独立 label、单位、范围和错误；只读字段为可选取文本并说明剖面限制，不伪装成禁用输入。应用成功保留同一对象焦点；改名后依据返回路径重定位。拒绝应用时保持原配置及所有输入，以便修正。

### 保存与生成预览

保存差异对话框列出整个文件集合、每个文件是否改变、路径、before／after 与差异；默认首个改变文件。生成预览列出 new／changed／unchanged 等后端状态、输出目录、交付种类、目标、文件归属与内容。二进制或不可展示内容明确说明，不显示空白假文本。

两个预览使用一致文件导航，但标题和确认动词严格不同。确认绑定预览的 revision 与当前输入身份；任何相关变化使旧预览失效，必须重新预览，不能把旧确认迁移到新目录或新目标。无变化时说明“没有需要写入的更改”，不鼓励空保存。关闭预览只放弃确认，不还原配置、不清除编辑草稿。

ARXML 属于用户配置集合；生成文件属于选定输出；构建产物属于独立构建目录；应用算法与既有用户代码不是可静默覆盖的生成物。展示后端实际拒绝或冲突，不能用设计层自动删除目录、改写源码或接受危险引用。

### 设置

三个导航项为“外观／官方资源／执行工具”。打开设置克隆当前值形成独立草稿；保存仅提交当前类别，其他类别仍是草稿。关闭丢弃尚未保存的设置草稿，不改变工程草稿。外观立即预览但关闭恢复已保存选择；主题保存是拟新增界面行为，不冒充现有 configureResources。

XSD／MOD 必须由使用者合法取得并显式指定；不捆绑、下载或借用交付包中的受限档案。正式软件调用 `configureResources` 核对固定摘要并原子保存，环境变量覆盖优先于保存值并明确列出。输入合法路径不等于档案身份已核对。

执行工具为 compiler、objdump、Git、锁定 CPython 的绝对可执行文件路径。设置保存成功不等于预检通过。配置和纯源码准备不要求自动运行编译器；现有资源门控仍应忠实呈现：当前通用 `disabled` 包含资源缺失，执行额外受 nativeExecution／toolError 限制。不能把“未来配置可独立使用”误写为所有现有导入／编辑在缺 XSD/MOD 时已可用。

## State Patterns

### 草稿、工程与结果分层

1. **未应用草稿**属于对象或配置文档，尚未改变内核工程。普通字段、诊断、DTC、标准参数草稿分别管理，不以一个“已保存”灯覆盖它们。
2. **已应用但未保存**属于当前内存工程；应用成功后才更新表格／引用，显示未保存，旧校验／生成／构建／运行结果失效。
3. **已保存配置**以返回 workspace 和实际 SaveOutcome 为准。后端仍 dirty、部分保存失败或返回 error 时不能显示完全保存。
4. **操作结果**绑定工程输入、资源、目标、产物和当前操作身份；存在旧文件不证明本次生成或构建成功。

现有阶段为 pending／running／done／failed／stale。界面分别写“尚未执行／正在…／完成／失败／已失效”，并给具体原因。标准 ECU 预检是单独报告，不把它增加为新的后端保证阶段；原型可用本地 `preflight` 演示状态表示报告生命周期，但不能声称已有控制器预检阶段存储。

### 不丢草稿

面板折叠、底部窗口切换、主题、设置、筛选和非破坏性标签切换都保留工程草稿。工程对象切换、关闭有草稿的标签、新建对象或问题定位若会替换当前编辑上下文，先提供“应用并继续／放弃草稿／留在当前对象”；应用失败不继续导航。只能在所属剖面允许应用时提供第一项。此三路保护是 PROPOSED；现有 `choose`／`openCreator` 主要为放弃确认，不能直接调用后再补救。

切换工程、重开来源、两种交接重导入须先解决全部未应用草稿及 dirty 工程：“返回并保存／明确放弃／取消切换”。返回保存需完成应用、预览及确认后再继续，不能自动写盘。现有导入方法没有所有入口一致的前置保护，因此新壳层必须共用一个切换入口，并复用 `confirmDiscard`／后端关闭约束。标签关闭不是关闭工程；不自动清掉全局 workspace。

“还原”只回到当前已应用值，不撤销历史内核修改；全局历史撤销及跨重启草稿恢复不在当前能力内。桌面退出保护属于拟新增界面要求，不能声称已有崩溃恢复或自动保存。

### 取消、失效与异步归属

现有 `call` 使用 epoch 和 capabilities fingerprint；不匹配结果以 STALE_DELIVERY 拒绝。新壳层保持此约束：旧操作结束不能覆盖新工程、重新选中的目标或更新后的文档。串行后台任务期间禁用会改变输入的动作，仍可查看日志／切换非破坏性工具窗口，提供“取消当前操作”。

取消先使本地任务归属失效，运行中阶段转 stale，再请求后端取消受管进程。确认成功显示旧结果未提交；取消失败保留错误及恢复建议。取消不是文件系统回滚承诺：已完成的写入以返回状态／实际重新读取为准，不宣称任何输出一定未改动。

- 应用对象／标准参数：保存、校验及下游结果失效，保留新对象焦点。
- 保存成功：配置变为已保存，下游回到尚未执行，不继承旧运行通过。
- 官方资源改变：校验失效，生成预览及产物归属清空，下游须重做。
- 工具改变：当前控制器也清除生成预览与生成／构建／运行结果，界面不得偷偷保留“已生成”成功摘要；预检报告同步失效。
- 目标改变：取消旧任务归属；生成预览、生成、预检、构建、运行结果不再适用。配置和原始文件不变化。目标切换失败不假显示新目标已启用。
- 标准输出目录或交付种类改变：清除生成及下游；构建目录改变只使构建／运行失效；对端目录改变清空对端二进制，对端二进制改变清除运行结果。

以上规则是结果生命周期说明，不要求使用者手工勾选状态，也不建立另一套状态矩阵或审批关卡。

## Interaction Primitives

单击树／表选择；双击或 Enter 打开所属文档；键盘箭头遍历、左右展开收起树。菜单与快捷键统一经过命令路由，按剖面和草稿计算可用性。Ctrl/Cmd+K 打开命令搜索；Ctrl/Cmd+S 进入预览保存而非静默保存，有草稿先提示应用或还原；Ctrl/Cmd+O 进入导入路径流程并遵守工程切换保护。Alt+1 切换工程树、Alt+4 打开构建窗口、Alt+9 打开主机验证。Escape 依次关闭最上层对话框／菜单，再关闭活动工具窗口并返回调用者，不丢草稿。焦点在编辑字段时不能让全局快捷键吞掉文本输入。标准复制操作复制文本，不新建工程对象。命令搜索仅搜索当前可用命令，不承诺工程内容全文搜索。

问题定位接力为：选择问题 → 解析真实对象 path／file → 处理当前草稿 → 揭示工程树节点 → 激活对应文档 → 滚动并选择对象行 → 打开属性与相关错误 → 焦点落在已知问题字段，未知字段落在对象标题。路径不能解析时保留问题详情并提供可定位来源文件；两者均无目标则不显示可点击假链接。只读标准对象仍可接力查看，但不出现“应用更改”。修复后旧问题不能自动消失为通过，必须重新校验或检查计划。

工具窗口打开不抢当前字段焦点；从问题列表主动定位才转移。关闭窗口后返回其调用者。设置及确认对话框阻止背景操作，键盘焦点在对话框内循环，关闭后回到打开它的菜单／按钮。

筛选仅作用当前范围，不是全工程语义搜索。关系跳转与问题跳转共享选择／草稿保护，不各建一份对象状态。面板展开和选择反馈使用 120–160 ms 的轻过渡，减少动态效果时即时完成；不动画模拟编译成功。

### 扩展接入点

未来真实能力获产品规划批准并有后端契约后，接入既有系统：对象类型加入工程树；编辑器加入中心文档；属性及真实引用加入检查器；校验诊断加入问题模型；生成／构建／运行结果进入既有工具窗口；资源进入设置类别。每个扩展需明确对象稳定身份、所属文件、可编辑字段、草稿应用／还原、预览 revision、结果失效及取消归属，并沿用公共命令路由。未获得这些契约的模块不提供按钮或占位“即将推出”工作页。本节定义接入位置，不批准新能力或修改已有 OS 路线。

## Accessibility Floor

所有动作可用键盘完成；树使用 tree／treeitem 及展开状态，表格保留列标题，标签与工具窗口提供可理解名称和当前状态。图标轨不能只有图形或颜色，须有可访问名称及可发现文字提示。选择色 `{colors.selection}` 之外还有选中标记；错误、成功、只读和失效均有文字，焦点轮廓不能被选中背景掩盖。

所有字段关联 label，错误用 aria-invalid／aria-describedby 指向具体说明；状态更新使用温和 live region，阻断错误才 alert，不逐行朗读高频日志。日志和路径可选择／复制，长路径可展开，不靠 hover 才可读。焦点转移优先对象或字段，不跳到页面顶部。对话框命名、焦点圈定与 Escape 回退必需。

正文按 `{typography.body.fontSize}`，密集表格不得以缩小到难读字号换空间；面板分隔拖动之外提供键盘调整／折叠入口。触控评审中的关键操作保持易触达。视觉对比及浅深色细节由 DESIGN.md 负责；本文件不宣称原型或正式软件已通过 WCAG 检测。

## Key Flows

以下为**具名工程师的说明性会话**，用于实现与评审行为，不是客户访谈、真实客户案例或验收成果。

### 林岚：修复 CAN 信号后交付源码

1. 集成工程师林岚在起始页合法配置官方档案，选择同一 ECU 的多份 ARXML。打开后落在 CAN 通信文档，工程树展示原文件及帧／信号。
2. 她选择 Rx 帧，在检查器修改超时；不慎切换对象时系统保护草稿，她选择应用并继续。表格更新但标题出现未保存，旧校验结果失效。
3. 她预览保存，逐文件查看差异，再确认保存。校验得到一个可定位问题，底部“问题”展开但工程上下文仍在。
4. **高潮**：点击问题，树、对象表与检查器接力到同一个信号；她修正位布局，应用后仍保持对象焦点，重新保存并校验，不把旧错误消失当作通过。
5. 她在源码交付文档选择独立目录，预览文件与差异，确认生成。没有编译器也不自动进入构建；已生成源码不标成已构建或已验证。

### 周衡：标准 ECU 的受限集成与显式主机验证

1. BSW 开发者周衡导入标准输入，系统依据真实计划进入标准输入文档。他检查类型、端口、诊断与引用的只读关系。
2. 他只修改允许的 CAN ID 与应用周期。输入被拒绝时原配置不动，错误定位到对应端口；修正后应用并校验，再预览和确认保存。
3. 选择 Windows 受控目标及交接种类，预览源码；此步骤检查标准输入，但不运行编译器。他确认写入独立输出目录。
4. 在设置填写真实执行工具后，他**显式**执行编译预检；工具就绪不等于预检通过，预检报告也不代替构建。他选择独立构建目录再构建。
5. **高潮**：主机行为验证窗口显示本次构建的 CAN／DID／N_Cr 返回结果。他只记录主机结果，不宣称实机、完整 SC1 等级或标准认证。
6. 改选 Linux 目标后原结果变失效；在不支持该目标执行的宿主上显示“未执行：本机不支持所选目标执行”，仍区分源码准备与宿主执行，不显示假的 Linux 通过。

### 陈澄：接收交接、诊断联调及取消恢复

1. 接收工程师陈澄使用 File 导入可重建主机交付包，或在标准 ECU 交付入口重导入 ECU 交接目录。两条入口各保留原动作名称，但进入同一工程壳层；不依赖原作者个人路径。
2. 如当前有草稿和未保存配置，导入先暂停，她可返回应用并保存；取消导入后原工程仍完整。交接内容不携带受限官方档案，缺依赖给出明确设置入口。
3. 在 CAN 工程诊断文档中，她建立 DID 的有序信号列表及可选单 DTC，依次应用，不把标准 ECU 的只读诊断当作同样可编辑。
4. 构建当前交付后，她选择对端工程和真实二进制执行双 ECU 信号运行，或独立诊断测试；标准 ECU 则使用自己的主机行为验证入口，不混用对端参数。
5. **高潮**：运行过久时点击取消，旧操作归属立即失效；若取消未确认，窗口保留具体错误，而不是伪造通过。晚到的旧结果不覆盖工程或目标。
6. 她重新检查适用输入／目标、显式构建和验证；交付文档、问题窗口和日志保持同一工程上下文，没有第二套“运行工作区”。

## Responsive & Platform

主平台是本地 Tauri 桌面，React/Web 技术不意味着浏览器具备文件或内核操作。主要尺寸默认 1480×920、桌面最低 1080×720；菜单和状态栏固定，工程树约 250 px、检查器约 290 px，底部结果按需展开约 210 px、默认收起，细节和间距遵循 DESIGN.md 与 `{spacing.panel}`。中央数据优先；窄窗先收起检查器，再折叠树，仍可通过工具轨恢复，不把对象表压成不可读卡片。

更小浏览器／移动视口仅为评审可读回退：文档可纵向阅读、表格横向滚动、树和检查器抽屉切换，外部演示提示保留。不承诺移动端产品、触屏完整工程操作或云端服务。真实浏览器模式如无 native 能力则明确不能选择文件、调用内核、编译或执行 ECU；本次静态原型能演示按钮反馈是内存模拟，不是绕过此限制。

Windows 与 Linux 为已有受控主机目标；宿主与选定目标分别显示。macOS 原生构建／IPC、MCU 与真实桌面验收不从本次原型推定。浅深色跟随系统变更不改变数据、筛选、标签或结果归属。长时工作保留键盘输入和可复制日志，动画克制。

## Inspiration & Anti-patterns

借鉴 JetBrains 的统一菜单、单一工程上下文、文档标签、边侧检查器与底部工具窗口；借鉴 ChatGPT 桌面的中性明暗层级、阅读舒适与有限角色色；重新设计独立身份标识，保留密集工程数据，不复制聊天结构、营销大标题或商业工具的能力承诺。

禁止：每个阶段单独做孤立页面；多棵竞争工程树；所有模块都像可编辑；底部切换重置草稿；问题跳转丢失输入；预览暗中写盘；生成自动构建／运行；旧结果覆盖新目标；用全绿仪表盘或新的保证等级矩阵概括工程；用纯颜色表示错误；无理由灰按钮；禁用输入充当只读说明；无契约的 ComM／NM／MCU／通用 ECUC 占位控件；把原型中的固定样例、设置路径或模拟成功写成真实核对结果。
