# Autosar Classic 产品简述

本仓库面向配置 AUTOSAR Classic ECU 的使用者：从新建配置或导入多文件 ARXML，到安全编辑、校验、生成可独立构建和运行的 C99 工程，并取得可复现的行为证据。长期方向是逐阶段覆盖所选 Classic 版次中当前有效的运行模块与多个目标平台；这表示逐个验证明确的模块、配置和目标组合，不表示一个 ECU 同时启用全部模块，也不预设总工作量或发布日期。

使用者应能从配置或真实 ARXML 输入，看到保存及生成差异，得到完整工程，离线构建、运行、复现成功与拒绝场景。无法安全保留的引用、影响生成的未知配置和未支持变体须明确拒绝。主机行为、内部已审支持、实机支持与公开发布是不同声明。

当前开发阶段聚焦 CAN 主机信号链和有界 DoCAN。已有实现与任务完成记录是起点，不能由历史任务数量推算 Classic 总完成率。以后每个受支持组合分别记录版次、配置、目标、工具链、规范义务和验收证据。

## 产品方向与阶段原则

- 以 CP/FO R24-11 和 Windows 主机虚拟 ECU 为当前基线，先形成可独立使用的 CAN 信号闭环，再做深同一总线的诊断能力，随后推进系统生命周期与虚拟 I/O，最后按依赖和真实使用场景扩展其他网络与横向模块。每阶段都交付端到端可验收的配置子集，不用空接口代替运行能力。
- 主机虚拟运行、指定芯片实机运行、第三方互操作、完整标准义务、功能安全和公开发布是不同的声明。取得板卡、合法工具及目标证据后，才为具体芯片和工具链建立实机档案；其他规范版次独立验证，不静默混版或迁移。
- Adaptive Platform 是单独的产品与部署方向。待多类 Classic 能力稳定、选定 AP 版次及真实模型和运行样本后再决定是否立项；不预造共用 CP/AP 模型或运行实现。
- 当前只在本地研发。开源是长期方向，发布许可、第三方权利、外部依赖和支持承诺在启动公开发布时单独核定；公开可读的规范和 XSD 不自动取得再分发权。

近期可执行需求见 [PRD](prd.md)，跨层设计约束见 [架构](architecture.md)，任务状态以 BMad sprint 文件为准。研究和早期决策保存在[项目历史资料](../../docs/project/archive/autosar-platform/map.md)，用于追溯依据，不再作为另一份当前规划。
