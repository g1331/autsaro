# Epic 4：FreeRTOS 路线的源码与可执行可行性调查

调查日期：2026-09-28。范围：架构决策及隔离研究；不是产品 OS 实现、SC1 符合性报告或功能开发。上位规则见 [spine](ARCHITECTURE-SPINE.md)，输入及规范责任见 [契约矩阵](R24-11-CONTRACT.md)。

## 结论与采用条件

**主路线已获维护者确认：FreeRTOS 内核复用，按“产品维护的单核调度策略扩展＋自有 AUTOSAR OS 语义实现”估算；否决“原生内核加薄 API 封装即可满足 SC1”的假设。**本轮在 Windows/GCC 上真实构建、运行固定源码的隔离实验；同级抢占恢复和资源优先级恢复的反例得到复现，研究补丁消除了这两个向量中的差异。入口重启、合法链式移交、自链及事件唤醒存在可运行机制。它们支持继续收口，不能据此采用生产依赖或声称完整 SC1 已可交付。

**原版 Windows 端口不能提供实际执行栈的 SC1 栈监测证据。**若 Epic 4 要声明 Windows SC1，须在本 Epic 内先证明自己的真实栈观测/故障处理端口方案；不能把这个义务推到 Epic 6 的 MCU 后继续声称主机 SC1。有界主机集成可以先形成阶段成果，但不自动满足 FR-6 或关闭 Epic 4。产品方向、依赖采用和实现就绪三者分别记录。

实施中的停止条件（架构路线已采用）：无法保存全部激活请求的规范顺序；需要第二个独立 runnable 选择器；必须重写上下文切换/SMP/主要内核机制；无法在所声明 Windows 目标上满足栈故障契约；补丁无法逐项复验或来源权利不闭合。遇到其中任一项，重新比较方案，不继续往 RTE/BSW 功能 story 上累积投入。

最终架构已固定真实线程栈策略及 W0–W5 的证据归属，见 [集成契约](INTEGRATION-CONTRACT.md)。完整 SC1 验收是实施出口，不阻断架构定稿；W1 的核心语义/真实栈/受控时间先于 W3 集成通过。

## 独立向量与实际观测

`A/B` 是同优先级任务；`H` 优先级更高；小写 `a/z` 是 A 的后续执行点。每个分支独立进程运行，程序退出后才打印内存 trace。研究补丁改变内核内部列表策略；不是通过外部线程轮询或另选下一任务制造预期。以下列出不同逻辑向量；两个分支共 22 个模式/分支组合，每个运行三次，共 66 次观测；重复次数及退出状态见 JSON。

| 模式 | 检验点与预期 | 原内核策略＋研究主机端口 | 策略扩展实验 | 可以得出的结论 |
| --- | --- | --- | --- | --- |
| 1 | A 被 H 抢占，H 结束后恢复 A，再执行 B：`AHaB` | `AHBa`，反例 | `AHaB` | 关闭时间片不足；必须修复抢占恢复的同级位置 |
| 2 | A 临时提升一个内核优先级 | `AHaB` | `AHaB` | 公共 API 能修复此例，但未证明任意 ceiling/激活配置；不据此选择通用优先级编码 |
| 3 | A 激活同级 B 后继续：`AaB` | `AaB` | `AaB` | 所测任务级 resume 没有同级立即抢占；不扩展成所有 FromISR/API 的证明 |
| 4 | 事件已置位，连续等待且未 Clear：`11B` | 直接 notification 映射为 `10B`，反例 | 仍 `10B` | notification 的 pending 状态被消费，不能等同 AUTOSAR 事件位；须自有 mask |
| 5 | A 升 ceiling，H 延迟至恢复后；A 仍先于同级 B：`AaHzB` | `AaHBz`，反例 | `AaHzB` | 优先级恢复须保留当前实例位置；单用 `vTaskPrioritySet` 不够 |
| 6 | 稳定 C99 wrapper 执行三次入口，B 在第二次 A 前就绪：`ABAA`，每次局部变量重新初始化 | `ABAA`，入口 3 次 | `ABAA`，入口 3 次 | `setjmp/longjmp`＋显式重排可验证入口重新进入；不是激活计数/全部 FIFO/栈监测的证明 |
| 7 | 调度器挂起期间直接 suspend 当前任务 | exit 99，内核 assert | exit 99，内核 assert | 不能用 `vTaskSuspendAll`＋自挂起简单拼出原子 Chain/Terminate；预期失败保留 |
| 8 | 检查执行局部变量是否位于传入 FreeRTOS 栈数组 | `OB`：在数组外 | `OB`：在数组外 | 源码与地址证据一致：配置栈不是 Windows 实际执行栈 |
| 9 | 延后高优先级 resume 至 `xTaskResumeAll`，保持 A 的同级位置：`AaHzB` | `AaHBz`，反例 | `AaHzB` | 调度器锁可延后移交，但无法独自修复队列顺序 |
| 10 | 合法 A→高优先级 B 移交，A 再激活从新入口执行，成功调用后不进入 X | 未实现该原子组合 | `ABbC`，入口 2 次 | 内核临界转换＋C99 wrapper 可实现此合法路径；错误回滚/ISR/Hook 未实现 |
| 11 | A 自链排到同级 B 后，重新进入 A，不进入 X | 未实现该原子组合 | `ABA`，入口 2 次 | 合法自链的队列和入口机制可运行；资源/并行激活边界未覆盖 |
| 13 | 自有事件 mask 已置位，连续检查，不消费事件 | 未实现自有 mask | `11B` | mask 与通知状态分离的必要性；此例不证明并发原子性 |
| 14 | 扩展任务等待，B 置事件后唤醒 A，位保持 | 未实现自有 mask/转换 | `WBEeb` | 后置事件的合法阻塞/唤醒路径可运行；任意 ISR 交错与丢失唤醒仍待系统向量 |

这里的“原内核策略”指 `tasks.c/list.c` 未改，主机优先级已按前述研究配置调整。观察匹配包括预期反例和 assert；不能把全部观测匹配称为全部标准测试通过。研究补丁只证明几个机制，未实现产品的 OS 服务、ECUC 生成、错误/Hook、完整元数据及接口。

## 推荐的跨单元契约

1. 上层只依赖标准 OS/RTE/SchM 接口；不把 FreeRTOS API 散入 BSW/SWC。Rust 配置计划是唯一对象、容量、优先级、调用层级与时间定义来源。
2. 自有层维护激活请求、事件、资源和错误等汽车语义；**FreeRTOS 仍拥有唯一实际 ready 队列、Running 裁定和上下文切换**。元数据不另建选择下一 runnable 的调度循环。
3. backend 显式封装 activation-ready、wait/wake、finish/chain、effective-priority 转换。待激活 FIFO 的顺序必须通过 ready 节点插入/重排体现，不能只增加计数然后循环调用入口。内核变更按“同级位置政策/原子转换/优先级恢复”独立记录；不把研究补丁当作已定的生产实现。
4. 单核目标先行；复用上游优先级选择与 CPU 上下文/端口基础。补丁禁止夹入 SMP/MPU 或另一个独立调度器；每次上游升级按同一向量复验，不能按通用 FreeRTOS 回归通过便认为汽车语义稳定。
5. C99 wrapper 的非局部退出只是一种已验证机制候选；production spec 必须确定编译器约束、自动变量、资源/中断清理、缺失结束处理及可维护性。未选择 C++/RAII 栈展开，也不把本实验当作其证明。
6. Windows backend 必须规定真实栈、宿主线程资源、模拟 ISR、时间/事件输入及终止策略；其有限逻辑结果与 MCU ISR/时序/栈证据分开。保持 FR-6 的等级要求，任何仅交付有界剖面的范围变更须由维护者明确决定。
