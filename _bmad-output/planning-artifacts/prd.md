# 首阶段产品需求：R24-11 主机虚拟 ECU

## 用户成果与边界

- R1：从 R24-11 多文件 ARXML 或工作台配置形成可检查的工程状态；保存与重开不得悄悄丢失引用或未支持内容。
- R2：确定性生成独立 C99 工程，完成主机 GCC 构建；其 CanIf→Can 信号收发及有界诊断按声明配置真实运行。
- R3：对不支持的版本、变体、引用、CAN ID、DLC、控制器状态和诊断输入提供可定位的拒绝结果，不输出假成功。
- R4：每项新能力交付输入、独立预期、实际正反向结果及适用规范出处；经六道证据门与独立复核后才可升级内部支持声明。
- R5：面向使用者的进度须区分新增运行行为、操作和交付改进、仅证据进展，以及仍未验证的维度。

当前声明仅限 CP/FO R24-11、Windows 虚拟 ECU、本地 GCC 和各能力档案所列的有界配置。真实 MCU、第三方互操作、完整 MISRA、功能安全、官方一致性及公开发布不包含在本阶段的通过声明内。

## 后续阶段方向（尚非已批准的完整需求清单）

1. **CAN 主机闭环：**从多文件配置与安全保存走到双虚拟 ECU 的独立构建、信号收发、状态与失败恢复。现有有界实现和 story 结果须对照该阶段出口核验，不能自动宣告整阶段完成。
2. **深入 CAN 诊断：**沿选定的 DoCAN/UDS 子集扩展真实多帧、会话、DTC 状态及主机持久恢复、受限访问和有状态写入/例程。每个 SID、子功能与故障路径单独界定；不把已有单项服务推定为整个诊断阶段通过。DoIP、OBD、J1939 和刷写另立范围。
3. **系统生命周期与虚拟 I/O：**按可运行的状态转换、唤醒/复位、存储恢复及虚拟引脚、计时和采样场景，逐步纳入相关 EcuM/BswM/ComM/CanSM、OS/RTE、存储与 I/O 子集；主机模拟不证明 MCU 寄存器、中断或电气行为。
4. **其他网络和横向模块：**根据实际前置条件与可验证对端扩展 Ethernet/DoIP 等网络链，随后评估 LIN、FlexRay、网关、安全、时间同步等模块族。模块是否纳入、先后次序及支持配置在对应阶段规划时决定，不把规范发布清单直接转成任务清单。

各阶段的退出条件相同：明确拟声明的版次、模块、配置/变体、目标与工具链；使用真实输入完成保存与生成闭包、独立构建、正反向运行和失败恢复；核对适用规范义务及证据。未通过的组合保持未支持或待审。实机和其他版次是独立验证轴；Adaptive Platform 待另行产品决定。这里只记录方向和阶段出口，后续阶段尚未拆分 story、估算工作量或承诺日期。
