# 架构约束与扩展接缝

Epic 4 的规范核定与路线决定见 [spine](architecture/epic-4/ARCHITECTURE-SPINE.md) 和 [R24-11 契约矩阵](architecture/epic-4/R24-11-CONTRACT.md)。维护者已确认主路线：以单核 SC1 为目标，固定 FreeRTOS 内核＋自有 AUTOSAR OS 语义实现＋有限单核策略扩展；原生 Windows 边界保持。Q2 已确认显式 S/R＋同步 C/S 应用 DID。Trampoline/ATK2 等保留参考和备选，不继续并列选型。路线采用本身不代表生产依赖、完整 SC1 或产品集成已验证；技术关口按该路线关闭，只有实际触发停止条件才重新选型。具体输入/接口/时间契约已由 [集成契约](architecture/epic-4/INTEGRATION-CONTRACT.md) 固定，Epic 4 架构已收口；`4844e1d` 已确认 W0–W5 共 22 条 stories，本轮 sprint 规划检查在此范围 PASS。4.1～4.22已完成BMad实施、验证及独立复核，固定Win64主机的全部适用SC1行为、跨story集成与新目录工程交接复验通过，实际状态以BMad sprint为准。早期首批进入判断保留在[实施就绪判断](implementation-readiness.md)，不作为另一份当前状态。

配置权威是 R24-11 多文件 ARXML；内部模型是解析、编辑和生成时的表示，不形成并行持久化配置。`core/src/` 负责模型、解析、跨文件引用与跨模块校验、生成计划和确定性代码生成；`src-tauri/` 连接桌面后端；`ui/src/` 提供配置与预览；`runtime/include/`、`runtime/src/` 随生成工程交付当前 C99 主机运行时。产品方向是以符合声明范围的 AUTOSAR OS 契约承载自有 Classic BSW 栈；早期可先用外部 RTOS 在 Windows 主机上做有界集成，再对指定 MCU 建立独立适配和证据。OS 实现、主机模拟及具体芯片驱动的责任边界须明确。运行代码须分清标准 BSW 接口、生成配置与 RTE、OS 实现及主机专属代码，不能让主机桥接行为冒充实机驱动或 AUTOSAR OS。

从空项目建立或导入多份 ARXML 时，保留源文件边界、未支持但有效内容的元素/属性/值/引用语义；未修改文件不重写。无法保证反向引用或并发修改安全时拒绝编辑或保存；未选定或未支持的变体影响本次生成时拒绝生成。版次与 Schema/ECUC 来源显式绑定，未经规则与往返验证不自动迁移其他版次。

生成计划应列出每个产物和外部符号的生产者、消费者及目标适配，验证通过后才输出独立工程。受支持的交付组合逐项列出自有通用运行代码、生成配置、构建说明和合法的外部依赖；不输出空壳模块，也不依赖另一套现成 BSW 协议栈。未来实机 MCAL 按具体芯片与工具链适配和验证，不从主机结果推定硬件能力。AP 只保留版次与平台边界，未取得真实 AP 工件和运行样本前不合并 CP/AP 模型。

Epic 3 已交付 R24-11 固定 Windows 主机剖面的可重建包与离线参考入口（历史 HEAD `817063e`，三个 story 与 sprint 均为 done）。当前普通工程交付 `files.list`、`files.sha256`、stdlib-only `tools/ecu-tool.py` 和说明；“导出可重建主机交付包”额外包含保存的 ARXML 与 `handoff.json`，与普通生成分开。Tauri 入口调用核心交付函数，不借助 UI 私有文件状态；交付从已保存且校验通过的 Workspace 文件集合保留原始 ARXML 字节与跨文件逻辑身份，记录工具/目标版次与来源并纳入完整性闭包。元数据不得写源机器绝对路径，不打包密钥、运行状态或官方规范；原始 ARXML 由交付者审阅。外部变更、未保存编辑、名称冲突及未闭合引用在交付前拒绝。重导入和再生成显式依赖同版工作台及合法 R24-11 XSD/MOD；封存工程离线构建不依赖 checkout、Rust、Node 或 uv。

参考双 ECU 离线复验使用产品维护的固定合法输入与独立预期报文；当前包内 stdlib-only 工具依赖声明的 CPython、目标 GCC/binutils 与 Git，校验完整性、构建、CAN/适用诊断及真实拒绝或恢复结果，不再交付 PowerShell runner。失败与未运行分开，任意用户配置不因参考向量通过而获得行为已验证声明。Epic3 当时未生成 ECU Extract、真实 SWC/RTE 或 AUTOSAR OS；后续参考 ECU 的实现与验收由 Epic4 story 记录，不反写历史能力。

通用 BSW 实现可以随工程复用，配置及必要接口按 ECU 输入生成；不追求所有源码由生成器即时写出。交付清单逐项标明源码/描述的来源、所需应用和OS 实现/目标驱动，以及实际配置下的符号与构建闭包。旧目标固定`Rte.c`转接主机Com信号。Epic4新目标从实际SWC／RTE映射生成单实例S/R和同步DID接口，生成、调度与应用调用链由正式测试验证。

改动跨越解析、生成与运行时时，必须沿输入及引用校验、生成工件闭包、独立构建、主机正反向行为走通。旧目标的`Os_Advance`只推进虚拟时间并轮询周期工作。Epic4新目标通过独立FreeRTOS backend运行实际任务、中断、事件和受控时间；两个目标不同时链接，各自保留实际行为回归，不能把函数改名作为RTOS适配。现有 `Can.c` 有标准命名入口与主机适配；对应 story 已完成，但不能仅凭接口名称宣布完整 Can Driver 支持。诊断阶段沿现有 LSduR/CanTp/PduR/Dcm、Dem/NvM 有界实现扩展，不并行生成空壳模块。

完整参考 ECU 须先依据 R24-11 OS SWS/RS 与 ECUC 定义声明扩展等级，列出适用接口、配置、调度、计时、同步、中断、资源及保护义务，按已确认的 FreeRTOS 内核＋自有语义及有限策略扩展路线建立实现与证据映射。原版FreeRTOS端口的研究观测不作为生产通过；新目标交付固定内核、真实执行栈适配及已验证汽车语义／策略补丁。通用 BSW 不直接散布 FreeRTOS 或 Windows API；主机端即使复用同一 BSW，也不继承 MCU 的实时性、内存段或中断证据。

首个硬件候选为 FRDM-A-S32K344，尚非已验证目标。外部 RTD、候选 OS 的主机/MCU 端口和工具链按实际取得的包及许可逐项固定版本；NXP RTD 包所标的 AUTOSAR 版次若不同于项目 R24-11 输入，须显式检查 ECUC 定义、配置结构、公开接口和生成物的转换边界，不能静默混版或把供应商版本差异归为标准兼容。驱动许可证与再分发条件单独记录，产品自有 BSW 的源码交付不自动包含供应商包。

当前运行时无 ComM、Nm、CanNm、CanSM 模块，也没有这些模块的 ECUC 配置闭包。`Can_SetControllerMode` 和主机 bus-off 注入只覆盖有界控制器行为，不能替代 ComM 请求仲裁、Nm/CanNm 的 NM PDU 与睡眠状态机，或 CanSM 的模式协调。未来引入网络管理时先确定常开、完整 NM、被动 NM、部分网络等哪些配置需要支持，再沿 ComM→Nm→CanNm→LSduR/CanIf 与 ComM→CanSM→CanIf/Can 的实际调用和回调链验收；未声明的变体不输出空壳配置。

首个参考 ECU 的集成契约沿[PRD FR-1–FR-15](prd.md)建立：系统/ECU Extract、产品 BSW 模块描述与 ECUC、示例 SWC 描述分别标明来源与版次；配置校验输出一份目标明确的生成计划；生成计划把 BSW 配置、RTE/调度接口、可复用 BSW 源码、OS 实现及其配置、目标驱动与构建入口逐项关联。缺生产者或消费者的接口不以空文件“补齐”，而阻断该目标交付。Windows 与实机的工程清单和证据分开，不能由同名接口推定同等运行语义。

参考网络管理采用单网络纵向调用链：通信使用者请求进入 ComM，ComM 经 Nm 驱动 CanNm 的网络请求/释放，并经 CanSM 协调 CanIf/Can 的通信模式；CanNm 的 NM PDU 经下层路由发送/接收。模块状态及回调必须能对应到一组可观察的对端 NM 报文和模式转换，不能让主机测试器直接改底层 Can 状态来代替上层请求。ComM `FULL`、主动 CanNm 是首个剖面的待核定配置；其他 NM 变体及部分网络延后。OS 接入点不得使 BSW 直接依赖 Windows 线程 API，未来目标驱动和实机中断由目标适配层负责。

每个 story 先定位适用版次的 AUTOSAR SWS/RS/MOD，形成条款、配置与声明范围的对应关系，再选择实现方案，并标明项目质量门和主机专属选择；不明确的标准义务先查证，不由熟悉的技术栈反推规范。新接口遵守 C99 与现有公开头文件契约；兼容既有 ARXML、生成工程及已验证主机行为。测试程序不得在使用者的交互桌面弹窗或抢焦点；无法隔离的原生 GUI 路径标为未验证。

当前实现采用左侧项目导航，将配置、诊断、生成与构建、虚拟运行分开，工程树与对象检查器位于配置页；R5 按[根 DESIGN.md](../../DESIGN.md)与[暂定 EXPERIENCE.md](ux-designs/ux-Autosar-2026-10-03/EXPERIENCE.md)迁移为统一工程壳层。已保存、已校验、已生成、已构建、主机已运行、指定目标已验证及适用验收门仍分别呈现，后一状态不由前一状态推断。早期原型及方案比较是[历史决策](../../docs/project/archive/autosar-platform/issues/10-configuration-workspace.md)，当前能力仍以源码和实际证据为准。


**FreeRTOS 可行性调查更新（2026-09-28）：**固定 V11.3.1 实际 commit `054e14f3397023aa83813a65aa065fc4597d481b` 和 GCC 16.1.0，已在隔离 Windows 后台进程构建、复现同级抢占恢复/资源恢复反例，并验证有限队列策略扩展、合法链式移交与 C99 入口重启机制；详见 [调查与采用条件](architecture/epic-4/FREERTOS-FEASIBILITY.md)。这条路线需要产品维护策略扩展，不能按薄 API 封装估算。原版 Windows 栈数组不是实际执行栈；主机 SC1 的真实栈门、全部激活请求 FIFO、错误/ISR/计时/Hook 与完整条款/输入证据仍未闭合。若首阶段先交付有界主机集成，FR-6 和 Epic 4 完整退出门仍保留，能力口径按story 验收确定，不再作为选型待决。该段记录采用时的研究缺口。4.1～4.22已在生产目标补齐并完成独立复验；采用时的缺口不作为当前未完成事项，实际状态由BMad sprint记录。

## 工程链与责任边界

外部 R24-11 ARXML 原字节是配置权威；现有实现仍从官方 XSD/MOD 校验，R5 则以软件独立实现的版本化内置规则和自有模块定义作为运行时校验来源，官方资料仅用于研发核对与独立对照。已验证的运行／生成关系由 `ValidatedIntegrationPlan` 表达。R5 的源结构、定义编辑和浏览投影从同一源集合派生，不替代生成计划或建立并行持久配置。目标选择与执行结果不反向写成参数。BSW 消费静态配置及明确接口；RTE/ECU 集成负责生产者—消费者、owner、事件、句柄和缓冲。FreeRTOS 是唯一任务调度器，汽车语义属于产品 OS 层，host 层只提供平台原语。

生成仅将已验证输入及目标渲染为确定性源码工件；执行消费封存工件及工具链身份；独立行为消费者维护预期，不能从生成器计算答案。新模块沿计划契约、静态配置、资源清单、目标描述和实际行为消费者接入，不先造空插件或第二套调度器。规范版次、配置/变体、目标与工具链随交接结果携带，各目标验证不能相互借用。

已发布 `epic4-win64-sr-cs-v1` 是历史集成 wire identity，不能从其名字推断当前工作台或执行宿主。旧 `autosar-host-handoff-v1` 仅按匹配源码版本、运行时与外部依赖进行精确重导入，不放宽源闭包与逐字节核对。本轮治理按阶段0环境→1进程owner→2 Linux受控OS→3目标/资源/纯源码→4生产双目标→5显式BSW策略→6工具责任→7工作台状态→8无checkout分发验收；阶段出口依实际运行确定，而非架构声明。

工作台状态由后台 `Session` 与前台 reducer 各自唯一拥有；类型化 fingerprint 将输入、目标、规则／资源、操作及实际结果绑定，immutable snapshot 和序列化 staging 阻止过期发布。现有交付仍要求使用者提供合法规范与原生执行工具；R5 规划改为随包提供独立实现的内置规则及自有定义，正常配置不再需要官方档案，原生执行工具仍单独提供。发行界面使用内嵌资源，不借用 Vite 或构建机器 checkout。Windows MSI、Linux deb/AppImage、macOS app/dmg 采用各自平台配置；真实包的配置、校验、源码生成、离线编译、行为、取消与搬移复验是独立关口，build/test 不能代替。macOS 原生构建／bundle／IPC 未验证；完整 SC1、实机和认证不从本轮有界行为推断。

## 下一产品增量的架构规划边界

长期候选路线以[产品简述](product-brief.md#长期候选路线)为准，近期需求见 PRD CFG-1–CFG-4、APP-1–APP-2；诊断 R7 接收 DIAG-1–DIAG-4 与历史 Epic 2。候选 R5–R29 不等同于正式 Epic ID，已有 Epic 4 契约和完成记录不重写。

R5 Configurator 的新建、导入、编辑、保存、校验与源码生成使用随包的产品内置规则及自有模块定义，不依赖用户准备官方 XSD／MOD、编译器、网络或执行环境。`RuleSetIdentity={release,rulesVersion,sha256}` 绑定软件规则实现／清单；校验、缓存、预览与 R5 交接使用同一身份及覆盖，不把软件规则摘要当成官方档案摘要，也不把有限内置结构检查称为全量官方 XSD 通过。第三方定义是显式可选扩展，不能替换核心规则或自动取得生成能力；官方资料仅作为研发对照输入。未知覆盖、扩展冲突与损坏的随包规则按实际原因拒绝，不关闭无关安全浏览。构建／虚拟 ECU 独立消费封存工程和执行工具。

R5 的选定 CFG-1–CFG-4 由[增量架构 spine](architecture/epic-7/ARCHITECTURE-SPINE.md)约束：原字节权威、内置规则与可选定义扩展、源对象投影、稳定身份、原子变化与安全保存、可搬移成员／原创模板、统一壳层及用户／生成物拥有权。正式编号是 Epic 7，来源为候选 R5，不复用历史 1–6。现有模型、生成计划、OS、Session／reducer 与交接链复用；旧交接 wire 的来源和闭包检查不通过本次规则切换自动改写。R6 仅继承对象／引用和应用所有权接缝，不在本轮扩展连接或调度。内置规则是待实现的新契约，实施就绪须核对更新后的 Story；规划通过不表示代码或运行能力已经实现。
