# 架构约束与扩展接缝

Epic 4 的规范核定与路线决定见 [spine](architecture/epic-4/ARCHITECTURE-SPINE.md) 和 [R24-11 契约矩阵](architecture/epic-4/R24-11-CONTRACT.md)。维护者已确认主路线：以单核 SC1 为目标，固定 FreeRTOS 内核＋自有 AUTOSAR OS 语义实现＋有限单核策略扩展；原生 Windows 边界保持。Q2 已确认显式 S/R＋同步 C/S 应用 DID。Trampoline/ATK2 等保留参考和备选，不继续并列选型。路线采用不代表生产依赖已引入、完整 SC1 或产品集成已验证；技术关口按该路线关闭，只有实际触发停止条件才重新选型。具体输入/接口/时间契约已由 [集成契约](architecture/epic-4/INTEGRATION-CONTRACT.md) 固定，Epic 4 架构已收口；`4844e1d` 已确认 W0–W5 共 22 条 stories，本轮 sprint 规划检查在此范围 PASS。尚无 ready-for-dev 开发工件，Epic 4 及新 stories 保持 backlog；首批进入条件见 [实施就绪判断](implementation-readiness.md)，本轮不开始功能开发。

配置权威是 R24-11 多文件 ARXML；内部模型是解析、编辑和生成时的表示，不形成并行持久化配置。`core/src/` 负责模型、解析、跨文件引用与跨模块校验、生成计划和确定性代码生成；`src-tauri/` 连接桌面后端；`ui/src/` 提供配置与预览；`runtime/include/`、`runtime/src/` 随生成工程交付当前 C99 主机运行时。产品方向是以符合声明范围的 AUTOSAR OS 契约承载自有 Classic BSW 栈；早期可先用外部 RTOS 在 Windows 主机上做有界集成，再对指定 MCU 建立独立适配和证据。OS 实现、主机模拟及具体芯片驱动的责任边界须明确。运行代码须分清标准 BSW 接口、生成配置与 RTE、OS 实现及主机专属代码，不能让主机桥接行为冒充实机驱动或 AUTOSAR OS。

从空项目建立或导入多份 ARXML 时，保留源文件边界、未支持但有效内容的元素/属性/值/引用语义；未修改文件不重写。无法保证反向引用或并发修改安全时拒绝编辑或保存；未选定或未支持的变体影响本次生成时拒绝生成。版次与 Schema/ECUC 来源显式绑定，未经规则与往返验证不自动迁移其他版次。

生成计划应列出每个产物和外部符号的生产者、消费者及目标适配，验证通过后才输出独立工程。受支持的交付组合逐项列出自有通用运行代码、生成配置、构建说明和合法的外部依赖；不输出空壳模块，也不依赖另一套现成 BSW 协议栈。未来实机 MCAL 按具体芯片与工具链适配和验证，不从主机结果推定硬件能力。AP 只保留版次与平台边界，未取得真实 AP 工件和运行样本前不合并 CP/AP 模型。

Epic 3 已交付当前 R24-11 固定 Windows 主机剖面的可重建包与离线参考入口（HEAD `817063e`，三个 story 与 sprint 均为 done）。普通生成工程含 `files.list`、`files.sha256`、`build.ps1` 和说明；“导出可重建主机交付包”额外包含保存的 ARXML 与 `handoff.json`，与既有“生成主机工程”分开；Tauri 入口调用核心交付函数，不借助 UI 私有文件状态。交付函数从已保存且校验通过的 Workspace 文件集合复制原始 ARXML 文本，保留跨文件引用所需的逻辑身份，记录工具/目标版次与来源，并纳入现有完整性清单；生成元数据不得写源机器绝对路径，且不得额外打包密钥或运行状态；原始 ARXML 内容由交付者审阅。源文件外部变更、未保存编辑、名称冲突或影响当前生成的未闭合引用必须在交付前拒绝。普通受限主机生成可保留既有行为，但不能显示成“可重建交付”。重新导入和生成须显式声明同版工作台及合法取得的 R24-11 XSD 为外部依赖；当前没有脱离源码目录的工作台安装包，也不得把官方 XSD 悄悄装入交付包。

参考双 ECU 离线复验使用产品维护的固定合法输入与独立预期报文，参考包提供 `verify.ps1` 和随包测试器；它只依赖声明的 Windows、PowerShell、GCC；校验输入完整性、构建、CAN/适用诊断行为及至少一项拒绝或恢复结果，并将失败与未运行分开。任意用户配置不因参考向量通过而获得行为已验证声明。此交付 Epic 不生成 ECU Extract、真实 SWC/RTE 或 AUTOSAR OS；它们仍按 PRD FR-1/FR-5/FR-6 在后续参考 ECU 阶段收口。

通用 BSW 实现可以随工程复用，配置及必要接口按 ECU 输入生成；不追求所有源码由生成器即时写出。交付清单逐项标明源码/描述的来源、所需应用和OS 实现/目标驱动，以及实际配置下的符号与构建闭包。当前固定 `Rte.c` 只转接主机 Com 信号，不是按 SWC 模型生成的 RTE；未来首次声明 SWC/RTE 集成前，须从真实应用描述验证接口、调度、生成物及其调用链。

改动跨越解析、生成与运行时时，必须沿输入及引用校验、生成工件闭包、独立构建、主机正反向行为走通。当前 `Os_Advance` 只推进虚拟时间并轮询主机周期工作，尚无选定 RTOS 的任务、中断、同步和目标移植接入；后续接入须使已验证 BSW 行为在 RTOS 调度下重新验收，不能把函数改名作为 RTOS 适配。现有 `Can.c` 有标准命名入口与主机适配；对应 story 已完成，但不能仅凭接口名称宣布完整 Can Driver 支持。诊断阶段沿现有 LSduR/CanTp/PduR/Dcm、Dem/NvM 有界实现扩展，不并行生成空壳模块。

完整参考 ECU 须先依据 R24-11 OS SWS/RS 与 ECUC 定义声明扩展等级，列出适用接口、配置、调度、计时、同步、中断、资源及保护义务，按已确认的 FreeRTOS 内核＋自有语义及有限策略扩展路线建立实现与证据映射。FreeRTOS 原生主机端口只用于有界集成实验，不预选为最终 OS。通用 BSW 不直接散布 FreeRTOS 或 Windows API；主机端即使复用同一 BSW，也不继承 MCU 的实时性、内存段或中断证据。

首个硬件候选为 FRDM-A-S32K344，尚非已验证目标。外部 RTD、候选 OS 的主机/MCU 端口和工具链按实际取得的包及许可逐项固定版本；NXP RTD 包所标的 AUTOSAR 版次若不同于项目 R24-11 输入，须显式检查 ECUC 定义、配置结构、公开接口和生成物的转换边界，不能静默混版或把供应商版本差异归为标准兼容。驱动许可证与再分发条件单独记录，产品自有 BSW 的源码交付不自动包含供应商包。

当前运行时无 ComM、Nm、CanNm、CanSM 模块，也没有这些模块的 ECUC 配置闭包。`Can_SetControllerMode` 和主机 bus-off 注入只覆盖有界控制器行为，不能替代 ComM 请求仲裁、Nm/CanNm 的 NM PDU 与睡眠状态机，或 CanSM 的模式协调。未来引入网络管理时先确定常开、完整 NM、被动 NM、部分网络等哪些配置需要支持，再沿 ComM→Nm→CanNm→LSduR/CanIf 与 ComM→CanSM→CanIf/Can 的实际调用和回调链验收；未声明的变体不输出空壳配置。

首个参考 ECU 的集成契约沿[PRD FR-1–FR-15](prd.md)建立：系统/ECU Extract、产品 BSW 模块描述与 ECUC、示例 SWC 描述分别标明来源与版次；配置校验输出一份目标明确的生成计划；生成计划把 BSW 配置、RTE/调度接口、可复用 BSW 源码、OS 实现及其配置、目标驱动与构建入口逐项关联。缺生产者或消费者的接口不以空文件“补齐”，而阻断该目标交付。Windows 与实机的工程清单和证据分开，不能由同名接口推定同等运行语义。

参考网络管理采用单网络纵向调用链：通信使用者请求进入 ComM，ComM 经 Nm 驱动 CanNm 的网络请求/释放，并经 CanSM 协调 CanIf/Can 的通信模式；CanNm 的 NM PDU 经下层路由发送/接收。模块状态及回调必须能对应到一组可观察的对端 NM 报文和模式转换，不能让主机测试器直接改底层 Can 状态来代替上层请求。ComM `FULL`、主动 CanNm 是首个剖面的待核定配置；其他 NM 变体及部分网络延后。OS 接入点不得使 BSW 直接依赖 Windows 线程 API，未来目标驱动和实机中断由目标适配层负责。

每个 story 先定位适用版次的 AUTOSAR SWS/RS/MOD，形成条款、配置与声明范围的对应关系，再选择实现方案，并标明项目质量门和主机专属选择；不明确的标准义务先查证，不由熟悉的技术栈反推规范。新接口遵守 C99 与现有公开头文件契约；兼容既有 ARXML、生成工程及已验证主机行为。测试程序不得在使用者的交互桌面弹窗或抢焦点；无法隔离的原生 GUI 路径标为未验证。

工作区采用左侧项目导航，将配置、诊断、生成与构建、虚拟运行分开；工程树与对象检查器位于配置页。界面需区分已保存、已校验、已生成、已构建、主机已运行、指定目标已验证和适用验收门已通过，后一状态不由前一状态自动推断。界面原型及早期方案比较见[历史决策](../../docs/project/archive/autosar-platform/issues/10-configuration-workspace.md)，当前实现和实际测试结果仍以源码及证据为准。
