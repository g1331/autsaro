topic: Autosar Classic reference ECU PRD
updated: 2026-09-28T00:20
---

- (decision) User confirmed product: self-maintained Classic BSW stack plus configuration, validation and generation tooling; complete supported ECU project closure is the objective.
- (decision) User confirmed first product chain is a generic CAN and diagnostics reference ECU, not a T-Box-specific stack; complete single-network management is in its exit criteria, while smaller increments may precede it.
- (decision) External RTOS retained; FreeRTOS is first evaluation candidate, not selected; AUTOSAR OS support requires separate evidence.
- (decision) Windows virtual ECU and selected MCU are distinct evidence targets; current host behavior does not establish board, real RTE or RTOS support.
- (decision) Learning layer is deferred until several complete stable engineering capabilities exist; no learning stories in the current implementation queue.
- (decision) PRD update is required because existing R1-R5 specify only the host profile, while full reference ECU acceptance and product functional requirements remain insufficiently specified.
- (change) Expanded existing host PRD with FR-1 through FR-15 for the complete generic single-CAN diagnostic reference ECU, including SWC/RTE, RTOS, network management, real target, evidence, and explicit decision gates; kept draft until profile and target choices are evidenced.
- (change) Official R24-11 Methodology, RTE, ComM, Nm, CanNm, CanSM and OS sources support the reference ECU input, integration and single-network requirements; they do not establish current implementation conformance.
- (change) Proposed first reference configuration uses one 11-bit Classical CAN network, one physical DoCAN connection, one SWC/DID, one DTC, selected existing host UDS services and ComM FULL with active CanNm; exact SWS/ECUC constraints remain to validate.
- (change) FreeRTOS MIT license and Windows simulation make it a credible first RTOS candidate, but its Windows timing is not hardware proof and it is not assumed to implement AUTOSAR OS.
- (decision) User has no MCU board; PM recommends evaluating FRDM-A-S32K344 because NXP documents onboard CAN, RTD and S32 Design Studio. Exact RTD/FreeRTOS version, license and R24-11 compatibility require a pre-purchase gate.
- (change) PRD review found reference ECU FRs not implementation-ready because input profile, diagnostic/NM exact configuration and hardware/RTOS target evidence remain unresolved; epics records outcome groups only, and sprint remains in sync with old host stories.
- (decision) PM selected FreeRTOS as the first reference ECU RTOS, based on user prior experience, official MIT licensing, and Windows simulation path; pinning exact host/MCU ports and target RTD versions remains a readiness gate, and AUTOSAR OS is not claimed.
- (correction) After checking official AUTOSAR CP R24-11 OS SWS/RS, withdrew the prior PM selection of FreeRTOS as the final reference ECU OS. FreeRTOS remains an early BSW host integration candidate only. The full reference ECU requires a declared AUTOSAR OS scalability class and verified applicable configuration, API and runtime obligations; evaluate a compatible FreeRTOS-based implementation against a legally deliverable AUTOSAR OS before choosing. Plan standards first, then technology and stories.
